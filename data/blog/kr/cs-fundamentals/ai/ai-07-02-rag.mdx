# 1. RAG(Retrieval Augmented Generation, 검색 증강 생성)

외부에서 검색된 데이터를 질문 또는 지시와 함께 제공하여 개선된 결과 도출

## 1. RAG 과정

### 1. indexing(인덱싱)

#### 1. chunk 분할

문서를 작은 단위로 분할

##### 청크 생성 전략

###### 1. 고정 크기 분할

간단하지만 문맥의 단절 위험이 있다.

###### 2. 중첩 분할

인접 [Chunk](glossary:chunking)간 일부를 중첩시켜서 문맥의 연속성을 보존시킨다

###### 3. 문단/섹션 기반 분할

문단 경계, 헤더 기준으로 문서를 분할시킨다

###### 4. 재귀적 분할

문단 > 문장 > 단어 순으로 분할시킨다
크기 초과시 더 잘게 분할시킨다

#### 2. embedding vector 생성

##### 임베딩 벡터의 정의

텍스트를 의미 보존하며 숫자 벡터로 변환

의미가 비슷한 단어는 [Vector space](glossary:vector-space)에서 가까이 위치

```json
예시

"강아지" → [0.23, -0.87, 0.14, 0.56, 0.91, ...]
"개" → [0.21, -0.83, 0.17, 0.52, 0.88, ...] ← 비슷
"자동차" → [0.91, 0.34, -0.67, 0.12, -0.44, ...] ← 다름
```

##### 임베딩 벡터의 encoder 생성 방법

###### 용어 정리

1. [hidden state](glossary:hidden-state): [Transformer](glossary:transformer)가 문맥을 반영해서 만든 각 [Token](glossary:token)의 내부 표현 벡터
2. [pooling](glossary:pooling): 여러 [Token](glossary:token) [hidden state](glossary:hidden-state)를 하나의 고정 크기 벡터로 합치는 방법
3. [RoBERTa](glossary:roberta): [BERT](glossary:bert) 계열의 [Transformer](glossary:transformer) [encoder](glossary:encoder), 입력 문장을 [Token](glossary:token)으로 쪼개고, 각 [Token](glossary:token)을 문맥이 반영된 벡터로 바꾼다.
4. [CLS](glossary:cls-token)(Classification):
   - [BERT](glossary:bert) 계열 모델에서 문장 맨 앞에 붙이는 특수 [Token](glossary:token)
   - [CLS](glossary:cls-token)의 [hidden state](glossary:hidden-state)를 문장 전체를 대표하는 벡터처럼 사용할 수 있다.
5. [Mean Polling](glossary:mean-pooling): 모든 [Token](glossary:token) 벡터의 평균, [sentence-BERT](glossary:sentence-bert)에서 사용(더 좋은 성능)
6. [Max Polling](glossary:max-pooling): 각 차원별 최댓값, 특징 강조에 유리
7. [CLS](glossary:cls-token) [Token](glossary:token) 사용 [Pooling](glossary:pooling): 문장 전체 의미를 압축한 [CLS](glossary:cls-token) [Token](glossary:token) 사용
8. [Bi-encoder](glossary:bi-encoder): 동일한 모델 2개가 각각 다른 문장을 입력으로 받아 [Similarity](glossary:similarity-search) 학습, [Embedding](glossary:embedding) [Vector DB](glossary:vector-database) 구성에 사용
9. [Cross-encoder](glossary:cross-encoder): [Encoder](glossary:encoder)가 두 개의 문장을 동시에 입력으로 받아 [Similarity](glossary:similarity-search) 학습, 후보들 중에서 질의에 부합하는 것의 선별을 위해 사용([Reranking](glossary:reranking))
   - [Bi-encoder](glossary:bi-encoder)가 대충 뽑은 후보 중에서 [Cross-encoder](glossary:cross-encoder)가 진짜 관련 높은 것을 다시 고른다

###### 단계 흐름

0. 입력텍스트를 [Tokenizer](glossary:tokenization)가 [Token](glossary:token) 형태로 만든다.
1. [Transformer](glossary:transformer) [Encoder](glossary:encoder)는 [Token](glossary:token)별 [hidden state](glossary:hidden-state)를 만든다.
2. 문장/[Chunk](glossary:chunking) [Embedding](glossary:embedding)을 만들려면 [Token](glossary:token)별 [hidden state](glossary:hidden-state)를 하나로 합쳐야 한다.
3. 이 합치는 방법이 [pooling](glossary:pooling)이다.
4. [pooling](glossary:pooling)의 선택지로 [[CLS](glossary:cls-token)], [mean pooling](glossary:mean-pooling), [max pooling](glossary:max-pooling), 마지막 [Token](glossary:token) 사용 등이 있다.
5. 이렇게 만들어진 텍스트 벡터를 [Bi-encoder](glossary:bi-encoder)에서는 질문/문서 각각에 대해 만들고 [Similarity](glossary:similarity-search)를 비교한다.
6. 고정 크기 벡터 생성하여 DB에 저장
7. [Cross-encoder](glossary:cross-encoder)에서는 질문과 문서를 함께 넣어 DB에 있는 벡터들의 관련성 점수를 직접 계산한다.
