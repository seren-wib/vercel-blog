> 시리즈 3편. 구축 1단계, 이미지 백업이다. 앞의 설계 이야기는 [2편](/kr/blog/woowangthon/woowangthon-02-network-design/)에, 전체 그림은 [Woowangthon 0](/kr/blog/woowangthon/woowangthon-00-overview/)에 있다.

## 한 줄 요약

학교에서 빌린 PC 세 대는 대회가 끝나면 돌려줘야 한다. 그래서 첫 작업은 설치가 아니라 **받은 상태를 통째로 저장해 두는 것**이었다. 로그인도 하기 전에 USB로 부팅해서 세 대의 내장 디스크를 외장 디스크에 이미지로 떴다. 그 과정에서 BIOS 화면이 안 나오고, PC마다 장치 이름이 다르고, 한 대는 이미 비밀번호가 바뀌어 있어서 이미지를 다시 떠야 했다.

![이름표를 붙인 학교 PC 세 대](/static/images/woowangthon-03-disk-images/three-pcs.webp)

_가운데가 리더, 양옆이 워커. 학교 자산 표시와 원래 호스트 이름은 가렸다_

## 1. 왜 이미지부터인가

반납할 때 PC를 원래대로 돌려놓는 방법은 둘이다.

| 방법              | 어떻게                                                | 걸리는 점                                                       |
| ----------------- | ----------------------------------------------------- | --------------------------------------------------------------- |
| 하나씩 지우기     | 깐 패키지, 만든 계정, 바꾼 설정을 목록대로 지운다     | 목록에서 빠진 게 남는다. 3주 동안 뭘 바꿨는지 다 기억할 수 없다 |
| **디스크 이미지** | 처음에 디스크 전체를 떠 두고, 반납 때 그걸로 덮어쓴다 | 처음에 한 대 20~30분, 저장할 외장 디스크가 필요하다             |

하나씩 지우는 쪽은 대비책으로만 두고 이미지로 갔다. 조건은 하나다. **아무것도 바꾸기 전에 떠야 한다.** 계정 하나, 패키지 하나만 깔아도 그건 "받은 상태"가 아니다. 그래서 로그인도 하지 않고 바로 USB로 부팅하는 게 계획이었다.

이미지에 안 들어가는 것도 있다. BIOS 설정은 디스크가 아니라 메인보드에 저장된다. 그래서 BIOS는 바꾸기 전에 화면을 사진으로 찍어 두기로 했다.

원상복구가 정말 반납 조건인지는 아직 모른다. 빌려준 분께 물어볼 일로 남겨 두고, 일단 필요하다고 보고 준비했다.

## 2. 준비물

전날 밤에 챙긴 것들이다.

| 물건               | 내용                                                                                                                                        |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 부팅 USB           | [Ventoy](https://www.ventoy.net)를 깐 115GB USB. Clonezilla live ISO를 넣고 체크섬을 확인했다. 혹시 몰라 Ubuntu와 Windows ISO도 같이 넣었다 |
| 이미지 저장 디스크 | 예전에 쓰던 512GB NVMe를 USB 케이스에 넣은 것. NTFS 파티션 하나                                                                             |
| 스위치, 랜선 4개   | 2편에서 산 것                                                                                                                               |
| 모니터, 키보드     | 동아리방 것 한 세트                                                                                                                         |

Ventoy는 USB 하나에 ISO 파일 여러 개를 넣어 두고 부팅할 때 고르게 해 주는 도구다. USB를 ISO마다 새로 구울 필요가 없다.

[Clonezilla](https://clonezilla.org)는 디스크를 통째로 복제하거나 이미지로 저장하는 무료 도구다. 디스크의 빈 공간은 건너뛰고 쓰는 부분만 압축해 저장해서, 1TB 디스크라도 이미지는 수십 GB면 된다.

## 3. BIOS 화면이 안 나온다

첫 PC부터 막혔다. USB로 부팅하려면 부팅 메뉴나 BIOS에 들어가야 하는데, 전원을 켜도 화면에 제조사 로고도 BIOS도 안 나오고 바로 로그인 화면이 떴다. 원인은 둘이었다.

- **모니터를 꽂은 곳.** 모니터가 메인보드의 HDMI 단자에 꽂혀 있었다. 이 PC에는 그래픽카드(RTX 3080)가 따로 있어서, 메인보드 쪽 출력은 부팅 초반 화면을 안 내보냈다. 그래픽카드의 HDMI로 옮기자 BIOS 화면이 나왔다. 세 대 모두 그래픽카드 쪽에 꽂아야 한다
- **Fast Boot.** BIOS의 Fast Boot가 켜져 있어서 키보드 입력을 받기 전에 부팅이 지나가 버렸다. 로고에서 누르는 키도, 부팅 메뉴 키도 안 먹었다

첫 PC는 결국 한 번 로그인해서 `sudo systemctl reboot --firmware-setup`으로 BIOS에 들어갔다. 다음 부팅을 BIOS 설정 화면으로 보내는 명령이다. 이 PC만은 이미지를 뜨기 전에 로그인 기록이 하나 남은 셈이다. 바뀐 건 로그인 기록뿐이다. 다음 PC부터는 모니터를 처음부터 그래픽카드에 꽂고, 로고가 뜰 때 부팅 메뉴 키(이 메인보드는 F11)를 눌러 바로 USB를 골랐다.

![BIOS의 부팅 설정 화면](/static/images/woowangthon-03-disk-images/bios-boot.webp)

_MSI BIOS의 부팅 설정. Fast Boot가 켜져 있다. 바꾸기 전에 이런 화면을 전부 찍어 두었다_

## 4. 누르면 안 되는 버튼

준비하면서 미리 적어 둔 함정이 하나 있다. Secure Boot가 켜진 PC에서 Ventoy로 부팅하면 파란 "Verification failed" 화면이 뜨고, 키를 등록(Enroll)하라고 한다. 등록하면 부팅은 되지만 **그 키는 PC 펌웨어에 남는다.** 디스크 이미지로 복원해도 안 지워진다. 남의 PC에 지울 수 없는 흔적을 남기는 셈이다.

그래서 그 화면이 뜨면 등록하지 말고, BIOS 화면을 찍은 뒤 Secure Boot만 잠시 끄기로 했다. 실제로는 세 대 모두 Secure Boot가 원래 꺼져 있어서 이 화면을 만나지 않았다.

## 5. 이미지 뜨기

Clonezilla에서 고른 순서는 이렇다.

1. `device-image`: 디스크를 이미지 파일로 저장
2. `local_dev`: 저장할 곳은 꽂아 둔 외장 디스크. 저장 폴더는 맨 위(`/`)
3. `Beginner` → `savedisk`: 디스크 전체를 저장
4. 이미지 이름: `<PC 이름>-orig-2026-11-04`
5. 원본 디스크: 내장 NVMe `nvme0n1`
6. 압축은 기본값, **저장한 이미지 검사: 예**, 암호화 안 함

![Clonezilla가 내장 디스크를 저장하는 화면](/static/images/woowangthon-03-disk-images/clonezilla-saving.webp)

_partclone이 루트 파티션을 읽는 중. 956GB 파티션 중 쓰는 공간은 48.6GB라 금방 끝난다_

5번에서 실수하면 끝이다. 원본과 저장 위치를 거꾸로 고르면 외장 디스크로 내장 디스크를 덮어쓴다. 그런데 **장치 이름이 PC마다 달랐다.** 한 PC에서는 Ventoy USB가 `sda`, 외장 디스크가 `sdb`였는데, 다른 PC에서는 외장 디스크가 `sda`로 잡혔다. 그래서 이름이 아니라 크기로 확인했다. 115GB는 USB, 477GB는 외장 디스크, 931GB가 내장 디스크다. 내장 디스크만 `nvme`로 시작해서 그나마 헷갈릴 여지가 적었다.

6번의 검사는 꼭 켰다. 저장이 끝나면 Clonezilla가 이미지를 다시 읽어서 복원할 수 있는지 확인한다. 검사가 실패한 이미지는 믿을 수 없으니 다시 떠야 한다. 반납하는 날 복원이 안 된다는 걸 알게 되면 늦다.

| PC     | 이미지 크기 | 비고                                                    |
| ------ | ----------- | ------------------------------------------------------- |
| 리더   | 19G         | EFI, 부트, 루트 파티션 저장. 스왑 파티션은 건너뜀(정상) |
| 워커 1 | 9.6G        | 검사 통과                                               |
| 워커 2 | 11G         | 다음 날 다시 뜸 (6절)                                   |

세 대 다 합쳐 40GB가 안 됐다. 512GB 외장 디스크는 이제 세 대의 원본을 들고 있는 유일한 곳이라 다른 용도로 쓰지 않는다.

## 6. 이미 바뀌어 있던 비밀번호

워커 2에서 문제가 생겼다. 이미지를 뜨고 나서 로그인하려는데, 빌려준 분께 받은 비밀번호가 안 맞았다. 알고 보니 팀원 한 명이 그 전에 이 PC에 로그인해서 비밀번호를 바꿔 둔 상태였다.

그러면 방금 뜬 이미지는 "받은 상태"가 아니다. 반납 때 이 이미지로 덮어쓰면 빌려준 분은 자기 비밀번호로 로그인하지 못한다. 그래서 순서를 이렇게 잡았다.

1. 팀원에게 바꾼 비밀번호를 받아 로그인한다
2. 비밀번호 말고 바꾼 게 있는지(패키지 설치, 설정 변경) 팀원에게 확인한다
3. `sudo passwd`로 원래 비밀번호로 되돌린다
4. 로그아웃하고 원래 비밀번호로 다시 로그인되는지 확인한다
5. 이미지를 같은 이름으로 다시 뜬다

![워커 2 이미지 검사 통과 화면](/static/images/woowangthon-03-disk-images/clonezilla-checked.webp)

_다시 뜬 워커 2 이미지. 파티션마다 restorable이 나오면 복원할 수 있다는 뜻이다_

다음 날 다시 뜬 이미지는 검사를 통과했고, 예전 이미지는 덮어써져 사라졌다. 같은 이름으로 덮어쓴 건 "받은 상태"를 담은 이미지가 하나만 있어야 헷갈리지 않아서다.

## 7. 이미지를 뜨고 나서 본 것

이미지를 뜬 다음에야 로그인해서 PC 안을 봤다.

| 확인                             | 결과                                                                             |
| -------------------------------- | -------------------------------------------------------------------------------- |
| OS                               | 세 대 모두 Ubuntu 24.04.5 LTS. 데스크탑 없는 최소 설치(minimized) 서버판         |
| 루트가 어디에 있나 (`findmnt /`) | 내장 NVMe의 ext4 파티션. 라이브 USB가 아니라 설치된 OS다                         |
| 이미 깔린 것                     | SSH 서버, Docker, open-iscsi. open-iscsi는 나중에 볼륨 복제(Longhorn)에 필요하다 |
| 유선 랜                          | 세 대 모두 2.5G 랜 포트가 비어 있다. USB 랜 어댑터는 필요 없다                   |
| **와이파이**                     | **세 대 모두 무선 카드가 없다**                                                  |

마지막 줄이 컸다. 2편의 예비안 하나가 여기서 사라졌다. 벽 랜 포트로 인터넷이 안 되면 PC마다 학교 와이파이로 나가려 했는데, 와이파이 카드가 없으니 그 길은 없다. 이제 인터넷은 벽 포트 하나에 달렸다. 그 이야기가 [4편](/kr/blog/woowangthon/woowangthon-04-remote-access/)이다.

## 8. 정리

| 겪은 일                                | 배운 것                                                                   |
| -------------------------------------- | ------------------------------------------------------------------------- |
| 빌린 PC를 원래대로 돌려놔야 한다       | 아무것도 바꾸기 전에 디스크 전체를 이미지로. 검사까지                     |
| BIOS가 안 보였다                       | 그래픽카드가 있으면 모니터는 그래픽카드에. Fast Boot면 `--firmware-setup` |
| Ventoy가 키 등록을 요구할 수 있다      | 펌웨어에 남는 건 누르지 않는다. Secure Boot를 잠시 끈다                   |
| 장치 이름이 PC마다 달랐다              | 원본과 저장 위치는 이름이 아니라 크기로 확인한다                          |
| 이미지를 뜨기 전에 이미 바뀐 게 있었다 | "받은 상태"인지부터 확인하고, 아니면 되돌린 뒤 다시 뜬다                  |
| BIOS 설정은 이미지에 안 들어간다       | 바꾸기 전에 사진                                                          |
