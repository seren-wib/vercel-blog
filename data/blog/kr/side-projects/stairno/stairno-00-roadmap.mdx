## 0. 들어가며

외주, 게임, 작은 프로그램과 웹 서비스를 각각 따로 굴리면 이름도 사이트도 계정도 셋이 된다. 혼자 운영하는 입장에서는 같은 일을 몇 번씩 하는 셈이라 한 이름 아래 묶기로 했다. 이 글은 그 전체 구조와 순서, 그리고 첫 작업인 공용 디자인 패키지를 다룬다.

식당으로 비유하면 Stairno는 체인 식당 이름이고, 매장 넷은 사이트 넷이다. 회원증은 매장마다 따로 만들지 않고 한 장으로 모든 매장에서 쓰며, 이 회원증 발급과 결제를 맡는 본사 창구가 계정 센터와 공용 [API](glossary:api)다. 간판과 인테리어 매뉴얼은 모든 매장이 똑같이 따르는 [Design system](glossary:design-system)이고, 매장 주소는 [Domain](glossary:domain)이다. 이름은 고트어로 별을 뜻하는 _stairno_ 에서 왔고, 영어로 읽으면 계단(_stair_)이 들어 있어 바닥에서 한 칸씩 올라가는 별이라는 뜻으로 골랐다. 이번에 한 일은 사이트 구조와 계정 방침 확정, 10단계 로드맵 작성, 허브 `stairno.com`의 모양을 `@stairno/ui` 패키지로 떼어 내기였다.

![시스템 아키텍처 다이어그램. 브라우저가 허브(Cloudflare Pages)와 계정 센터(Worker)에 접속하고, 계정 센터와 브라우저가 Hono·Better Auth API Worker를 호출하면 API가 Neon PostgreSQL, Resend, 토스페이먼츠, PayPal, R2와 통신하고, 다른 Stairno 사이트는 이 API의 OIDC로 로그인하며 GitHub Actions가 마이그레이션과 배포를 맡는다](/static/images/stairno-00-roadmap/system-architecture.drawio.svg)

## 1. 사이트는 넷, 계정은 하나

![Stairno 전체 구조](/static/images/stairno-00-roadmap/structure.svg)

_실선은 지금 운영 중, 점선은 만들 예정_

| 사이트               | 역할                                                                |
| -------------------- | ------------------------------------------------------------------- |
| **stairno.com**      | **허브.** Stairno를 소개하고 각 사이트로 보낸다. 물건을 팔지 않는다 |
| **stairnoworks.com** | **Works.** 외주 창구. 의뢰 접수, 견적, 선금, 진행 상황              |
| **stairnogames.com** | **Games.** 게임 Vane의 자리                                         |
| **stairnolabs.com**  | **Labs.** 제품 카탈로그이자 스토어. 데스크톱 프로그램을 여기서 산다 |

하는 일이 달라 사이트를 나눴다. [Domain](glossary:domain)은 넷 다 2026년 10월 17일에 샀다.

사이트가 넷이면 로그인과 결제도 넷이 되기 쉽다. 사이트마다 회원가입, [Payment gateway](glossary:payment-gateway), 환불 절차를 두면 같은 일을 네 번 하고 버그와 보안 구멍도 네 배가 된다. 그래서 Amazon 계정처럼 만들기로 했다.

- **Stairno 계정 하나**로 허브를 뺀 모든 사이트와 제품에 로그인한다
- **카드는 한 번만** 등록한다
- 구매, 구독, 다운로드 내역은 **계정 센터**(`account.stairno.com`)에서 본다
- 결제, 구독, 권한은 **공용 [API](glossary:api)**(`api.stairno.com`) 한 곳에서 처리한다

나머지 사이트는 이 둘을 불러다 쓰기만 한다. 그림에서 모든 화살표가 가운데 띠로 모이는 이유다. 허브에는 계정 화면도 결제도 없다.

## 2. 로드맵 10단계

10월 18일에 날짜 없이 순서만 정했다.

| 단계 | 할 일                                                 | 내용                                                                                       | 상태  |
| ---- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------ | ----- |
| 1    | 공용 디자인 패키지 `stairno-ui`                       | 허브의 색, 글꼴, 헤더, 푸터를 떼어 내 모든 사이트가 같은 모양을 쓰게 한다                  | ✅ 끝 |
| 2    | 계정 센터 문서                                        | 계획서, [SRS](glossary:srs), [SDD](glossary:sdd). 다른 Domain끼리 로그인이 되는지 실험부터 | ✅ 끝 |
| 3    | 계정 센터 1차: 로그인                                 | 가입, 로그인, 인증 메일, 기기 관리, 사이트 로그인 창구. 운영 공개                          | ✅ 끝 |
| 4    | 계정 센터 2차: 결제 ([Test mode](glossary:test-mode)) | 카드 등록, 1회 결제, 구독, 환불, 결제 메일. 실제 돈은 안 오간다                            | ✅ 끝 |
| 5    | stairnolabs.com                                       | 제품 카탈로그 → 결제와 다운로드. 처음으로 Stairno 계정에 붙는 사이트                       |       |
| 6    | stairnoworks.com                                      | 서비스 소개 → 의뢰 접수, 견적, 선금                                                        |       |
| 7    | stairnogames.com                                      | Vane 소개와 개발 일지                                                                      |       |
| 8    | 첫 제품 공개                                          | 학습 로드맵 서비스 atlas-odyssey를 Stairno 계정으로 무료 공개                              |       |
| 9    | 사업자등록 → 실제 결제                                | [Payment gateway](glossary:payment-gateway) 계약을 맺고 테스트 키를 진짜 키로 바꾼다       |       |
| 10   | Vane                                                  | 플레이 가능한 한 구간부터                                                                  |       |

이 순서인 이유는 넷이다.

- **디자인 패키지가 맨 앞이다.** 모든 사이트가 허브와 같은 모양으로 시작하게 하려고. 사이트를 먼저 만들고 모양을 맞추면 사이트 수만큼 고쳐야 한다
- **계정과 [API](glossary:api)가 사이트보다 앞이다.** 나머지 사이트가 전부 이 둘을 불러다 쓴다. 서버는 이 둘뿐이고, 사이트는 소개 페이지로 시작해 로그인과 결제가 필요한 곳만 나중에 붙인다
- **실제 결제는 9단계다.** 진짜 돈을 받으려면 사업자등록과 [Payment gateway](glossary:payment-gateway) 계약이 먼저다. 그 전까지는 전부 [Test mode](glossary:test-mode)로 만들고, 전환은 키만 바꾸면 되게 설계한다
- **Works는 Labs 다음이다.** 외주 사이트는 리뷰가 쌓여야 쓸모가 생긴다. 그 전까지 외주는 외주 플랫폼에서 받는다

## 3. 일하는 원칙과 도구

원칙은 넷이고 시리즈 전체에 깔린다.

1. **혼자 운영할 수 있는가.** 언어는 하나([TypeScript](glossary:typescript)), 서버는 남이 관리해 주는 것, 고정비는 0원에 가깝게
2. **문서가 먼저다.** 코드 전에 계획서, [SRS](glossary:srs), [SDD](glossary:sdd)를 쓰고, 문서와 코드가 어긋나면 같은 변경 안에서 하나를 고친다
3. **테스트가 먼저다.** [TDD](glossary:tdd)로 실패하는 [Software testing](glossary:software-testing)을 먼저 쓰고 통과시킨다
4. **운영에서 확인한다.** 단계가 끝날 때마다 실제 서비스 주소에서 [Acceptance criteria](glossary:acceptance-criteria)를 하나씩 확인한다

도구는 [Astro](glossary:astro)(허브, 계정 센터 화면), [Hono](glossary:hono)와 [Better Auth](glossary:better-auth)(공용 API), [Cloudflare Workers](glossary:cloudflare-workers)와 [Cloudflare Pages](glossary:cloudflare-pages)(모든 사이트와 API), [Neon](glossary:neon)의 [PostgreSQL](glossary:postgresql)을 [Drizzle](glossary:drizzle)로 다루는 [Database](glossary:database), 메일은 [Resend](glossary:resend), 결제는 [Toss Payments](glossary:toss-payments)(원화)와 [PayPal](glossary:paypal)(달러), 테스트는 [Vitest](glossary:vitest), 자동화는 [GitHub Actions](glossary:github-actions)다. 코드 대부분은 [AI coding agent](glossary:ai-coding-agent)인 [Claude Code](glossary:claude-code)가 썼고, 나는 범위와 결정을 정하고 결과를 확인하고 대시보드 설정이나 카드 입력처럼 사람이 해야 하는 일을 했다.

## 4. 1단계: 공용 디자인 패키지

### 시작점과 문제

1단계 전에 허브가 먼저 있었다. 10월 17일 하루 만에 만들어 공개한 [Static site](glossary:static-site)로, [Astro](glossary:astro)로 미리 만든 페이지를 [Cloudflare Pages](glossary:cloudflare-pages)에 올렸고 로그인도 [Database](glossary:database)도 없다. 디자인은 흑백뿐이고 밤하늘과 계단을 점으로 그려 별이 계단을 올라간다. 글꼴은 [Pretendard](glossary:pretendard)다. 한국어·영어 전환, 라이트·[Dark mode](glossary:dark-mode) 전환(처음엔 컴퓨터 설정을 따른다), [Responsive design](glossary:responsive-design)을 갖췄다.

10월 18일에 "모든 Stairno 사이트는 허브와 똑같이 생긴다"고 정했는데, 허브의 모양은 허브 코드에 섞여 있었다. 새 사이트마다 복사해 가면 허브 헤더 버튼 하나를 고칠 때 나머지 셋에도 같은 수정을 해야 하고, 하나를 빼먹으면 몇 달 뒤 사이트마다 조금씩 달라진다. 그래서 모양을 한 곳에서만 관리하는 `@stairno/ui`(레포 `stairno-ui`)를 만들었다.

### 떼어 낸 것

| 떼어 낸 것                            | 내용                                                              |
| ------------------------------------- | ----------------------------------------------------------------- |
| [Design token](glossary:design-token) | 색, 간격, 모서리 둥글기에 이름을 붙인 값. `--bg`(배경색)처럼 쓴다 |
| 기본 스타일                           | 글꼴, 글자 크기, 본문 폭, 고정 헤더, 푸터, 버튼 모양              |
| 헤더와 푸터                           | 문구와 링크는 사이트가 넘겨준다                                   |
| 테마 전환 버튼                        | 라이트와 다크를 바꾸고 선택을 기억한다                            |
| [i18n](glossary:i18n)                 | `/ko`와 `/en` 사이를 오가는 링크                                  |
| [Font loading](glossary:font-loading) | [Pretendard](glossary:pretendard)를 어디서 어떻게 가져올지        |

점으로 그린 글자와 밤하늘 애니메이션은 허브만의 첫인상이라 허브에 남겼다. 계정 센터에서 점 글자가 떠다니면 방해가 되기 때문이다. 공용 부품은 "무엇을 보여줄지"를 모른다. 헤더는 메뉴 항목을 받아서 그리기만 하고 내용은 쓰는 사이트가 정하므로, 허브와 계정 센터의 메뉴가 달라도 같은 헤더를 쓴다.

### 버전을 고정해서 설치

다른 사이트는 [Package](glossary:package)를 [GitHub](glossary:github) 레포에서 [npm](glossary:npm)으로 바로 설치하고, 반드시 [Git tag](glossary:git-tag)를 붙인다.

```bash
npm install github:seren-wib/stairno-ui#v0.2.2
```

태그 없이 설치하면 설치하는 순간의 최신 코드가 들어온다. 그러면 허브는 어제 코드, 계정 센터는 오늘 코드를 쓰게 되어 [Semantic versioning](glossary:semantic-versioning)을 올린 적이 없는데 모양이 바뀐다. 태그를 붙이면 사이트마다 "나는 v0.2.2를 쓴다"가 기록된다. 모양을 바꾸는 순서는 `stairno-ui`를 고치고 테스트하기, 새 버전 태그 붙이기, 각 사이트에서 [Dependency](glossary:dependency)를 새 버전으로 올리기다.

### 1픽셀도 안 바뀌었나

성공 조건은 "허브가 아무것도 안 바뀐 것처럼 보인다"였고, 세 겹으로 확인했다.

1. **결과 파일 비교.** 전후 허브를 빌드해 비교하니 HTML은 스크립트 들여쓰기만, CSS는 같은 규칙 두 덩어리가 하나로 합쳐진 것만 달랐다
2. **[Visual regression testing](glossary:visual-regression-testing).** 라이트·다크 × 데스크톱(1280px)·모바일(360px) × 한국어·영어·[HTTP status code](glossary:http-status-code) 404 페이지, 총 12장을 [Pixel diff](glossary:pixel-diff)로 비교해 **12장 전부 0픽셀 차이**였다
3. **동작 확인과 [Unit test](glossary:unit-test).** 테마 버튼, 선택 기억, 스크롤 시 헤더 변화, 언어 링크를 직접 눌러 봤고, 테스트는 허브 118개, 패키지 43개가 통과했다

10월 18일 새벽에 `stairno-ui` `v0.1.0`을 내고 허브가 이를 쓰게 바꾼 변경을 머지했다. 1단계 끝.

### 계정 메뉴 추가

같은 날 오후 3단계를 하다가 패키지에 계정 메뉴를 더했다. 원래 허브에는 로그인 관련 화면을 두지 않기로 했지만, 계정 센터를 만들고 보니 브랜드 첫 화면에서 로그인 여부와 계정 센터 가는 길이 안 보이는 게 불편했다. 그래서 허브 헤더 오른쪽에 동그란 버튼 하나만 두기로 바꿨다. 계정 화면과 결제는 여전히 허브에 없다. 모든 사이트에 똑같이 들어가야 하니 공용 패키지에 만들었다.

- **로그인한 상태**: 이름 첫 글자 버튼. 누르면 이름, 이메일, "계정 관리", "로그아웃" 카드가 열린다
- **로그인 안 한 상태**: 사람 아이콘. 누르면 "로그인", "가입"
- **허브처럼 서버 없는 사이트**: 브라우저가 공용 [API](glossary:api)에 로그인한 사람을 직접 묻는다. 3초 안에 답이 없거나 실패하면 로그인 안 한 상태로 보여 준다
- **[Keyboard navigation](glossary:keyboard-navigation)**: 열면 첫 링크로 [Focus](glossary:focus)가 가고, Esc나 바깥 클릭이면 닫히며 Focus가 버튼으로 돌아온다([Accessibility](glossary:accessibility))

연습용 사이트를 새로 만들어 로그인/로그아웃/허브 방식 × 라이트·다크 × 데스크톱·모바일로 16장을 찍어 확인했다.

| 버전     | 바뀐 것                                                                           |
| -------- | --------------------------------------------------------------------------------- |
| `v0.1.0` | 허브에서 떼어 낸 첫 버전                                                          |
| `v0.2.0` | 계정 메뉴 추가                                                                    |
| `v0.2.1` | 내용이 짧은 페이지에서 푸터 아래에 빈 띠가 생기던 문제 수정                       |
| `v0.2.2` | 브랜드 로고가 가리키는 주소를 사이트가 정할 수 있게. 계정 센터 로고는 허브로 간다 |

남은 것은 [Font loading](glossary:font-loading)이다. [Pretendard](glossary:pretendard) 설정 파일을 받는 동안 화면 그리기가 0.9초쯤 멈춘다. 계정 센터 로그인 화면의 [Lighthouse](glossary:lighthouse) 성능 점수가 영어 91점, 한국어 81~85점으로 목표 90점에 못 미친 주원인이다. 글꼴을 기다리지 않고 먼저 그리게 바꾸는 [Issue](glossary:issue)가 `stairno-ui`에 남아 있다.
