## 0. Introduction

> Part 2 of the skills series. What a skill is, and why these rules moved out of the instruction file, is in [CH0. Skills Overview](/en/blog/side-projects/skills/skills-00-overview/).

The rules for documents (plan pages, report format, the language of public docs, [Google Docs](glossary:google-docs) image tips) were scattered across several global memory files. They only matter when writing a document, so I gathered them into one [skill](glossary:agent-skill) that loads only then.

In restaurant terms, it is recipe cards for each kind of dish pinned on the kitchen wall, where you take down only the card for the dish you are cooking. The stack of cards is the `docs-style` [skill](glossary:agent-skill), the kinds of dish are the kinds of document, and one card is one `##` section of `SKILL.md`.

`docs-style` is the [skill](glossary:agent-skill) opened right before writing a document. It holds six groups of rules: plan pages and checklists, option comparisons, the language of public repo docs, file formats, building school reports, and [Google Docs](glossary:google-docs) gotchas. Over two weeks and seven [commits](glossary:commit) it moved the source of school reports from [Google Docs](glossary:google-docs) to local files. The size history is in the table in section 7.

## 2. Plan pages and checklists

![One TODO list ticked off in place instead of lists split by person](/static/images/skills-02-docs-style/todo-list.svg)

_One TODO list ticked off in place instead of lists split by person_

A plan page is one **TODO list**, and finished items are ticked with the [Markdown](glossary:markdown) [task list](glossary:task-list) `- [x]`. There are three rules.

- No person's name anywhere, mine included. Lines like "owner: ○○○" or "for ○○ to do" are out.
- One list. No "done / who does what" split; finished items are checked where they are. Groups are by phase or place only ("prep", "at school (per PC)", "check"). When the device matters, prefix it ("desktop:").
- Role tables a team defines in its own repo docs are outside this rule. If unsure, ask.

The **team documents** rule added the same day sits here too. Before changing a document a teammate owns, report whose it is, where it is and what would change, then wait for an answer. This line came from tidying a team assignment's combined document, where teammates' sections had to be shortened to fit the page limit (old memory record).

## 3. Option comparisons

For an **option comparison** table or list there are two rules.

- Every drawback that matters gets its own bullet, with the concrete consequence. Several costs are never shrunk into one soft phrase.
- Before finishing, check that every cost of an option mentioned in chat is also in the document.

The second rule follows from comparisons happening in conversation first. If a cost said in chat drops out on the way into the document, anyone reading only the document later never learns about it. The specific incident behind this rule is not recorded. The format for keeping rejected options and their reasons in [decision records](glossary:decision-record) is in [the entry shape in Project Docs 2](/en/blog/side-projects/project-docs/project-docs-00-overview/#5-decision-records-inside-the-sdd).

## 4. Language and file formats

**Language** rules:

- Public documents a visitor reads first ([README](glossary:readme), [CONTRIBUTING](glossary:contributingmd), SECURITY, [CHANGELOG](glossary:changelog), [PR](glossary:pull-request) templates) are in English, and the repo docs say so.
- Planning documents (`docs/specs/`), their [Google Docs](glossary:google-docs) copies, [CLAUDE.md](glossary:claudemd), and [commit](glossary:commit) and [PR](glossary:pull-request) language follow the repo's own rule.

The **file format** rules came in on 2026-11-27.

- A document is a [docx](glossary:docx) and a sheet is an [xlsx](glossary:xlsx), built locally. I open them in [Google Docs](glossary:google-docs) and Sheets through [Drive](glossary:google-drive).
- Deliverables are not made as new native [Google Docs](glossary:google-docs) or Sheets. Existing ones stay as they are.
- Exceptions: [Markdown](glossary:markdown) in a repo, the repo → [Google Docs](glossary:google-docs) sync in `project-docs` ([Project Docs 4](/en/blog/side-projects/project-docs/project-docs-04-docs-sync/)), and documents teammates edit together.
- On the Mac, the iCloud Drive `UNIV/` folder shows in [Drive](glossary:google-drive) under "Computers → mac → UNIV". It was the only folder [Google Drive](glossary:google-drive) for desktop had added on that Mac (checked 2026-11-27), and the [Drive](glossary:google-drive) API reports those copies as `canEdit: false`. The Windows side has not been checked.

## 5. Building school reports

![A build pipeline from an HTML source and a build script to docx and PDF, with Google Docs dropped as the source](/static/images/skills-02-docs-style/report-pipeline.svg)

_A [build pipeline](glossary:build-pipeline) from an [HTML](glossary:html) source and a [build script](glossary:build) to [docx](glossary:docx) and [PDF](glossary:pdf), with [Google Docs](glossary:google-docs) dropped as the source_

A report starts as one [HTML](glossary:html) body, the [build script](glossary:build) turns it into a [docx](glossary:docx), and that is converted to a [PDF](glossary:pdf). To fix something, you don't edit the [docx](glossary:docx); you fix the source and build again.

- The source stays local: one [HTML](glossary:html) body and one [build script](glossary:build) (`hwN-body.html` + `hwN-docx-build.js`). The script builds the [docx](glossary:docx) with the [npm](glossary:npm) packages `docx` and `node-html-parser`. Figures are referenced by file path.
- For the [PDF](glossary:pdf), a copy with fonts swapped is converted through `soffice` (바탕 → AppleMyungjo, Consolas → Menlo, 맑은 고딕 → Apple SD Gothic Neo). Why the fonts are swapped is not written in the [skill](glossary:agent-skill) (not recorded).
- If the course folder has its own `CLAUDE.md`, it wins over this section.

### Why Google Docs stopped being the source

The first rule (2026-11-13) was to build reports in [Google Docs](glossary:google-docs) and export them to [PDF](glossary:pdf). On 2026-11-25 the default moved to a local source, and the [skill](glossary:agent-skill) keeps three reasons measured on a cloud computing assignment.

- A Doc with screenshots returns over 400k characters per `read_doc`. The local [HTML](glossary:html) source is about 30k characters.
- Every fix repeats read, write and re-check.
- Conversion drops the TOC heading ids, and the API can't restore them.

The same conclusion showed up earlier in that course folder's memory. On 2026-10-04 there is a record of trying to edit HW3 in [Google Docs](glossary:google-docs) and going back to [docx](glossary:docx), and from then on cloud computing reports were local [docx](glossary:docx) as an exception in the course `CLAUDE.md`. The 11-25 [commit](glossary:commit) promoted that exception to the default and deleted the exception sentence. Text-only reports are built locally too. Only documents teammates edit together stay in [Google Docs](glossary:google-docs).

### Page rules

- Page 1 cover: the CBNU (Chungbuk National University) logo, title, course, submission date and authors. Authors are GitHub handles or roles, never real names. The logo line came in on 2026-11-17, when 13 document instructions from that day were checked against the [skill](glossary:agent-skill) and it was one of the 5 found missing.
- Page 2 table of contents: indented headings, no page numbers.
- A big block (a diagram section, a schema or table spec, each algorithm) starts with a page break. To keep a heading from sitting alone at the bottom of a page, headings get keep-with-next.
- Heading levels follow weight. A major component like a Class Diagram or the DB schema is never at the same level as a small subtopic. Sub-sections are numbered like 2-2-1.
- Figures are embedded images in the [docx](glossary:docx). No links or paths where a figure should be. [SVG](glossary:svg) diagrams are rendered to [PNG](glossary:png) locally before embedding.
- Section names use the assignment's own wording ("사용자 인터페이스 명세 및 설계", user interface specification and design, not just "wireframe").
- A report built from stage documents has its own source. Docs that the `project-docs` sync overwrites are never edited.
- After building, every page of the [PDF](glossary:pdf) is rendered and looked at before reporting.

## 6. Google Docs gotchas

![Converting an SVG from a public repo to PNG through weserv and inserting it with insertInlineImage](/static/images/skills-02-docs-style/svg-to-docs.svg)

_Converting an [SVG](glossary:svg) from a public repo to [PNG](glossary:png) through weserv and inserting it with insertInlineImage_

The image [proxy](glossary:proxy) **images.weserv.nl** and the format the [Google Docs API](glossary:google-docs-api) `insertInlineImage` accepts are the heart of this section. Even after report sources moved local, these gotchas still show up in Docs shared with teammates and in synced Docs.

- `insertInlineImage` takes only [PNG](glossary:png), JPEG or GIF from a public URL. An [SVG](glossary:svg) in a public GitHub repo goes in as `https://images.weserv.nl/?url=raw.githubusercontent.com/<owner>/<repo>/<sha>/<path>.svg&output=png&w=1600`. The path uses a [commit SHA](glossary:commit-hash) instead of `main`, because weserv [caches](glossary:cache) by URL and a `main` path can return an old picture. Fetch it with curl and look at it before inserting. [drawio](glossary:drawio) [SVG](glossary:svg)s with Korean text render fine.
- [Mermaid](glossary:mermaid) source is not sent to mermaid.ink without asking. That counts as uploading data, so it is rendered locally.
- To resize an inline image, delete it and insert again with a new `objectSize`. About 420-440 pt wide × 300 pt high fits two landscape diagrams on one page.
- `read_file_content` shows bold text inside tables as `\*\*text\*\*`. Those are not literal asterisks.
- A `read_doc` result over 1 MB is saved to a file. Extract it with node and find the body after the first HEADING_1 (the TOC lines repeat the headings). The final check is exporting to [PDF](glossary:pdf) and rendering every page.
