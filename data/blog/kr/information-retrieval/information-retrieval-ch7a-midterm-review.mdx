# 정보검색 중간고사 정리 (ch1\~7, 흐름 순)

질의 [Brutus Caesar]가 들어와서 top k가 나가기까지. 출제 예고: 07system 슬라이드 51 weight-sorted (6단계).

**전체 흐름**: 질의 글자 → term으로([ch2](/kr/blog/information-retrieval/information-retrieval-ch2-term-vocabulary-postings/)) → 사전에서 term 찾기([ch3](/kr/blog/information-retrieval/information-retrieval-ch3-dictionaries-tolerant-retrieval/)) → 포스팅 가져와 교집합([ch1](/kr/blog/information-retrieval/information-retrieval-ch1-boolean-retrieval/)) → 문서마다 점수 합([ch6](/kr/blog/information-retrieval/information-retrieval-ch6-scoring-term-weighting-vector-space/)) → 빠르게 top k([ch7](/kr/blog/information-retrieval/information-retrieval-ch7-scores-complete-search-system/)). 포스팅은 어떻게 만들었고([ch4](/kr/blog/information-retrieval/information-retrieval-ch4-index-construction/)) 어떻게 작게 저장했나([ch5](/kr/blog/information-retrieval/information-retrieval-ch5-index-compression/)).

## 1단계. 질의 글자를 term으로 (ch2)

**사용자가 친 글자 그대로는 사전에 없음. 문서 색인할 때랑 똑같이 바꿔야 함**

- **word** 글자열 그대로 / **token** 등장 하나 / **term** 정규화한 동치류 / **type** ≈ term. "the the the" → token 3, term 1
- 문서 파싱부터 정할 것: 형식, 언어, 문자 집합 (셋 다 분류 문제). 문서 단위도 설계 결정
- 전처리: 정규화(USA = U.S.A.), 토큰화(O'Neill), 하이픈, 숫자(요샌 색인), 악센트, **case folding**, **불용어**(요샌 구문 질의 때문에 안 뺌)
- **Lemmatization**: 언어 지식으로 기본형, am/are/is → be / **Stemming**: 끝을 규칙으로 자름, automation → automat (사전에 없어도 됨)
- **Porter**: 5단계, 가장 긴 접미사 규칙. SSES→SS, IES→I, SS→SS, S→삭제. caresses → caress, ponies → poni. Porter가 Lovins·Paice보다 덜 자름
- stemming 효과: 재현율 ↑ 정밀도 ↓. [operational AND research] → oper로 묶여 operating까지 걸림
- 불용어가 term으로 남으면 거의 모든 문서에 있어서 교집합도 안 줄고 idf ≈ 0이라 점수에도 안 보탬

## 2단계. 사전에서 term 찾기 (ch3)

**Brutus라는 글자로 사전의 줄을 찾아야 포스팅 포인터가 나옴. 오타·와일드카드면 term 집합으로 바꿔야 함**

- **사전 = 고정 길이 배열**, 한 줄 term 20 + df 4 + 포스팅 포인터 4 = **28바이트**. 단어 → 줄 번호를 **해시 or 트리**로
- **해시** O(1). 변형(résumé) X, 접두사 X, 어휘 늘면 rehash / **트리** O(log M), 접두사 O. 이진 트리는 재균형 비쌈 → **B-tree**(자식 [2, 4])
- **wildcard** → 맞는 term 집합 → 그 term 중 하나라도 있는 문서(OR)
  - `mon*` B-tree 범위 `mon ≤ t < moo` / `*mon` 뒤집은 트리 `nom ≤ t < non` / `m*nchen` 둘 교집합(비쌈)
  - **permuterm**: `$` 붙이고 회전 전부 B-tree에. `hello$ ello$h llo$he lo$hel o$hell $hello`. 질의도 돌려 `*`를 끝으로: `X` → `X$`, `X*` → `$X*`, `*X` → `X$*`, `*X*` → `X*`, `X*Y` → `Y$X*`. `hel*o` → `o$hel*`, `c*t` → `t$c*`. 사전 4배
  - **k-gram**: k-gram → term 역색인. april → `$a ap pr ri il l$`. `mon*` = `$m AND mo AND on` → moon 끼어듦 → **후처리** 필수. 공간은 덜 씀
  - 구글이 안 하는 이유: term 여러 개로 펼쳐져 OR 묶음의 AND가 비쌈, `[pyth* theo*]` 남발
- **오타** → 거리 가까운 맞는 term으로
  - **Levenshtein** insert/delete/replace 각 1. dog-do 1, cat-act 2 / **Damerau** + transposition, cat-act 1
  - 표: 0행 0 1 2 …, 0열 0 1 2 …, 칸 = min(↘ 같으면 +0 다르면 +1, ↓ +1 delete, → +1 insert), **답 = 오른쪽 아래**. cats → fast 3, oslo → snow 3, cat → catcat 3
  - DP인 이유: 최적 부분 구조 + 겹치는 부분 문제. **weighted**: m→n이 m→q보다 쌈, 가중치 행렬
  - **isolated word**(form/from 못 잡음) vs **context-sensitive**. 문서는 안 고침
  - k-gram 교정: bordroom bigram bo or rd dr ro oo om → 겹치는 수로 threshold
  - **hit-based**: flew form munich → 한 번에 한 단어만 바꾼 구절 전부 질의 → hit 최다가 정답. 후보 7·20·3 → 30번(조합은 420)
  - Norvig: 사전에 있으면 그대로 → 거리 1 → 거리 2 → 원래. 빈도 최고
- **Soundex**(발음): 첫 글자 그대로, AEIOUHWY→0, BFPV 1 / CGJKQSXZ 2 / DT 3 / L 4 / MN 5 / R 6, 연속 중복 하나로, 0 지우고 **글자 1 + 숫자 3**. HERMAN(N) → H655, LEE → L000. IR엔 별로, high recall엔 OK

## 3단계. 포스팅 가져와서 교집합 (ch1, ch2 뒷부분)

**사전 줄의 포인터 따라가면 포스팅 리스트. 불리언이면 여기서 끝**

- **역색인**: dictionary(term + df + 포인터) / posting(docID 하나) / postings list(docID 오름차순). **df** = term이 든 **문서 수**(10번 나와도 1)
- 왜 역색인: grep은 느리고 줄 단위고 NOT·근접 안 됨 / incidence matrix(행 term 열 문서 0/1)는 N 10⁶ × M 500,000 = 5×10¹¹칸인데 1은 최대 10⁹ → 희소 → 1만 저장
- NOT은 비트 반전: `Brutus AND Caesar AND NOT Calpurnia` = 110100 AND 110111 AND 101111 = 100100
- **Intersect(p1, p2)**: 같으면 추가하고 둘 다 전진, 다르면 작은 쪽 전진. O(x + y). 위 예시 → 1 하나
- **최적화**: AND 여러 개면 **df 작은 리스트부터**. result 비면 바로 끝. OR 크기는 df 합으로 어림(상한 = 보수적)
- **skip pointer**: 몇 칸 뒤 포인터, skip 대상 ≤ 상대 docID일 때만(`<=`) while로 연속 점프. 길이 P에 **√P개**(16 → 4개, 4칸마다). 요샌 CPU 좋아서 효과 작음
- **구문 질의**: biword(두 단어를 term 하나로, 긴 구문은 false positive·사전 폭발) → **positional**(포스팅 = docID + 위치 목록, `to, 993427:`의 993427 = df). docID 교집합 → 문서 안에서 to 위치 i, be 위치 i+1
- **proximity** `/k`: PositionalIntersect, 바깥은 Intersect, 안에서 위치 차 ≤ k. 위치까지 돌려줌(요약문). **combination**: 흔한 biword만 term, 나머지 positional, 더 빠르고 공간 26% 더
- **Westlaw**: 불리언 기본. `/3` `/s` `/p`, 공백 = OR(구글은 AND), `!`, `"…"`. 이유: 정밀도·투명성·통제
- 불리언 문제 → **feast or famine**(20만 개 아니면 0개) → 점수로 줄 세우자(4단계)

## 4단계. 문서마다 점수 합 (ch6)

**교집합 대신 표를 만듦. 행 = 문서, 열 = 질의 term, 칸 = 가중치, 합 = 점수**

```text
docID   Brutus  Caesar  합
1       2       1       3
5       -       1       1
7       3       -       3
13      -       1       1
17      -       1       1
83      1       -       1
87      2       -       2
```

- 위는 tf 그대로 더한 것. 진짜 칸 = **w(t,d) × w(t,q)**, 합 = 점수(0\~1로 정규화하면 코사인)
- **Jaccard** |A ∩ B| / |A ∪ B|, "ides of March" vs "Caesar died in March" = 1/6. 빈도·드문 term 무시 → 버림
- **bag of words**: 순서 무시 (positional에서 한 발 후퇴)
- **log tf**: w = 1 + log₁₀ tf (tf > 0). 1→1, 2→1.3, 10→2, 1000→4
- **idf = log₁₀(N / df)**. N 10⁶: df 1→6, 100→4, 1000→3, 10⁴→2, 10⁵→1, 10⁶→0 (0 개수). term 2개 이상일 때만 순위에 영향
- **cf**(전체 횟수) vs **df**(문서 수): insurance cf 10440 df 3997 / try cf 10422 df 8760 → df로. df ≤ cf
- **tf-idf** w = (1 + log tf) × log(N / df)
- 거리 말고 **코사인**: 긴 문서 손해, d와 d+d가 멀어짐. cos = Σqᵢdᵢ / (√Σqᵢ² √Σdᵢ²), 정규화하면 dot product
- 소설: SaS 길이 √(3.06² + 2² + 1.3²) ≈ 3.88 → 0.789. cos(SaS, PaP) 0.94 / (SaS, WH) 0.79 / (PaP, WH) 0.69
- **SMART ddd.qqq**: tf n/l(1+log)/a/b, df n/t(idf), norm n/c(코사인)
- **lnc.ltn**: 문서 log tf·idf X·코사인 / 질의 log tf·idf·정규화 X. idf는 질의 쪽에서 한 번만. "best car insurance" vs "car insurance auto insurance": 질의 car 2.0 insurance 3.0 / 문서 길이 √(1+1+1.3²) ≈ 1.92 → car 0.52 insurance 0.68 → **0.52×2 + 0.68×3 = 3.08**
- **CosineScore**: term마다 포스팅 돌며 Scores[d] += w(t,d) × w(t,q) → Length로 나눔 → **top K** 반환. 위 표를 **열 순서**로 채우는 코드

## 5단계. 합을 정렬해서 top k (ch7 앞부분)

**합 큰 순으로 줄 세워 위 k개만 보여줌. 1위 맞히기가 제일 중요**

- 위 표 k = 3 → 1, 7, 87. 나머지는 계산하고 버림
- Dan Russell 실험: 1\~4위 요약을 7\~10위보다 훨씬 많이 읽음, 클릭은 더 위로, **2번 중 1번 1위 클릭**, 1위가 틀려도 30%. 순위 = 신규 검색엔진 진입 장벽(클릭 데이터)
- 코사인 문제: 짧은 문서 유리 (d1 + 무관 기사 5개인 d2가 손해) → **pivot normalization**: 실제 관련 확률 곡선과 만나는 길이 = pivot, 거기 중심으로 선 돌림 → 짧은 문서 ↓ 긴 문서 ↑
- **tiered index**: 중요도별 층(tier 1 제목, 2 본문). tier 1부터, k개 넘으면 멈춤. 각 tier 다음보다 10배 작게, 대부분 질의가 tier 1에서 끝나야 함
- 안 배운 부품: 문서 캐시(snippet), zone 색인, 기계학습 순위, proximity 순위, 질의 파서
- 벡터 공간 + 구문(구문마다 idf 불가) / + 불리언 `+` `-`(후처리, 비효율) / + wildcard: 쉬운 답 없음

## 6단계. 표를 덜 채우고도 top k 맞히기 (ch7 7.4, 출제 예고)

**문서 200억 개면 표를 다 못 만듦. 행을 덜 만들고, 덜 채우고, 중간에 멈춤**

- **포스팅에 tf**: (docID, tf), tf는 **정수**(실수 가중치는 압축 어려움)
- **min heap**: 부모 &lt; 자식, 루트 = top k 중 최솟값. 새 합 s ≤ 루트 → 버림, s > 루트 → 루트 빼고 넣기 O(log k). 전체 O(N log k). 정렬 안 하고 top k 유지
- 표 채우는 순서 2가지
  - **document-at-a-time**: **행 하나 완성 → 다음 행**. 1행 3 확정, 5행 1 확정 …. 조건: 모든 포스팅이 **같은 순서**(docID 순 or PageRank 순)여야 "지금 제일 작은 문서"를 고름
  - **term-at-a-time**: **열 하나 끝 → 다음 열**. Brutus 열(1, 7, 83, 87) 다 채우고 Caesar 열. 합은 마지막 열 끝나야 확정. 문서마다 **accumulator**(누적 칸). 포스팅 순서가 term마다 달라도 됨 = CosineScore
- **PageRank 순 + 조기 종료**: net-score = g(d) + cos. 포스팅을 g 큰 순. 지금 g &lt; 0.1, top k 최솟값 1.2, cos ≤ 1 → 뒤는 최대 1.1 &lt; 1.2 → **멈춤**
- **weight-sorted postings (슬라이드 51)**: 포스팅을 가중치(정규화 tf-idf) 큰 순 → top k가 앞에 몰림 → 뒤 안 보고 끝내도 top k 거의 안 바뀜. 대가: term마다 순서 달라짐 → document-at-a-time **불가** → **term-at-a-time만**
- **accumulator**: 질의 term 포스팅에 나오는 문서만 행을 만듦 = 합 0인 문서는 행 자체가 없음. 위 예시 **7개**(1 5 7 13 17 83 87), 1은 두 번 더해짐
- **conjunctive(AND)**: 모든 질의 term이 있는 문서만 행 → 양쪽 다 찬 **1행 하나**. 구글 기본. 불용어는 전처리에서 빠지거나 남아도 거의 안 거름

## 뒤에서 받치는 것 A. 포스팅은 어떻게 만들었나 (ch4)

**(term, docID) 쌍을 모아 term 순 정렬 → 같은 term 묶음. 메모리에 안 들어가면?**

- 하드웨어: 메모리가 디스크보다 약 10배 빠름, **seek이 압도적으로 비쌈**(5ms = 25만 바이트), 블록 I/O, 결함 허용 비쌈 → 평범한 기계 여러 대
- **RCV1**: N 800,000 / L 200 / M 400,000 / T 1억. term당 평균 160M / 400K = **400번**, positional 포스팅 = token 수 1.6억
- **BSBI**: 포스팅 12바이트(termID 4 + docID 4 + 빈도 4), 블록 1천만 개(120MB) → 10블록. 블록마다 메모리 정렬 → 디스크 → **병합**(앞끼리 비교, term 순 → docID 순). 문제: term → termID 사전을 계속 메모리에
- **SPIMI**: 블록마다 **새 해시 사전**, **정렬 안 함**(token 나오는 대로 리스트에 붙임, 차면 2배), 메모리 차면 **term만 정렬**해서 디스크. 병합은 같음

|        | BSBI                  | SPIMI                |
| ------ | --------------------- | -------------------- |
| 사전   | termID 사전 하나 유지 | 블록마다 새 해시     |
| 포스팅 | (termID, docID) 쌍    | term별 리스트에 바로 |
| 정렬   | 쌍 전부               | term만 (쓸 때)       |

- 고장: 1000대 다 살 확률 0.999¹⁰⁰⁰ ≈ **0.37**. 100만 대 3년에 한 번 → 1,576,800 / 10⁶ = **1.6분마다 하나**
- **MapReduce**: master(안 죽음)가 split → **parser(map)**: (term, docID)를 구간(a-f, g-p, q-z)별 segment 파일 → **inverter(reduce)**: 구간 하나 전부 모아 정렬 → 포스팅. map input → list(k, v), reduce (k, list(v)) → output. k = termID, v = docID
- 예: d1 `C came, C c'ed.` d2 `C died.` → map (C,d2)(died,d2)(C,d1)(came,d1)(C,d1)(c'ed,d1) → reduce C → (d1:2, d2:1), died (d2:1), came (d1:1), c'ed (d1:1)
- **term-partitioned** vs **document-partitioned**(모든 기계에 보내고 합침, 긴 포스팅 안 옮기고 부하 안 몰림)
- **동적**: main(디스크) + aux(메모리). 삭제는 무효화 비트 벡터. 병합 때마다 main 전부 다시 씀 → a + 2a + … + na = **O(T²)**
- **Logarithmic merge**: Z0(n) → I0(n) I1(2n) I2(4n) …. Z0 차면 I0 비었으면 저장, 있으면 합쳐 올림. **k번째 = k의 이진수**(4번째 100 → I2, 6번째 110 → I2 I1). 색인 수 O(log T), 비용 **O(T log T)**

## 뒤에서 받치는 것 B. 사전·포스팅을 작게 (ch5)

**사전은 메모리에 올릴 만큼, 포스팅은 gap + 가변 길이 코드**

- lossy(소문자화·불용어·stemming = 전처리) vs **lossless**(색인 압축)
- 전처리 효과: 대소문자·stemming은 non-positional만 줄음(The+the 포스팅 합쳐짐, token은 그대로), 불용어는 positional이 훨씬 줄음(문서당 수십 번). 사전은 불용어 빼도 거의 안 줄음
- **Heaps** M = k · T^b, b ≈ 0.5. 연습: 10,000 → 3,000, 1,000,000 → 30,000 → 10 = 100^b → **b 0.5**, k = 3,000/100 = **30**. T = 2×10¹⁰ × 200 = 4×10¹² → M = 30 × 2×10⁶ = **6천만**
- **Zipf** cf_i ∝ 1/i, log-log 기울기 −1. 흔한 term 몇 개, 드문 term 엄청 많음
- 사전 (M 400,000):

| 방식                    | 계산                  | 크기    |
| ----------------------- | --------------------- | ------- |
| 고정 길이 20+4+4        | 28 × 400K             | 11.2 MB |
| 문자열 + term 포인터 3B | (4+4+3+8) × 400K      | 7.6 MB  |
| + blocking k=4          | 블록당 5B 절약 × 100K | 7.1 MB  |
| + front coding          |                       | 5.9 MB  |

- 포인터 3바이트: 8 × 400K = 3.2M → log₂ ≈ 21.6 &lt; 24비트. **blocking**: 4개마다 포인터 1 + 길이 1바이트씩(12 → 7), 블록까지 이진 탐색 → 안은 순차. **front coding**: `8automat*a1◇e2◇ic3◇ion`
- **gap**: 283154 283159 283202 → 283154, 5, 43. 흔한 term은 gap 작음. docID 그냥 저장하면 log₂ 800,000 ≈ 20비트
- **VB**: 바이트 = c 1 + 7비트, 128로 나눠 뒤에서부터, **마지막만 c = 1**. 824 = 6×128+56 → `00000110 10111000` / 5 → `10000101` / 130 → `00000001 10000010`. 디코딩 n = 128n + 7비트, c = 1이면 끝
- **γ** = 길이(unary) + offset. offset = 2진수 맨 앞 1 뗀 것, 길이 = offset 비트 수를 1…10으로. 13 = 1101 → `1110,101` / 1 → `0` / 2 → `10,0` / 4 → `110,00` / 9 → `1110,001` / 24 → `11110,1000` / 130 → `11111110,0000010`. 길이 **2⌊log₂G⌋ + 1**(홀수). prefix-free, universal, parameter-free, 최적 3배(2배) 안
- VB 바이트 정렬이라 빠르고 단순 116 MB / γ 더 작은 101 MB지만 느릴 수 있음. matrix 40,000 / 32비트 400 / 20비트 250. 색인 = 텍스트(960)의 10\~15%
