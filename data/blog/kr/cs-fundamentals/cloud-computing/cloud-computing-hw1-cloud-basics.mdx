[Cloud computing](glossary:cloud-computing) 첫 번째 과제로 교재 1장 연습문제 다섯 개를 정리했다.

# 1. 클라우드 컴퓨팅의 정의

**필요할 때마다 컴퓨터 자원을 빌려 쓰는 것.** 전기, 가스, 수도처럼 쓰는 만큼 내는 [utility computing](glossary:utility-computing)이다. 시작은 1961년 존 매카시가 말한 [utility computing](glossary:utility-computing)이다.

| --------------------- | ---------------------------------------------------------------------------------- |
| [NIST](glossary:nist) | 5가지 특성, 3가지 서비스 모델, 4가지 배포 모델로 정의                              |
| 가트너                | 확장 가능하고 탄력적인 IT 기능을 서비스 형태로 제공하는 컴퓨팅 방식                |
| 포레스터 리서치       | 인터넷 기술을 통해 사용량에 따라 과금하거나 셀프서비스로 제공되는 표준화된 IT 기능 |

# 2. 컴퓨팅의 성능과 용량을 늘리는 방법

가장 먼저 떠올리는 건 CPU, 메모리 같은 부품을 업그레이드하는 거다. 하지만 한 대의 컴퓨터를 키우는 데는 한계가 있다.

그래서 두 방향으로 간다.

- **[Clustering](glossary:clustering)**: 여러 컴퓨터를 묶어 하나의 목적으로 쓴다. 묶어서 성능을 올리는 건 **[orchestration](glossary:orchestration)**이 바탕이다.
- **자원 분리**: 한 컴퓨터의 자원을 나눠서 여러 용도로 쓴다. 이건 **[virtualization](glossary:virtualization)**가 바탕이다.

# 3. 컴퓨터 가상화의 세 범주

[Virtualization](glossary:virtualization)은 **[CPU virtualization](glossary:cpu-virtualization), [memory virtualization](glossary:memory-virtualization), [I/O virtualization](glossary:io-virtualization)**로 나뉜다.

## 가상화 방식

[Guest OS](glossary:guest-os)를 고치느냐에 따라 나뉜다.

- **[Full virtualization](glossary:full-virtualization)**: [Guest OS](glossary:guest-os)를 수정하지 않는다.
- **[Para virtualization](glossary:paravirtualization)**: [Guest OS](glossary:guest-os)를 수정한다.

## 하이퍼바이저

[Virtualization](glossary:virtualization)을 구현하는 소프트웨어다. 설치 위치에 따라 두 가지로 나뉜다.

- **[Type 1](glossary:type-1-hypervisor) (native)**: 하드웨어 위에 [hypervisor](glossary:hypervisor)를 바로 설치하고, 그 위에 [VM](glossary:vm)을 올린다.
- **[Type 2](glossary:type-2-hypervisor) (hosted)**: 하드웨어 → [Host OS](glossary:host-os) → [hypervisor](glossary:hypervisor) → [Guest OS](glossary:guest-os) 순서다.

## 범주별로 어떻게 가상화되는지

**[CPU virtualization](glossary:cpu-virtualization)**

- [Guest OS](glossary:guest-os)가 실행하는 [privileged instruction](glossary:privileged-instruction)을 [hypervisor](glossary:hypervisor)가 대신 처리한다.
- 게스트를 수정하지 않으면 [hypervisor](glossary:hypervisor)가 명령을 가로채서 흉내 낸다.
- 게스트를 수정하면 그 명령을 [hypercall](glossary:hypercall)로 바꿔 [hypervisor](glossary:hypervisor)에 직접 요청한다.

**[Memory virtualization](glossary:memory-virtualization)**

- 주소 변환이 한 단계 늘어난다: 게스트 [virtual address](glossary:virtual-address) → 게스트 [physical address](glossary:physical-address) → 실제 [physical address](glossary:physical-address).
- [Hypervisor](glossary:hypervisor)가 **[shadow page table](glossary:shadow-page-table)**로 이 변환을 관리한다. [VM](glossary:vm) 안의 [physical address](glossary:physical-address)는 가짜라서, 게스트 [virtual address](glossary:virtual-address)를 실제 주소로 바로 연결하는 테이블을 따로 두는 거다.
- 또는 수정된 게스트가 [page table](glossary:page-table)을 바꿀 때 [hypervisor](glossary:hypervisor)에 요청한다.

**[I/O virtualization](glossary:io-virtualization)**

- 여러 [VM](glossary:vm)이 디스크, 네트워크 카드 같은 물리 장치를 나눠 쓴다.
- [Hypervisor](glossary:hypervisor)가 장치를 소프트웨어로 흉내 내거나, 게스트에 [virtualization](glossary:virtualization) 전용 [device driver](glossary:device-driver)([virtio](glossary:virtio) 등)를 설치해 직접 통신한다.

# 4. HPC, HTC, 그리드, 클라우드는 어떻게 이어지나

| 키워드                                      | 한 줄 설명                                                                                          |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| [HPC](glossary:hpc)                         | 빠른 계산이 목표. 슈퍼컴퓨터                                                                        |
| [HTC](glossary:htc)                         | 처리량이 목표. 많은 작업을 처리하려고 노는 자원의 활용성을 높임                                     |
| [Grid computing](glossary:grid-computing)   | 전 세계에 흩어진 쉬는 컴퓨터를 묶어 씀. [orchestration](glossary:orchestration) 기반                |
| [Cloud computing](glossary:cloud-computing) | 한 컴퓨터의 자원을 [VM](glossary:vm) 단위로 나눠 씀. [virtualization](glossary:virtualization) 기반 |

**[HPC](glossary:hpc)**는 하나의 계산을 빨리 끝내는 게 목표다. 슈퍼컴퓨터가 여기 해당한다.

처리량이 목표라면 **[HTC](glossary:htc)**를 쓴다. 많은 작업을 처리해야 하니까 놀고 있는 자원을 최대한 활용하는 게 핵심이다.

[HTC](glossary:htc)에 속하는 게 **[grid computing](glossary:grid-computing)**과 **[cloud computing](glossary:cloud-computing)**이다. 둘 다 쉬는 자원을 활용한다는 역할은 같지만 구현 방식이 다르다.

- [grid](glossary:grid-computing)는 전 세계에 흩어진 유휴 컴퓨터들을 **묶어서** 쓴다. 그래서 [orchestration](glossary:orchestration)이 바탕이다.
- 클라우드는 [hypervisor](glossary:hypervisor)로 한 컴퓨터의 자원을 [VM](glossary:vm) 단위로 **나눠서** 쓴다. 이게 [virtualization](glossary:virtualization)다.

# 5. 데이터센터 운영의 3대 이슈와 클라우드

| 이슈                                                 | 클라우드로 해결하는 방법                                                                                                      |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 유휴 자원 찾기 ([utilization](glossary:utilization)) | [virtualization](glossary:virtualization)으로 유휴 자원을 [VM](glossary:vm) 단위로 나눠 사용자에게 서비스로 제공              |
| 문제 서비스 분리 (service stability)                 | [hypervisor](glossary:hypervisor)가 [VM](glossary:vm)끼리 [isolation](glossary:isolation)해서 A의 작업이 B에 영향을 주지 않음 |
| 신속한 복구 (fast recovery)                          | [VM](glossary:vm)을 이미지로 저장해 두고 새로 띄우거나 다른 서버로 옮겨 빠르게 복구                                           |

세 이슈 모두 [virtualization](glossary:virtualization)으로 풀 수 있다. 자원을 잘게 나누고, 서로 [isolation](glossary:isolation)하고, 파일 하나로 통째로 옮길 수 있다는 [VM](glossary:vm)의 성질 덕분이다.
