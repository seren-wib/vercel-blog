# 1. Language Model

주어진 텍스트의 문맥을 기반으로 가장 적절한 다음 단어(next word) 예측하는 확률적 모델

# 2. LLM(Large Language Model)

대량의 텍스트 데이터로 학습된 [Parameter](glossary:parameter) 개수의 매우 많은 [language model](glossary:language-model)

주로 [Transformer](glossary:transformer) 기반의 모델로 구현

## LLM 기본 개념

### 1. 토큰화(tokenization)

1. 문장을 더 작은 단위인 [Token](glossary:token)으로 쪼개는 단계

2. 분리된 [Token](glossary:token)들은 미리 정해진 [vocabulary](glossary:vocabulary)에 따라 정수 ID로 매핑

### 2. 임베딩(embedding)

3. 개별 [Token](glossary:token)을 수백 또는 수천 차원의 수치 [Vector](glossary:vector) 표현으로 변환
   - 유사한 개념들은 [Vector](glossary:vector)상으로 유사한 방향을 가리킨다.
   - 동일 단어도 문맥에 따라 서로 다른 [Vector](glossary:vector) 값을 가진다.

### 변환 단계: 토큰 > 정수 ID > 어휘집(voca) > 임베딩 벡터

### transformer 모델

[large language model](glossary:llm)의 핵심이 되는 신경망 구조

데이터([Token](glossary:token)의 [Embedding](glossary:embedding) [Vector](glossary:vector)들)를 병렬로 처리하며 문맥을 깊이 있게 이해

문장 전체를 한꺼번에 입력받아 처리하므로 학습 속도가 이전에 비해 크게 개선

다음 [Token](glossary:token)(단어, next [token](glossary:token))의 확률분포 계산

### 온도(temperature)

[temperature](glossary:temperature)는 모델이 단어를 선택하기 전에 단어의 확률을 조정하여 텍스트 생성의 무작위성 제어

고온(≥ 1) : 더욱 다양하고 창의적인 결과물

저온(~0) : 보다 집중적이고 예측 가능한 응답 생성

### 샘플링(sampling)

1. [Top-k sampling](glossary:top-k-sampling)
   - 단어 풀(pool) 제한
   - 확률이 가장 큰 상위 K개 중에서 확률적으로 선택
   - 후보 단어 개수 고정, K=5이면 언제나 5개 선별

2. [Top-p sampling](glossary:top-p-sampling)
   - 누적 확률이 p에 도달할 때까지 동적으로 변화하는 단어 풀에서 단어를 선택
   - 후보 단어 개수 변동, 누적확률 p에 도달할 때까지 후보를 넣음.

# 3. Transformer 모델

각 [Token](glossary:token)의 [Embedding](glossary:embedding) [Vector](glossary:vector)에서 [Query, Key, Value](glossary:query-key-value)라는 세 종류의 [Vector](glossary:vector)를 만들고, 한 [Token](glossary:token)의 [Query](glossary:query-key-value)가 모든 [Token](glossary:token)의 [Key](glossary:query-key-value)와 얼마나 관련 있는지 계산한 뒤, 그 관련도만큼 [Value](glossary:query-key-value)들을 섞어서 새 [Vector](glossary:vector)를 만든다

Q([Query](glossary:query-key-value)): 내가 찾고 싶은 정보

K([Key](glossary:query-key-value)): 나는 이런 정보와 관련이 있다

V([Value](glossary:query-key-value)): 실제로 넘겨줄 내용

## 1. 자기주목(self attention) 연산

1. input1, input2, input3이 들어옴
   ```
   예시
   input = [1010, 0202, 1111]
   ```
2. 각 input에서 모델 안에 들어있는 학습된 [weight matrix](glossary:weight)를 곱해서 [query](glossary:query-key-value), [key](glossary:query-key-value), [value](glossary:query-key-value)를 만듦
   ```
   예시
   key = [[0,1,1], [4,4,0], [2,3,1]]
   value = [[1,2,3], [2,8,0], [2,6,3]]
   query = [[1,0,2], [2,2,2], [2,1,3]]
   ```
3. query1이 모든 [key](glossary:query-key-value)와 비교함([Vector](glossary:vector)의 [dot product](glossary:dot-product) 계산)

   ```
   예시
   query1 = [1, 0, 2]

   key1 = [0, 1, 1]
   key2 = [4, 4, 0]
   key3 = [2, 3, 1]

   query1 · key1
   = [1, 0, 2] · [0, 1, 1]
   = 1×0 + 0×1 + 2×1
   = 2
   score1 = 2

   query1 · key2
   = [1, 0, 2] · [4, 4, 0]
   = 4 + 0 + 0
   = 4
   score2 = 4

   query1 · key3
   = [1, 0, 2] · [2, 3, 1]
   = 2 + 0 + 2
   =4
   score3 = 4

   score = [2, 4, 4]
   ```

4. 비교 결과로 score가 나옴

5. score를 [softmax](glossary:softmax)로 비율로 바꿈

   ```math
   softmax(score_i) = \frac{e^{score_i}}{e^{score_1}+e^{score_2}+e^{score_3}}
   ```

   ```
   예시
   score1 = 2
   score2 = 4
   score3 = 4

   query1 = [1,0,2]

   e^2 ≈ 7.389
   e^4 ≈ 54.598
   e^4 ≈ 54.598

   분모 = 7.389 + 54.598 + 54.598 = 116.585

   softmax(2) = 7.389 / 116.585 ≈ 0.063
   softmax(4) = 54.598 / 116.585 ≈ 0.468
   softmax(4) = 54.598 / 116.585 ≈ 0.468

   softmax([2, 4, 4]) ≈ [0.063, 0.468, 0.468]
   ```

6. 그 비율을 모든 [value](glossary:query-key-value)에 곱함

   ```
   예시

   multiplication1
   0.063 × value1
   = 0.063 × [1, 2, 3]
   = [0.063, 0.126, 0.189]

   multiplication2
   0.468 × value2
   = 0.468 × [2, 8, 0]
   = [0.936, 3.744, 0]

   multiplication3
   0.468 × value3
   = 0.468 × [2, 6, 3]
   = [0.936, 2.808, 1.404]
   ```

7. 곱한 [value](glossary:query-key-value)들을 더해서 output1을 만듦

   ```
   예시
   [0.063, 0.126, 0.189]
   + [0.936, 3.744, 0]
   + [0.936, 2.808, 1.404]

   = [1.935, 6.678, 1.593]

   output1 ≈ [1.935, 6.678, 1.593]
   ```

8. query2, query3도 같은 방식으로 output2, output3을 만듦

## 2. 위치 임베딩((positional embedding)) 벡터

[Self-Attention](glossary:self-attention)은 [Token](glossary:token)들 사이의 관계를 계산한다.

그런데 순서 정보가 없으면 문장 의미가 무너진다.

그래서 각 [Token](glossary:token) [Embedding](glossary:embedding)에 [positional embedding](glossary:positional-embedding)을 더한다.

그 결과 [Transformer](glossary:transformer)는 “단어 의미 + 위치”를 함께 입력받는다.

[Token](glossary:token) [Embedding](glossary:embedding)과 같은 차원으로 만들어야 한다.

## 3. Transformer 블록의 구성

### Self-Attention

각 [Token](glossary:token)이 문장 안의 다른 [Token](glossary:token)들을 얼마나 참고할지 계산

### FFN(Feed Forward Network) 또는 MLP

[Self-Attention](glossary:self-attention)이 “[Token](glossary:token)들 사이의 관계”를 처리했다면, [FFN](glossary:feed-forward-network)은 각 [Token](glossary:token) [Vector](glossary:vector)를 따로 받아서 한 번 더 변환

보통 선형층, [activation function](glossary:activation-function), 선형층으로 구성

### Skip Connection(지름길 층)

[self attention](glossary:self-attention)결과 + 원래 입력

이전 레이어 정보를 보존하고 학습을 안정적으로 만들어준다

### LayerNorm(정규화 층)

[Vector](glossary:vector) 값들이 너무 커지거나 들쭉날쭉해지는 걸 정리해주는 정규화.

계산이 계속 쌓이면 값의 분포가 흔들릴 수 있으니까, 각 층마다 안정적으로 맞춰주는 역할

### 흐름

```
입력 벡터(토큰 임베딩 + 위치 임베딩)
↓
Self-Attention
↓
Skip Connection + LayerNorm
↓
Feed Forward Network
↓
Skip Connection + LayerNorm
↓
출력 벡터
```

1. 입력 [Vector](glossary:vector)가 들어온다

2. [Self-Attention](glossary:self-attention)으로 [Token](glossary:token) 간 관계를 반영한다

3. 원래 입력을 더한다
   = [Skip Connection](glossary:skip-connection)

4. 값을 정리한다
   = [LayerNorm](glossary:layer-normalization)

5. [FFN](glossary:feed-forward-network)으로 각 [Token](glossary:token) [Vector](glossary:vector)를 한 번 더 가공한다

6. 다시 원래 값을 더한다
   = [Skip Connection](glossary:skip-connection)

7. 다시 정규화한다
   = [LayerNorm](glossary:layer-normalization)

8. 다음 [Transformer](glossary:transformer) 블록으로 넘긴다

## 4. mulit-head attention(멀티헤드 주목)

[Self-attention](glossary:self-attention) 방식에서는 한 종류의 관계만 강하게 볼 수 있기 때문에 나온 개념.

- [linear projection](glossary:linear-projection)
  - [Vector](glossary:vector)에 [weight matrix](glossary:weight)를 곱해서, 다른 [Vector](glossary:vector) 공간으로 바꾸는 것
  - 차원을 줄일 수도 있고, 늘릴 수도 있고, 같은 차원 안에서 방향만 바꿀 수도 있다.

```
입력 X
↓
head 1용 Q1, K1, V1 생성
head 2용 Q2, K2, V2 생성
head 3용 Q3, K3, V3 생성
...
↓
각 head에서 self-attention 따로 수행
↓
head 출력들을 이어붙임 concatenation
↓
다시 선형 변환
↓
multi-head attention output
```

## 5. 인코더와 디코더

**[Encoder](glossary:encoder)는 입력 문장을 읽어서 의미 [Vector](glossary:vector)들을 만들고, [Decoder](glossary:decoder)는 출력 문장을 만들 때 그 [Encoder](glossary:encoder)의 마지막 층을 참고**

이떄의 참고 방식: [Cross-Attention](glossary:cross-attention)

### Cross-Attention

[Encoder](glossary:encoder) 마지막 층 출력 = 입력 문장을 다 읽고 정리한 [Vector](glossary:vector)들

[Decoder](glossary:decoder)의 [Query](glossary:query-key-value) = 지금 출력하려는 위치에서 필요한 정보 요청

[Encoder](glossary:encoder)의 [Key](glossary:query-key-value) = 각 입력 [Token](glossary:token)이 어떤 정보인지 나타내는 검색 태그

[Encoder](glossary:encoder)의 [Value](glossary:query-key-value) = 실제로 [Decoder](glossary:decoder)에게 넘겨줄 입력 정보

[Cross-Attention](glossary:cross-attention) = [Decoder](glossary:decoder) [Query](glossary:query-key-value)로 [Encoder](glossary:encoder) [Key](glossary:query-key-value)를 검색하고, 맞는 [Value](glossary:query-key-value)를 가져오는 과정

### 인코더 디코더의 추론

주어진 입력에 대한 [Encoder](glossary:encoder)의 출력으로 부터 [key](glossary:query-key-value)와 [value](glossary:query-key-value) [Vector](glossary:vector) 생성

# 4. Transformer를 이용한 모델

## 1. BERT(Bi-directional Encoder Representations from Transformers)

[Transformer](glossary:transformer) [Encoder](glossary:encoder) 기반 모델

두개의 문장을 입력으로 사용 - 문장 A와 문장 B를 넣고, 두 문장이 이어지는 관계인지 판단하는 방식.

### 잘 학습된 BERT 언어모델에 classification layer(분류층)를 붙여서 다양한 NLP task(자연어 처리 작업)를 수행

문장 분류, 감정 분석, [next sentence prediction](glossary:next-sentence-prediction) 같은 작업

1. [Next Sentence Prediction](glossary:next-sentence-prediction)
2. [Autoencoding](glossary:masked-language-modeling)학습: 가려진 [Masked](glossary:masked-language-modeling) [Token](glossary:token) 복원
   - 나는 [\[MASK\]](glossary:masked-language-modeling)을 먹었다
   - MASK된 부분을 문맥을 보고 판단

## 2. GPT(Generative Pre-trained Transformer)

[Transformer](glossary:transformer) [Decoder](glossary:decoder) 기반 모델

[auto-regressive](glossary:autoregressive-model): 이전 출력 결과를 바탕으로 다음 [Token](glossary:token)을 생성

대부분의 [LLM](glossary:llm)에서 사용하는 구조

### GPT 동작 흐름

```
입력 단어
↓
단어를 임베딩 벡터로 변환
↓
트랜스포머 디코더가 처리
↓
다음 단어 예측
↓
예측한 단어를 다시 입력해 포함해 반복 생성
```

# 5. LLM의 학습

## 1. 사전학습(pre-training)

대규모 [corpus](glossary:corpus), 즉 수조 개 [Token](glossary:token) 수준의 텍스트로 다음 [Token](glossary:token) 예측을 학습하는 단계(세계 지식 압축)

1. 이전 단어들로 부터 다음 단어 예측하도록 학습
   - 다음 [Token](glossary:token)(next [token](glossary:token))을 예측하는 단순한 과제 하나로 모든 것 학습
   - 레이블이 데이터 자체에 내재되어 있어 [self-supervised](glossary:self-supervised-learning)

2. 인터넷 전체를 압축해 [Parameter](glossary:parameter)에 녹여 넣는 것
3. 이 단계에서 언어 구조, 사실 지식, 추론 능력의 기반 획득
4. 데이터 품질 필터링이 결정적
5. 고품질 데이터셋은 중복 제거, 음란물 필터, 언어 감지, 품질 분류기 통과

- 이 단계를 마친 모델은 [Base Model](glossary:base-model)이라 함
- 지식은 있지만 지시에 응답하는 방법을 잘 모는 상태 > [SFT](glossary:sft) 필요

## 2. SFT(supervised fine-tuning, 지도 상세학습)

질문과 이상적인 응답 쌍을 보고, 모델이 지시를 받았을 때 어떤 형식과 태도로 답해야 하는지 배우는 단계(형식-태도 학습)

- 데이터 수집 방법
  1. 인간 작성: 전문 어노테이터가 (질문, 이상적 응답) 쌍을 직접 작성. 품질 최고, 비용 최고.
  2. 모델 생성 + 인간 검수: GPT-4로 초안 생성 → 인간이 수정. InstructGPT, Alpaca 방식.
  3. [Self-Instruct](glossary:self-instruct): 모델이 스스로 다양한 지시와 응답을 생성. 품질 편차 큼

- [SFT](glossary:sft) 이후 모델의 특성: 지시를 따르게 됐지만 유해한 요청도 그대로 따를 수 있음 > [RLHF](glossary:rlhf) 필요

## 3. RLHF (reinforcement learning with human feedback, 사용자 피드백 반영 강화학습)

사람이 더 선호하는 답변을 기준으로 모델을 조정(인간 선호 정렬)

- 데이터 수집
  - 동일한 질문에 대해 여러 응답을 생성하고 인간 평가자가 [pairwise comparison](glossary:pairwise-comparison)으로 선호 표시
  - OpenAI의 InstructGPT 용 평가자 인터페이스

모델의 [reinforcement learning](glossary:reinforcement-learning)

- 원래 모델에서 너무 멀어지지 않으면서, 인간의 선호도가 높은 결과가 나오도록 학습

# 6. Multimodal LLM

**텍스트뿐만 아니라 이미지, 음성, 비디오 같은 여러 형식의 데이터를 하나의 모델에서 이해하고 생성하는 모델**

- [Modality](glossary:modality): 데이터 형식(텍스트, 음성, 이미지, 비디오)
- [Projection layer](glossary:projection-layer): 이미지나 음성 같은 다른 [Modality](glossary:modality)를 [Encoder](glossary:encoder)로 [Vector](glossary:vector)화한 다음, 그 [Vector](glossary:vector)를 [LLM](glossary:llm)이 받을 수 있는 형태로 맞춰주는 중간 변환층
- [large language model](glossary:llm)을 [backbone](glossary:backbone)로 하여, 다른 [Modality](glossary:modality)의 데이터는 별도의 [Encoder](glossary:encoder)를 사용하여 [Vector](glossary:vector)화하여 [large language model](glossary:llm)에 입력
- [fine-tuning](glossary:fine-tuning) 학습 필요

## VLM(Vision Language Model)

- 이미지나 영상 같은 시각 정보와 자연어(텍스트)를 동시에 이해하고 처리할 수 있도록 설계된 모델
- '눈'을 가진 것처럼 이미지를 보고 설명하거나 질문에 답하는 다각적인 추론 능력 제공
- 이미지를 [LLM](glossary:llm)이 읽을 수 있는 [Token](glossary:token)으로 번역
