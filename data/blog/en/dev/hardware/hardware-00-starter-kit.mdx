## 0. Introduction

I started hardware as a hobby, and the first project is a portable [Bluetooth](glossary:bluetooth) speaker. I wrote this post before buying anything (November 17, 2026), so every price is what the shops listed on that day.

In restaurant terms, there is a temporary kitchen for testing the menu, a first proper kitchen set up inside the shop, and a flagship building built to the blueprint. Before opening, you buy the knives and cutting boards and fix the order of cooking. The temporary kitchen is the [breadboard](glossary:breadboard), the proper kitchen is the [perfboard](glossary:perfboard), the flagship building is the [PCB](glossary:pcb), the knives and cutting boards are the [soldering iron](glossary:soldering-iron) and [multimeter](glossary:multimeter), and the order of cooking is the five-stage build order.

This post sets the build order and lists what to buy and which tools to learn before starting. The next post will cover receiving the tools and soldering on [perfboard](glossary:perfboard) for the first time.

## 1. What the speaker consists of

A portable speaker that receives music from a phone over [Bluetooth](glossary:bluetooth) and plays it through a speaker. It has four main parts.

| Part                                                                                | What it does                                                                                                                                            |
| ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [ESP32](glossary:esp32) dev board                                                   | Receives sound from the phone over [Bluetooth](glossary:bluetooth). The [firmware](glossary:firmware) I write runs on it                                |
| [I2S](glossary:i2s) [amplifier](glossary:amplifier) board                           | Takes the digital audio signal from the [ESP32](glossary:esp32) and amplifies it enough to drive a speaker ([MAX98357A](glossary:max98357a) or similar) |
| Speaker                                                                             | Makes the sound                                                                                                                                         |
| Battery with charging and [protection circuit](glossary:battery-protection-circuit) | Lets it run without a cable. Added in the very last stage                                                                                               |

I am going with the **original [ESP32](glossary:esp32)**. The [Bluetooth](glossary:bluetooth) mode a phone uses to send music ([A2DP](glossary:a2dp) over Classic [Bluetooth](glossary:bluetooth)) is supported only by the original [ESP32](glossary:esp32), not by the later chips with names like S3 or C3. Even among original [ESP32](glossary:esp32) boards, modules whose name ends in `U` (WROOM-32U) need a separate external antenna, so I pick an `E` or `D` model with the antenna on the board.

## 2. Build order

| Stage | What happens                                                                                                                                                                | Result                                                   |
| ----- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 1     | Plug the [ESP32](glossary:esp32), [amplifier](glossary:amplifier) board and speaker into a [breadboard](glossary:breadboard) and check that it plays sound                  | A working test circuit                                   |
| 2     | Move the same circuit to a [perfboard](glossary:perfboard) and fix it in place with solder. **The first speaker is finished this way**                                      | The first finished build                                 |
| 3     | Design the [schematic](glossary:schematic) and board in [KiCad](glossary:kicad) and order it from a [PCB](glossary:pcb) factory. The wireless part stays a certified module | A second version soldered on a green [PCB](glossary:pcb) |
| 4     | Design the case in a CAD you write in Python ([CadQuery](glossary:cadquery)) and send it to a [3D printing](glossary:3d-printing) service                                   | The case                                                 |
| 5     | Add a [lithium battery](glossary:lithium-battery) and [protection circuit](glossary:battery-protection-circuit)                                                             | The portable version                                     |

There are two reasons for this order. Ordering a board before knowing the circuit works means paying for a wrong board. And handling the first ordered board with hands that have never soldered is an easy way to ruin it. So I check the circuit on a [breadboard](glossary:breadboard), learn soldering on a [perfboard](glossary:perfboard), and only then move to a factory [PCB](glossary:pcb). A [3D printer](glossary:3d-printing) costs quite a bit, so I am not buying one at first. The case goes to a printing service: mainly an online one where I upload the file and get the print shipped, and I also want to visit an offline print shop at least once. The offline candidate is Chungbuk Pro Maker Center (충북Pro메이커센터), which has [3D printers](glossary:3d-printing); I have not checked yet on what terms students can use them. I will buy a printer later. The battery can catch fire if handled wrong, so it goes on last, after the circuit is stable.

Each project lives in its own repo, split into `firmware/` ([firmware](glossary:firmware)), `hardware/` ([KiCad](glossary:kicad) files), `enclosure/` (case) and `docs/`.

## 3. Shopping list

The first purchase is not parts but **tools and consumables**. The [pin header](glossary:pin-header) on the [amplifier](glossary:amplifier) board has to be soldered by hand, so a [soldering iron](glossary:soldering-iron) is needed from stage 1.

The prices below are what each product page showed on November 17, 2026, VAT included (prices in KRW, ₩). The shop is not final yet. I also looked on a price comparison site, but for small tools like these it only turned up bulk industrial packs (1 kg of solder wire, for example) or overseas resellers, so I listed prices from an electronics parts shop.

| [Flux](glossary:flux)                    | SME [flux](glossary:flux) pen HS02 (for [leaded solder](glossary:leaded-solder)) | ₩11,210                                                                  | For when solder just beads up and will not flow                                                                        |

| Desoldering pump                         | EXSO DS-1010                                                                     | ₩7,480                                                                   | For fixing mistakes. A spring pump that sucks up melted solder                                                         |

Two things came up while choosing the iron.

- On the local price comparison site, the [Pinecil](glossary:pinecil) was only sold by overseas resellers, at ₩159,600 to ₩163,100. That is more than four times the official price, so I will order directly from the official store.
- The [Pinecil](glossary:pinecil) needs a **[USB-C PD](glossary:usb-power-delivery) charger of 45 W or more** to heat properly. Phone chargers are usually 15 to 25 W and heat it slowly. A laptop charger almost always works. I am using a charger I already have, so it is off the list.

I am starting with **[leaded solder](glossary:leaded-solder)** (tin mixed with lead). It melts at a lower temperature than [lead-free solder](glossary:lead-free-solder) and flows better, so it is easier to work with. Because it contains lead, I keep the room ventilated and wash my hands after working. Switching to [lead-free solder](glossary:lead-free-solder) also means switching to a [flux](glossary:flux) made for [lead-free solder](glossary:lead-free-solder).

## 4. Tools to learn by stage

Knowing one CAD program is not enough. Each stage needs different tools.

I am doing this with [Claude Code](glossary:claude-code) (an AI coding tool that reads and edits files and runs commands in the terminal). So for each tool I also noted whether [Claude Code](glossary:claude-code) can handle it directly. The rule is simple: tools that work through text files and the [command line](glossary:cli) ([CLI](glossary:cli)), [Claude Code](glossary:claude-code) uses directly; anything that needs mouse work on screen or hands on hardware, I do.

| Mark | Meaning                                                                                                          |
| ---- | ---------------------------------------------------------------------------------------------------------------- |
| ●    | [Claude Code](glossary:claude-code) does it directly (writing files, running commands, checking results)         |
| ◐    | [Claude Code](glossary:claude-code) does part of it (generating files, checks, exports); I do the on-screen work |
| ○    | I do it (hands-on work, payment). [Claude Code](glossary:claude-code) only helps with explanations and checks    |

### 4.1 Stage 1: Breadboard

| To learn                          | What it is                                                                                                                                                                                                                                              | [Claude Code](glossary:claude-code)                                                             |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Circuit basics                    | How voltage, current and resistance relate ([Ohm's law](glossary:ohms-law)), and how to find pin numbers and voltage ranges in a [datasheet](glossary:datasheet). Without this I cannot draw a [schematic](glossary:schematic)                          | ◐ Reads [datasheets](glossary:datasheet) and makes connection tables. Understanding is on me    |
| [PlatformIO](glossary:platformio) | The [firmware](glossary:firmware) development environment. Writing code, compiling for the [ESP32](glossary:esp32), writing it to the board over USB ([flashing](glossary:flashing)) and the [serial monitor](glossary:serial-monitor) all in one place | ● Builds with `pio run`, uploads with `pio run -t upload`, reads logs with `pio device monitor` |
| [Multimeter](glossary:multimeter) | [Continuity](glossary:continuity-test) tests and voltage readings                                                                                                                                                                                       | ○ [Claude Code](glossary:claude-code) tells me what to measure and where                        |
| Soldering                         | Start by soldering resistor legs into a [perfboard](glossary:perfboard)                                                                                                                                                                                 | ○                                                                                               |

I picked the [firmware](glossary:firmware) environment from three options.

| Tool                              | Notes                                                                                  | Choice     |
| --------------------------------- | -------------------------------------------------------------------------------------- | ---------- |
| [Arduino IDE](glossary:arduino)   | Install it and go with a few buttons. The easiest                                      |            |
| [PlatformIO](glossary:platformio) | Board type, library versions and upload settings all live in one `platformio.ini` file | **Chosen** |
| [ESP-IDF](glossary:esp-idf)       | The chip maker's official tool. The most control, but a lot to set up                  |            |

There are four reasons for [PlatformIO](glossary:platformio). It runs inside the editor I already use ([VS Code](glossary:vs-code)), so no new tool. With the settings file committed to the repo, it builds with the same versions on Windows and Mac. Build and upload are one command each, so [Claude Code](glossary:claude-code) can change the code, flash the board and read the logs right away. For the same reason, it is easy to add a [CI](glossary:ci) build check later.

One thing is still open. The [ESP32](glossary:esp32)-A2DP library, which handles receiving music over [Bluetooth](glossary:bluetooth), depends on the [ESP32](glossary:esp32) Arduino core version. I have not checked which core version [PlatformIO](glossary:platformio)'s official [ESP32](glossary:esp32) platform supports. That is the first thing to check when I set up the environment after the board arrives.

### 4.2 Stages 2 and 3: Perfboard and factory PCB

| To learn                                                | What it is                                                                                                                                                                     | [Claude Code](glossary:claude-code)                                                                      |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| [Perfboard](glossary:perfboard) layout                  | A drawing of which part goes in which hole and what connects to what                                                                                                           | ● Makes the connection table and layout. Soldering is ○                                                  |
| [KiCad](glossary:kicad) [schematic](glossary:schematic) | Placing parts as symbols and connecting them with wires                                                                                                                        | ◐ [KiCad](glossary:kicad) files are text, so it can read and edit them. I do the on-screen polishing     |
| [KiCad](glossary:kicad) [PCB](glossary:pcb) layout      | Placing part [footprints](glossary:footprint) on the actual board and drawing the copper traces                                                                                | ◐ I place and route on screen. [Claude Code](glossary:claude-code) helps with placement rules and review |
| [DRC](glossary:drc) (design rule check)                 | Automatically finds traces that are too close or broken                                                                                                                        | ● Runs the check with `kicad-cli` and reads the results                                                  |
| Order files                                             | [Gerber files](glossary:gerber-file) for the [PCB](glossary:pcb) factory, plus a [BOM](glossary:bom) (bill of materials) and placement file when ordering with parts assembled | ● Exports them with `kicad-cli`                                                                          |
| [PCB](glossary:pcb) factory order                       | Upload the files, choose options, pay                                                                                                                                          | ○ I pay                                                                                                  |

A [PCB](glossary:pcb) does not have to come from a factory. There are three ways to make one.

| Method                                         | Pros                                                            | Cons                                                                                 |
| ---------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Hand-wiring on [perfboard](glossary:perfboard) | The most practical way to build a single unit without a factory | The wiring gets messy and the board gets big, which makes a portable case tight      |
| Etching copper board at home                   | You can make it right away                                      | Needs chemical handling, ventilation and waste disposal, and is usually single-sided |
| Factory order                                  | The board arrives with the green coating                        | Takes 1 to 2 weeks and costs shipping. A wrong circuit means ordering again          |

The first speaker will be finished on [perfboard](glossary:perfboard), and a factory order is planned for the next version. I will check the factory cost when I order.

### 4.3 Stage 4: Case

| To learn                      | What it is                                                                                                                                               | [Claude Code](glossary:claude-code)                              |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| [CadQuery](glossary:cadquery) | A CAD for drawing 3D shapes in Python                                                                                                                    | ● Writes and runs the Python code to build the model             |
| Fitting board and case        | Export the board from [KiCad](glossary:kicad) as a 3D file ([STEP](glossary:step)), place it inside the case and line up the screw holes and USB opening | ● Board [STEP](glossary:step) export and dimension checks        |
| Print files                   | Export the [STL](glossary:stl) file to send to the printing service                                                                                      | ● Exports [STL](glossary:stl) from [CadQuery](glossary:cadquery) |
| Printing service order        | Online: upload the file, choose a material, pay. Also visit Chungbuk Pro Maker Center once                                                               | ○                                                                |

I compared two CAD tools that work in code.

| Tool                          | Notes                                                             | Choice     |
| ----------------------------- | ----------------------------------------------------------------- | ---------- |
| [OpenSCAD](glossary:openscad) | Its own language. Easy to learn                                   |            |
| [CadQuery](glossary:cadquery) | A Python library. Easier for complex shapes such as rounded edges | **Chosen** |

There are three reasons for [CadQuery](glossary:cadquery). It is a language I already use (Python), so no new syntax. Dimensions can be variables, and changes can be tracked in [Git](glossary:git). And because it is code, [Claude Code](glossary:claude-code) can write and change it directly. With a mouse-driven CAD, all of this part would have been on my hands.

A [slicer](glossary:slicer) (the program that turns a model into printer instructions) is handled by the service, so I will learn it when I buy a printer.

### 4.4 Stage 5: Battery

No new tools. It is about understanding the [lithium battery](glossary:lithium-battery) charging board and [protection circuit](glossary:battery-protection-circuit) (the circuit that prevents overcharge, over-discharge and short circuits). Wiring it wrong can start a fire, so I check the connections against the [datasheets](glossary:datasheet) with [Claude Code](glossary:claude-code) and do the hands-on work myself.
