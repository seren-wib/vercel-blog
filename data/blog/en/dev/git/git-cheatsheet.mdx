## 0. Introduction

A personal cheatsheet for when I get confused. Run the commands in a terminal after moving into the [repository](glossary:repository) folder.

In restaurant terms, the working folder on my computer is the kitchen and the [repository](glossary:repository) on [GitHub](glossary:github) is the head-office storeroom. A photo of a finished plate is a record of one change, and setting a plate that is still being cooked into a drawer for a moment is putting work aside. That is, the kitchen is the local [repository](glossary:repository), the storeroom is the [remote](glossary:remote) called [origin](glossary:origin), the photo is a [commit](glossary:commit), and the drawer is a [stash](glossary:stash).

This post covers checking status, a [pull](glossary:pull) that loses no changes, resolving [conflicts](glossary:merge-conflict), committing and [pushing](glossary:push), and undoing changes.

---

## 1. Checking the Current State

```bash
git status              # which files changed
git log --oneline -10   # the 10 most recent commits
git fetch               # only fetches remote info (files don't change)
git log HEAD..@{u} --oneline   # commits that are on the remote but not on mine
```

---

## 2. Pulling Without Losing Changes

What I did on 2026-06-13. When I have files being edited locally and the [remote](glossary:remote) also has new [commits](glossary:commit).
A plain `git pull` stops or is refused on overlapping files. The safe order:

```bash
# 1. Put local changes away in the drawer (-u also includes newly created untracked files)
git stash push -u -m "stash before pull"

# 2. Fetch the remote from the clean state
git pull --ff-only

# 3. Take the stashed changes back out
git stash pop
```

- If files overlap, `stash pop` produces a **[conflict](glossary:merge-conflict)** → go to section 3 below.
- No data is lost. Even on a [conflict](glossary:merge-conflict), the [stash](glossary:stash) stays in `git stash list`.

---

## 3. Resolving Conflicts

When you open a conflicted file, it contains [markers](glossary:conflict-marker) like these:

```
<<<<<<< Updated upstream
Remote (fetched side) content
=======
My local (stash) content
>>>>>>> Stashed changes
```

How to resolve:

1. Keep only the content you want and **delete the three [marker](glossary:conflict-marker) lines yourself** (`<<<`, `===`, `>>>`)
2. If both sides are needed, keep both and delete only the [markers](glossary:conflict-marker)
3. Stage the cleaned-up file:

```bash
git add "path/to/file"
```

**Delete vs modify [conflict](glossary:merge-conflict)** (one side deleted the file and the other edited it):

```bash
git rm "path/to/file"      # when choosing deletion
# or
git add "path/to/file"     # when choosing to keep it (the file stays)
```

Once all [conflicts](glossary:merge-conflict) are cleaned up, empty the [stash](glossary:stash) drawer:

```bash
git stash drop         # delete the stash just popped
git stash list         # check the remaining stashes
```

---

## 4. Committing and Pushing

```bash
git add .                    # stage all changes (or just "file name")
git commit -m "message"        # commit
git push                     # upload to the remote (GitHub)
```

---

## 5. Undoing (When You Make a Mistake)

```bash
git restore "path/to/file"           # discard edits and go back to the last commit's state
git restore --staged "path/to/file"  # undo an add (changes are kept)
git stash list               # list of stashed changes
git stash pop                # take the most recent stash back out
git reset --hard HEAD        # ⚠️ discards all local changes (cannot be undone, careful)
```
