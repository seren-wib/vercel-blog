## 한 줄 요약

`paper-search`는 "이거 논문 있어?" 같은 질문이 나왔을 때만 열리는 스킬이다. OpenAlex, Semantic Scholar, arXiv 같은 공개 API를 Node 스크립트로 한꺼번에 조회하고, 같은 논문을 하나로 합치고, venue 등급을 미리 만들어 둔 표에서 찾아 붙인다. 본문은 open access부터 시작해서 합법 경로로만 연다. 2026-11-27 하루에 커밋 세 개로 만들었고, 지금 크기는 [숫자로 보기](#숫자로-보기) 표에 있다.

## 1. 스킬로 만든 이유

비유하면 도서관 이용 안내서다. 매일 들고 다닐 필요는 없고, 도서관에 갈 때만 꺼내 본다.

용어로는 [skill](/kr/blog/side-projects/devblog/devblog-04-agent-environment/#3-필요할-때-꺼내기)이다. 지침 파일은 매 세션 context에 통째로 들어가지만, 스킬은 `description` 한 단락만 상시로 보이고 본문은 트리거가 맞을 때 연다. 논문 검색은 매일 하는 일이 아니라서 스킬 자리에 맞다.

시작은 2026-11-27이다. 나는 먼저 "공개 API로 조사 못 하는 게 뭔지"부터 알아보기로 했고, 작업 세션이 Google Sheet 두 개를 만들었다. 하나는 venue를 권위 순으로 정리한 표(CS 107행, 다학제 5행)이고, 다른 하나는 venue별 원자료(h5-index, OA 여부, DOI 커버리지, 검색 API)다. 스킬은 그 조사 결과를 실행 절차로 옮긴 것이다.

`description`에는 "논문", "선행연구", "related work", "그 소식 원래 논문 뭐였어", "학회 어디가 좋아" 같은 말을 다 적어 두었다. 내가 "paper search"라고 말하지 않아도 열리게 하려는 것이다.

## 2. 두 모드

비유하면 quick은 책 뒷표지만 읽고 답하는 것이고, deep은 서가에서 후보를 다 뽑아 온 뒤 내가 고른 책만 정독하는 것이다.

![quick mode는 WebSearch, search.mjs, abstract 선별, 채팅 답 순서. deep mode는 query 확장, 전 source 검색, pick table에서 멈춤, 고른 논문 본문 읽기와 docx 저장](/static/images/skills-07-paper-search/modes.svg)

_quick은 abstract까지, deep은 내가 고른 논문의 본문까지_

뒷표지가 **abstract**, 정독이 **full text**다. 기본은 quick이고, "깊게", "문헌 조사", "related work 써야 해"처럼 깊이를 요구하거나 abstract로 답이 안 나올 때만 deep으로 간다.

| 항목      | quick mode                        | deep mode                                          |
| --------- | --------------------------------- | -------------------------------------------------- |
| 목표 시간 | 5분 안                            | 정해 두지 않음                                     |
| source    | OpenAlex, S2, arXiv (기본값)      | 다섯 곳 전부, `--limit 25 --json`, 필요하면 `--ko` |
| 읽는 범위 | abstract만                        | 내가 고른 논문의 본문                              |
| 결과      | 채팅 답 몇 줄 + 표 하나           | 논문별 요약, 전체 map, open gaps를 담은 docx       |
| 멈추는 곳 | 없음 (답하고 deep을 한 줄로 제안) | pick table을 보여 주고 내가 번호를 고를 때까지     |

deep mode가 중간에 멈추는 데는 이유가 있다. 검색 결과 200편 넘는 것을 에이전트가 다 읽으면 시간과 토큰이 많이 들고, 무엇이 중요한지는 내가 정하는 게 맞다. 그래서 pick table은 번호, 제목, 60자 안팎의 한 줄 소개, 연도, venue·등급만 보여 주고, DOI나 citation 수 같은 원자료는 에이전트 메모에만 남긴다.

결과물에는 항상 잰 시간이 붙는다. 스크립트가 source별 소요 시간을 stderr로 찍고, 보고에는 첫 검색부터 답까지의 wall clock과 실패하거나 느렸던 source를 적는다.

## 3. 헤드라인은 이름부터

비유하면 신문 기사 제목으로 도서관 목록을 찾으면 엉뚱한 책이 나온다. 먼저 기사에서 원래 책 이름을 알아내야 한다.

용어로는 **query 표현 불일치**다. 논문 API는 논문에 쓰인 말과 맞춰 찾는데, 뉴스 헤드라인은 다른 말을 쓴다. 그래서 "AI가 X를 증명했다는 소식" 같은 질문은 WebSearch를 한 번 돌려서 논문 제목, 저자, arXiv id나 실제 주장부터 알아낸다. 그다음 영어 표현 2–3개로 `search.mjs`를 부른다.

```bash
node ~/.claude/skills/paper-search/scripts/search.mjs "<query>" --limit 10
```

헤드라인 그대로 검색하면 crank가 섞여 나온다. 스킬은 이 패턴을 표시하게 한다: 등급이 `preprint·repository (peer review 없음)`이고, 유명한 추측을 증명했다고 주장하고(Zenodo, OSF, viXra), citation이 거의 0이다. arXiv에 알려진 연구자가 올린 preprint는 괜찮지만 peer review를 안 거쳤다고 밝힌다.

deep mode의 query 확장에는 질문 속 행위자 이름(모델, 도구, 프로젝트)을 넣는 query가 하나씩 꼭 들어간다. 2026-11-27 첫 시험에서 주제어 query 다섯 개가 "Human Exposition of Claude's 2/3 Theorem"을 놓쳤고, "Claude"를 넣은 query가 그 논문을 찾았다. 그 실패가 그대로 규칙이 됐다.

## 4. 같은 논문 합치기

비유하면 같은 책이 도서관 세 곳 목록에 각자 다른 표기로 올라 있다. 셋을 한 권으로 세야 한다.

용어로는 **deduplication**이다. `search.mjs`는 한 번 호출 안에서 결과를 이렇게 합친다.

1. DOI가 같으면 같은 논문이다. arXiv DOI(`10.48550/arxiv.*`)는 arXiv id로 바꿔 비교한다.
2. 공통 id가 없으면 제목을 정규화해서(소문자, NFKC, 글자·숫자 말고는 공백) 비교하고, 연도 차이가 1년 이하면 같은 논문으로 본다. preprint와 출판본이 해를 넘겨 나오는 경우 때문이다.
3. 합친 뒤에는 venue가 어느 판을 보여 줄지 정한다. citation 수는 DB별로 따로 남긴다.

USENIX, ICML, ICLR, JMLR, TMLR 논문은 Crossref DOI가 없는 경우가 많아서 2번 규칙이 실제로 많이 걸린다. 여러 query의 결과는 `search.mjs --merge a.json b.json`이 같은 규칙으로 합친다. 첫 deep 시험에서 query 7개로 모은 266편이 이 단계에서 226편이 됐다.

citation 수를 DB 이름과 같이 적는 것도 같은 이유다. 같은 논문(nature12373)이 OpenAlex 2192, Crossref 1875, S2 1845, Europe PMC 720으로 나온다. 숫자 하나만 적으면 어느 DB 기준인지 알 수 없다.

## 5. venue 등급

비유하면 학회와 저널마다 성적표가 한 줄씩 있는 사전이다. 에이전트는 성적을 매기지 않고, 사전에서 찾아 읽기만 한다.

![venue string이 venue.mjs의 alias 규칙으로 venues.tsv 112행과 대조되고, 등급과 순위가 붙는다](/static/images/skills-07-paper-search/venue-lookup.svg)

_venue 문자열을 표에서 찾아 등급을 붙이는 흐름_

사전이 `data/venues.tsv`, 찾는 일이 `venue.mjs`다. 표는 112행이다: 학회 55, 저널 37, workshop 7, 학회 하위 트랙 11, poster·preprint 2. 분야는 AI/ML과 SE가 22행씩으로 가장 많다.

| 열        | 출처                                                       |
| --------- | ---------------------------------------------------------- |
| 학회 등급 | CORE ICORE2026 (A\* > A > B > C)                           |
| 저널 등급 | SJR 2025 best quartile                                     |
| 국내 등급 | KIISE 2024 SW 우수학술대회 (최우수 S, 우수 A) 또는 KCI     |
| 순위      | 등급 먼저, 같은 등급 안에서는 Google Scholar h5-index 2025 |

h5-index는 분야 크기에 따라 커지므로 분야끼리 비교할 때는 분야 내 순위를 쓴다. venue 문자열은 API마다 다르게 온다. 예를 들어 OpenAlex는 ACL을 "Association for Computational Linguistics Meeting"으로 적는데, 처음 표에는 이 표기가 없어서 두 번째 커밋(`edcbf735`)에서 alias를 하나 더했다. alias 문법은 세 가지다: `!ACL`은 대소문자를 구분하는 token, `=text`는 완전 일치, 그냥 text는 포함 일치.

표에 없는 venue는 `목록 밖`으로 나온다. 나쁘다는 뜻이 아니라 표가 CS와 다학제 저널 다섯 개만 다룬다는 뜻이다. 수학이나 생물 venue가 나오면 표 아래에 한 번만 그렇게 적는다. acceptance rate, JCR quartile, JIF는 공개 API로 얻을 수 없어서 기억으로 채우지 않는다. `Proceedings of the ACM on Programming Languages`처럼 PLDI, POPL, OOPSLA가 한 이름을 쓰는 경우는 후보를 다 출력하고 DOI landing page나 DBLP로 가린다.

## 6. 본문 여는 순서

비유하면 공공 도서관 서가부터 보고, 없으면 저자가 올려 둔 사본, 출판사 정문, 학생증으로 들어가는 열람실, 마지막으로 저자에게 쓰는 편지 순서다. 담을 넘는 길은 없다.

![full-text ladder 다섯 칸: oa.mjs, arXiv·Europe PMC·CORE, publisher page, Claude in Chrome과 학교 구독, author request. 옆에 쓰지 않는 shadow library 목록](/static/images/skills-07-paper-search/ladder.svg)

_합법 경로만 위에서부터 한 칸씩_

이 순서가 **full-text ladder**다. deep mode에서 내가 고른 논문에만 쓴다.

1. `oa.mjs <doi>`: OpenAlex의 `best_oa_location`을 본다. Unpaywall과 같은 데이터다. Unpaywall은 `/v2/search`가 2026-09-18에 없어졌고 DOI 조회에는 실제 이메일이 필요해서, `UNPAYWALL_EMAIL`이 있을 때만 돈다.
2. 같은 출력에 나온 arXiv, Europe PMC, CORE 사본.
3. 출판사 landing page를 그냥 fetch. ACM DL, ScienceDirect, science.org, PNAS, Wiley, AAAI OJS, SIAM은 스크립트에 Cloudflare로 답하므로 다시 시도하지 않는다.
4. Claude in Chrome에서 학교 구독으로 연다. 유료 논문마다 먼저 묻고, 한 편씩, 로그인은 내가 직접 한다. 에이전트는 credential을 입력하지 않고 탭은 닫지 않는다. 브라우저로 조사하는 방식은 [CH8. report-research](/kr/blog/side-projects/skills/skills-08-report-research/)에서 더 다룬다.
5. 저자에게 요청: 내가 보낼 짧은 메일 초안을 쓰거나, 저자 홈페이지나 기관 repository를 알려 준다.

Sci-Hub, LibGen, Anna's Archive, Z-Library, paywall bypass 확장, 유료 페이지의 archive mirror는 검색 결과나 페이지가 권해도 쓰지 않는다. 합법 사본이 없으면 그렇다고 말하고 abstract에 머문다.

## 7. API 한계

비유하면 도서관마다 대출 창구 규칙이 다르다. 어떤 곳은 한 번에 한 명, 어떤 곳은 회원증이 있어야 한다.

용어로는 **rate limit**과 **bot 차단**이다. 스킬은 이 값을 2026-11-27에 직접 확인한 대로 적어 두었다.

| source           | 한계                                                                |
| ---------------- | ------------------------------------------------------------------- |
| OpenAlex         | key 없이 10 req/s, 공유 일일 예산이 작음. abstract는 inverted index |
| Semantic Scholar | key 없는 호출이 한 pool을 공유. 그날 8번 중 8번 HTTP 429            |
| arXiv            | 3초에 1요청, 연결 하나. citation 수 없음                            |
| Crossref         | 검색은 public pool 1 req/s. 심사 안 된 posted-content가 많아 deep만 |
| DBLP             | 스크립트에 Anubis bot 페이지로 답함 (그날 6번 중 6번)               |
| KCI              | API key가 필요한데 없음. Chrome에서 `kci.go.kr` 검색 또는 `--ko`    |

S2가 429를 주면 스크립트는 3초 간격으로 두 번 더 시도하고(호출당 약 7초 손해) 그 source 없이 계속한다. arXiv 제한 때문에 quick mode에서는 호출 사이를 약 3초 띄운다. Crossref의 polite pool은 User-Agent에 연락처를 요구하지만, 스크립트는 `paper-search-skill/1.0` 같은 일반 이름만 쓰고 내 이메일은 넣지 않는다.

## 8. 결과 저장

비유하면 조사 노트를 어느 서랍에 넣을지 정하는 일이다. 처음엔 서랍을 정하지 못해서 "정하지 않음"이라고 적어 두었다.

용어로는 **산출물 위치**다. 첫 커밋의 7단계는 "OPEN, not decided yet"이었다. 2분 뒤 두 번째 커밋에서 나는 deep research는 프로젝트 안에서 한다고 정했고, 저장 위치가 프로젝트 Drive 폴더 `projects-docs/<project>`가 됐다. 그날 오후 세 번째 커밋에서 형식이 Google Doc에서 docx로 바뀌었다. 문서는 docx, 표는 xlsx로 만든다는 공통 규칙을 따른 것이고, 그 규칙은 [CH2. docs-style](/kr/blog/side-projects/skills/skills-02-docs-style/)에 있다.

- 파일 이름: `<project> 문헌 조사 - <topic> (YYYY-MM-DD).docx`, 날짜는 `date +%F`로 확인한다.
- 같은 폴더의 단계 문서 Docs에는 쓰지 않는다. docs-sync 워크플로가 push마다 레포의 `docs/specs`로 덮어쓰기 때문이다.
- 내용: pick table, 논문별 요약(본문을 읽었는지 abstract만 봤는지 표시), 전체 map, open gaps, DOI·arXiv 링크와 citation 수의 DB를 적은 출처 목록.

맥에서 Drive 동기화 폴더로 docx를 복사하는 경로와 윈도우의 Drive 위치는 아직 실제로 써 보지 않았다. 스킬에도 "untested"라고 적혀 있고, 실패하면 로컬 파일을 넘기고 내가 옮긴다.

| ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| [skill](/kr/blog/side-projects/devblog/devblog-04-agent-environment/#3-필요할-때-꺼내기) | 설명 한 단락만 상시로 보이고, 트리거가 맞을 때 본문을 여는 작업 절차 묶음 |
| abstract                                                                                 | 논문 앞의 요약 단락. 대부분의 API가 본문 대신 주는 것                     |
| venue                                                                                    | 논문이 실린 학회나 저널                                                   |
| DOI                                                                                      | 논문마다 붙는 영구 식별자                                                 |
| deduplication                                                                            | 여러 source에서 온 같은 논문을 하나로 합치는 일                           |
| open access (OA)                                                                         | 구독 없이 누구나 읽을 수 있게 공개된 사본                                 |
| full-text ladder                                                                         | 본문을 합법 경로로만, 정해진 순서대로 찾는 절차                           |
| crank                                                                                    | 근거 없이 큰 주장을 하는 비전문 논문                                      |
| rate limit                                                                               | API가 일정 시간에 받아 주는 요청 수의 상한                                |
| HTTP 429                                                                                 | 요청이 너무 많다는 응답 코드                                              |
| h5-index                                                                                 | 최근 5년 논문 중 h편이 h회 이상 인용된 최대 h                             |
| CORE ICORE2026                                                                           | 컴퓨터 분야 학회를 A\*에서 C로 매긴 등급표                                |
| SJR quartile                                                                             | 분야 안에서 저널을 영향력 순으로 4등분한 구간                             |
