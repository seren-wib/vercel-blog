## 0. 들어가며

- 사이드 프로젝트 아이디어는 늘 이미 아는 기술에서 출발함. 그러면 새로 손대 보는 기술이 거의 안 생김
- 그래서 내 기술 목록에서 **무작위로 몇 개를 뽑고**, 그 조합으로 Claude와 아이디어를 내 보고 싶었음
- 문제는 모델한테 "랜덤으로 골라"를 맡기면 진짜 랜덤이 아니라는 것. [React](glossary:react), [Docker](glossary:docker), [PostgreSQL](glossary:postgresql)처럼 이미 익숙한 이름으로 계속 쏠림
- 그러면 뽑기는 스크립트가 하고, Claude는 뽑힌 결과로 아이디어만 내면 됨

식당으로 비유하면 늘 먹던 메뉴만 시키는 손님에게 추첨기로 재료 몇 개를 뽑아 주고, 요리사가 그 재료를 전부 써서 요리를 내는 구조임. 여기서 손님은 나, 메뉴판은 `techs.json`, 추첨기는 [Seed](glossary:seed)가 있는 [PRNG](glossary:prng)인 [mulberry32](glossary:mulberry32), 요리사는 Claude, 이 식당 전체는 [Claude skill](glossary:claude-skill)임.

기술 목록에서 무작위로 몇 개를 뽑고 그 조합으로 Claude와 프로젝트 아이디어를 내는 [Claude skill](glossary:claude-skill) **random-idea**를 만들었음. [Claude Code plugin](glossary:claude-code-plugin)으로도 설치됨. 레포는 [seren-wib/random-idea-generator](https://github.com/seren-wib/random-idea-generator)

## 1. 비슷한 도구 조사

만들기 전에 찾아본 것들 (2026-11-17 기준)

- **StackRoulette** (⭐12): 웹 스택만 다루고, 2023-02 이후 멈춰 있음
- **random-stack 류 레포**: 별 0~2개짜리 작은 레포들
- **Hack Club What Should I Build?**, **onemillionideas**: 프로젝트 아이디어를 보여주는 사이트
- **IdeaXApi**, **Pickproject**: 아이디어 생성에 [LLM](glossary:llm)을 붙인 형태
- **분야별 개수를 정해서 뽑는 것**("AI 하나, 하드웨어 하나, [Frontend](glossary:frontend) 둘")은 못 찾았음. 그래서 직접 만들기로 함

## 3. 시드로 뽑기

`scripts/pick.mjs`가 뽑음

- [Seed](glossary:seed)가 있는 [PRNG](glossary:prng) **[mulberry32](glossary:mulberry32)**로 뽑음. 같은 [Seed](glossary:seed)면 어느 컴퓨터, 어느 [Node](glossary:nodejs) 버전에서도 같은 결과가 나옴
- 결과는 [Markdown](glossary:markdown) 표와 [Seed](glossary:seed) 한 줄. [Seed](glossary:seed)를 다시 넣으면 같은 추첨을 반복할 수 있음

```bash
node scripts/pick.mjs [options]
```

| 옵션                          | 하는 일                                              |
| ----------------------------- | ---------------------------------------------------- |
| `-n`, `--count N`             | 전체에서 N개 뽑기. 기본 4                            |
| `--from "AI/ML=1,Frontend=2"` | 분야별로 개수를 정해 뽑기. 분야 이름은 대소문자 무시 |
| `--seed S`                    | 예전 추첨 반복                                       |
| `--categories`                | 분야와 분야별 개수 보기                              |
| `-h`, `--help`                | 옵션 보기                                            |

- `-n`과 `--from`은 같이 못 씀

## 4. Claude가 아이디어를 내는 순서

1. 요청 문장("AI 하나, 하드웨어 하나로 아이디어 줘")을 옵션으로 바꿔서 `pick.mjs`를 실행
2. 뽑힌 표와 [Seed](glossary:seed)를 보여줌
3. 아이디어 3개를 냄. 아이디어마다 뽑힌 기술을 어디에 쓰는지, 주말에 끝낼 수 있는 가장 작은 버전, 가장 막힐 것 같은 부분

- **바꿔치기 금지.** 조합이 어색해 보여도 뽑힌 기술을 하나도 빼거나 다른 걸로 바꾸지 않게 [Claude skill](glossary:claude-skill)에 적어 둠. [Database](glossary:database)나 [Hosting](glossary:hosting)처럼 따로 필요한 건 "also needed" 줄로 분리
- **목록은 대화에 안 읽힘.** 500 KB짜리 `techs.json`은 스크립트만 읽고, 대화에는 뽑힌 줄만 들어감. 그래서 한 번 뽑는 데 [Token](glossary:token) 몇백 개면 됨

## 5. 설치

[Claude Code](glossary:claude-code)에서 마켓플레이스를 추가하고 [Claude Code plugin](glossary:claude-code-plugin)을 설치

```bash
claude plugin marketplace add seren-wib/random-idea-generator
```

```bash
claude plugin install random-idea@seren-wib
```

- 새 세션을 열거나 열린 세션에서 `/reload-plugins`
- [Claude skill](glossary:claude-skill)이 `node`를 실행하므로 터미널에서 `node --version`이 돼야 함

## 7. 만들면서 바뀐 결정

- **웹페이지 없이 [CLI](glossary:cli)로.** 뽑기 화면은 만들지 않음. 아이디어는 어차피 Claude와 대화하면서 냄
- **[CLI](glossary:cli) 레포 대신 [Claude skill](glossary:claude-skill) 하나로.** 따로 설치하는 [CLI](glossary:cli) 도구 대신 [Claude skill](glossary:claude-skill) 폴더 하나(`SKILL.md`, 스크립트, 목록)에 다 넣음
- **아는 정도(known) 칸은 뺌.** 기술마다 아는지 표시해서 아는 것과 모르는 것의 비율로 뽑는 칸을 넣으려다 뺐음
- **private → 공개, 영어로.** 처음엔 private 레포였다가 공개로 바꾸고, [README](glossary:readme)와 목록을 영어로 씀
