## 0. 들어가며

[정적 사이트](glossary:static-site)인 이 블로그에 글 읽기 말고도 코드를 직접 돌려 보는 Playground, 정렬 과정을 보여 주는 시각화, 글마다 달리는 댓글을 붙이고 싶었음. 코드를 받아 줄 [서버](glossary:server)와 댓글 DB는 만들지 않기로 함.

식당으로 비유하면 이 블로그는 주방 없이 미리 만든 도시락만 파는 가게. 손님이 요리를 주문하면 가게 안에서 직접 만들고, 못 만드는 건 옆집에 시키고, 방명록은 이웃 가게 장부를 빌림. 도시락 가게는 [Static site](glossary:static-site), 가게 안 요리는 브라우저 안 실행([Web Worker](glossary:web-worker), [Pyodide](glossary:pyodide)), 옆집은 [Compiler Explorer](glossary:compiler-explorer) [API](glossary:api), 이웃 장부는 [GitHub Discussions](glossary:github-discussions).

[Vercel](glossary:vercel)에서 서버 없이 SQL, HTML, JavaScript, Python, C, C++ 실행 창을 만들고, 그 위에 정렬 시각화를 얹고, [giscus](glossary:giscus)로 댓글창을 붙임.

![시스템 아키텍처 다이어그램. 작성자가 mdx를 GitHub main에 PR로 올리면 GitHub Actions가 검사하고 Vercel이 contentlayer2와 Next.js로 빌드해 /kr·/en 정적 페이지를 배포하고, 방문자 브라우저는 middleware를 거쳐 페이지를 받아 Pyodide·sql.js·Web Worker로 코드를 실행하며 giscus(GitHub Discussions)·Compiler Explorer·Umami·AdSense를 직접 호출한다](/static/images/devblog-01-playground/system-architecture.drawio.svg)

## 1. 언어별로 실행할 곳 고르기

질문은 하나로 줄어듦. **"이 언어는 어디서 실행할 수 있나"**

| 언어       | 실행 위치                                                           | 이유                                                                                                                           |
| ---------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| SQL        | 브라우저 ([sql.js](glossary:sqljs), [SQLite](glossary:sqlite) WASM) | [데이터베이스시스템 3장](/kr/blog/cs-fundamentals/database-systems/database-systems-ch3-sql/#0-직접-돌려보기)에 만든 것 재사용 |
| JavaScript | 브라우저 ([Web Worker](glossary:web-worker))                        | 브라우저가 원래 돌리는 언어                                                                                                    |
| HTML       | 브라우저 ([sandbox](glossary:sandbox) [iframe](glossary:iframe))    | 브라우저가 원래 그리는 언어                                                                                                    |
| Python     | 브라우저 ([Pyodide](glossary:pyodide))                              | [CPython](glossary:cpython)을 [WebAssembly](glossary:webassembly)로 옮긴 것. 약 10MB                                           |
| C, C++     | 외부 서버 ([Compiler Explorer](glossary:compiler-explorer))         | 컴파일러를 브라우저로 옮기면 수십 MB. 공개 [API](glossary:api)에 맡김                                                          |

- Piston 공개 [API](glossary:api)는 키 없이 부르면 `401`이라 제외. Compiler Explorer(godbolt.org)는 [API](glossary:api) 하나로 컴파일과 실행이 되고 `Access-Control-Allow-Origin: *`라 다른 사이트에서 불러도 [CORS](glossary:cors)에 안 막힘
- 대가: C/C++ 코드가 godbolt로 전송되고 호출 제한이 있음. 연습용이라 받아들임
- 언어 목록은 `data/playground.ts` 한 곳에만 있고, 상단 메뉴·카드 페이지·연습 창 주소·[sitemap](glossary:sitemap)이 전부 이 배열을 읽음. `generateStaticParams`로 6개 언어 × 한/영 = 12페이지를 빌드 때 만듦
- 상단 바 드롭다운은 [JavaScript](glossary:javascript) 없이 [CSS](glossary:css)만으로 만듦(`group-hover`, `group-focus-within`이라 Tab으로도 열림). 링크와 목록 사이 `pt-2` 여백은 **목록 쪽에** 둬서 마우스가 내려가는 동안 hover가 안 끊김. 기존 메뉴는 `overflow-x-auto` 상자라 목록이 잘려서, Playground는 그 상자 **밖**에 둠

## 2. 에디터와 JavaScript Worker

- 문법 색([Syntax highlighting](glossary:syntax-highlighting)), 줄 번호, 괄호 짝, Tab 들여쓰기가 필요해서 textarea 대신 [CodeMirror](glossary:codemirror) 6. 하이라이트 스타일을 `Compartment`에 넣고 다크 모드가 바뀌면 그 칸만 교체해서 커서와 내용이 유지됨
- `Prec.highest`로 Ctrl/⌘+Enter 실행을 기본 키맵보다 먼저 잡음. godbolt 에러에는 줄·칸 번호가 있어서 `@codemirror/lint`의 `setDiagnostics`로 넘기면 해당 줄에 빨간 밑줄. 코드와 [stdin](glossary:stdin)은 [localStorage](glossary:localstorage)에 저장
- 페이지에서 바로 [eval](glossary:eval)하면 `while (true) {}` 한 줄에 탭 전체가 멈춤. **실행마다 새 [Web Worker](glossary:web-worker)**를 만들고 멈추면 `worker.terminate()`로 버림. `console.log`를 덮어써 [postMessage](glossary:postmessage)로 출력을 보내고, 코드를 `AsyncFunction`으로 감싸 맨 바깥 `await`를 허용

```js:public/static/playground/js-worker.js
console.log = function () { send('out', arguments) }

const AsyncFunction = Object.getPrototypeOf(async function () {}).constructor
self.onmessage = (e) => {
  new AsyncFunction(e.data.code)().then(
    () => self.postMessage({ type: 'done' }),
    (err) => { self.postMessage({ type: 'err', text: errorText(err) }); self.postMessage({ type: 'done' }) }
  )
}
```

- 15초 안에 안 끝나면 [Worker](glossary:web-worker)를 죽이고 "시간 제한" 줄을 찍음. 본문이 끝나도 바로 안 죽이는 건 [setTimeout](glossary:settimeout)으로 나중에 찍히는 출력까지 받으려는 것

## 3. HTML은 sandbox iframe

- `<iframe srcdoc>`에 `sandbox="allow-scripts allow-modals allow-forms allow-popups"`. `allow-same-origin`은 **일부러 뺌**. 그러면 [iframe](glossary:iframe)이 이름 없는 [출처](glossary:same-origin-policy)가 돼서 안의 스크립트가 블로그 페이지나 저장소를 못 건드림
- `<head>` 바로 뒤에 작은 스크립트를 끼워 `console.*`과 에러를 `parent.postMessage`로 보냄. 페이지는 그 [iframe](glossary:iframe)의 메시지만 받음. 입력이 멈추고 0.6초 뒤 미리보기를 새로 그림
- 버그: `srcdoc`만 바꾸면 첫 화면이 가끔 빈 채로 남았음(같은 HTML을 새 [iframe](glossary:iframe)에 넣으면 정상). 갱신마다 [React](glossary:react) `key`를 바꿔 [iframe](glossary:iframe)을 새로 만들게 한 뒤 사라짐

## 4. Python은 Pyodide

- [npm](glossary:npm) `pyodide` 314.0.7(Python 3.14)의 런타임 파일 5개(약 12MB)를 `public/static/pyodide/`로 복사해 이 사이트에서 직접 내려줌. git에 12MB를 안 넣으려고 `.gitignore`에 두고 `predev`·`prebuild` 스크립트가 `node_modules`에서 복사함. Vercel도 `npm run build`라 같이 돎

```json:package.json
"predev": "node ./scripts/copy-pyodide.mjs",
"prebuild": "node ./scripts/copy-pyodide.mjs",
```

- [Worker](glossary:web-worker) 안에서 돌려 [무한 루프](glossary:infinite-loop)를 죽일 수 있게 함. 로딩이 몇 초라 Worker는 **실행 사이에 재사용**하되 실행마다 새 전역 dict를 만들어 변수가 안 남음. Stop이나 시간 제한으로 죽이면 다음에 새로 띄움. Python 페이지를 열면 바로 로딩 시작
- `input()`은 실행 전에 [stdin](glossary:stdin) 칸을 줄 단위로 넘김(`setStdin`). numpy 같은 패키지는 `loadPackagesFromImports`가 import를 보고 필요한 것만 jsDelivr에서 받음

## 5. C, C++는 Compiler Explorer API

```ts:components/playground/runners.ts
fetch(`https://godbolt.org/api/compiler/${compiler.id}/compile`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', Accept: 'application/json' },
  body: JSON.stringify({
    source: code,
    options: {
      userArguments: '-O2 -Wall -std=c++20 -fdiagnostics-color=never',
      executeParameters: { stdin },
      compilerOptions: { executorRequest: true },
      filters: { execute: true },
    },
  }),
})
```

- 컴파일러 id는 `/api/compilers/c` 목록에서 골라 C는 `cg152`(GCC 15.2), C++은 `g152`. `-fdiagnostics-color=never`가 없으면 에러에 터미널 색 코드가 섞임
- 응답에서 `buildResult`(에러·경고와 줄 번호), `stdout`·`stderr`, `code`, `execTime`, `timedOut`을 씀. [무한 루프](glossary:infinite-loop)는 약 20초 뒤 godbolt가 죽이고 `timedOut: true`. 입력은 실행 전에 [stdin](glossary:stdin) 칸에 적는 방식이라 중간에 주고받지 못함

## 6. CSP 유지와 출력 폭주 대비

- [CSP](glossary:csp)는 안 바꿈. [Worker](glossary:web-worker)와 [Pyodide](glossary:pyodide) 파일은 `'self'`, [WebAssembly](glossary:webassembly) 컴파일은 기존 `'unsafe-eval'`, godbolt와 jsDelivr는 `fetch`라 이미 열린 `connect-src`에 해당. `srcdoc`은 부모 [CSP](glossary:csp)를 물려받아 인라인은 되고 외부 스크립트는 막혀서 미리보기 안내에 "외부 스크립트는 불러오지 않습니다"라고 적음
- `while True: print(1)`은 1초에 수만 줄. 줄마다 [React](glossary:react) 상태를 바꾸면 굳으므로 버퍼에 쌓았다가 [requestAnimationFrame](glossary:requestanimationframe)에서 한 번에 반영하고, 2000줄이 넘으면 버리고 한 줄로 알림

## 7. 정렬 시각화: 프로그램이 일기 쓰게 하기

[힙 정렬](/kr/blog/cs-fundamentals/data-structures/data-structures-heap-sort/#0-직접-돌려보기) 글 맨 위의 시각화. C와 Python 구현을 **실제로 실행**하고 값 크기만큼의 막대가 정렬되는 애니메이션을 보여 주며, 입력은 매번 랜덤. 실행기는 위 Playground 것을 그대로 씀.

| 방법                                | 문제                                                               |
| ----------------------------------- | ------------------------------------------------------------------ |
| JavaScript로 정렬을 다시 짜서 그림  | 화면이 C/Python 실행 결과가 아님                                   |
| 실행 중인 프로그램의 메모리를 엿봄  | godbolt나 [Pyodide](glossary:pyodide) 밖에서 배열을 볼 방법이 없음 |
| **프로그램이 한 일을 한 줄씩 출력** | [printf](glossary:printf) 몇 줄이 늘지만 화면 = 실제 실행 결과     |

세 번째로 감. 프로그램은 비교·교환마다 한 줄 남기고, 페이지가 그 출력([Execution trace](glossary:execution-trace))을 읽어 처음부터 다시 그림. 형식은 정렬이면 공통으로 씀.

| 줄             | 뜻                       |
| -------------- | ------------------------ |
| `INIT v0 v1 …` | 입력 배열                |
| `PHASE name`   | 단계 시작 (캡션에 표시)  |
| `CMP i j`      | `a[i]`와 `a[j]`를 비교함 |
| `SWAP i j`     | `a[i]`와 `a[j]`를 바꿈   |
| `SORTED i`     | `a[i]`가 제자리를 찾음   |
| `DONE v0 v1 …` | 결과 배열                |

- 크기 16이면 출력은 150줄 정도
- 랜덤 입력은 프로그램 안의 `srand`가 아니라 **페이지가 만들어 [stdin](glossary:stdin)으로 넘김**(5~99, 크기 8~32). C `rand()`와 Python `random`은 같은 [시드](glossary:random-seed)여도 다른 수를 내므로 똑같은 배열을 주려는 것. 입력이 요청 본문에 들어가 요청이 매번 달라지고, 입력 배열을 화면에 보여 줄 수도 있음

```ts:components/visualizer/SortVisualizer.tsx
const input = randomInput(size)            // 5 ~ 99, 크기 8 ~ 32
const stdin = `${size}\n${input.join(' ')}\n`
```

- `trace.ts`가 출력을 한 줄씩 읽으며 배열을 직접 다시 바꾸고 그 순간의 배열 전체를 [프레임](glossary:frame) 하나로 저장. 크기 최대 32, 단계 수백 개라 통째 복사해도 가벼워서 슬라이더로 아무 단계나 바로 감
- 검증: 페이지가 다시 바꾼 배열이 `DONE`과 같은지, 오름차순인지 확인. `printf`를 하나 빠뜨리면 그림과 실제가 어긋나는데 막대 아래에 알려 줌. 범위 밖 인덱스, `INIT`·`DONE` 누락도 같은 자리에 알림

```ts:components/visualizer/trace.ts
} else if (cmd === 'CMP' || cmd === 'SWAP') {
  const [i, j] = nums
  if (cmd === 'SWAP') [values[i], values[j]] = [values[j], values[i]]
  push({ kind: cmd === 'CMP' ? 'cmp' : 'swap', i, j })
}
```

## 8. 재생과 지연 로드

- 재생은 `index`를 [setTimeout](glossary:settimeout)으로 올리는 게 전부(기본 420ms, 0.5×~4×). 막대 높이는 `값 / 최댓값 × 100%`에 `transition`. 비교는 파랑, 교환은 빨강, 제자리는 검정, 나머지는 회색. 컨트롤은 재생/일시정지, 한 단계씩, 슬라이더, 속도
- [MDX](glossary:mdx) 컴포넌트 목록은 **모든 글이 공유**해서 시각화를 그냥 import하면 [CodeMirror](glossary:codemirror)(수백 KB)가 시각화 없는 글에도 실림. [next/dynamic](glossary:nextjs)으로 감싼 `SortVisualizerLazy`만 등록해 이 컴포넌트가 든 글에서만 [지연 로드](glossary:lazy-loading)함. 글에는 `<SortVisualizer algorithm="heap-sort" />` 한 줄. Python 탭을 누르는 순간 [Pyodide](glossary:pyodide) 로딩을 시작해서 글만 읽는 사람은 10MB를 안 받음
- 확인: 같은 입력 `[42, 7, 93, 15, 61, 28, 77, 3, 50, 66]`으로 C(godbolt)와 Python의 출력 75줄이 **한 줄도 다르지 않음**, 연속 두 번 실행하면 입력이 다름, 폭 390px에서 가로 스크롤 없음
- 새 알고리즘은 `components/visualizer/algorithms.ts`에 C·Python 코드와 단계 이름만 넣으면 됨. 같은 출력 형식이 조건이고, 값을 옮겨 쓰는 [병합 정렬](glossary:merge-sort)은 `SET i v` 줄을 더 정할 예정

## 9. giscus로 댓글

글 하나 = 토론 하나. 이 블로그는 [tailwind-nextjs-starter-blog](https://github.com/timlrx/tailwind-nextjs-starter-blog) [템플릿](glossary:template-repository)에서 시작해서 댓글 코드는 처음부터 있었고, 빠진 건 설정값뿐이었음.

| 방식       | 저장 위치                                         | 문제                                                            |
| ---------- | ------------------------------------------------- | --------------------------------------------------------------- |
| Disqus     | Disqus 서버                                       | 광고와 추적 스크립트. 데이터가 남의 것                          |
| utterances | [GitHub Issues](glossary:github-issues)           | 댓글이 이슈 목록에 섞임. 답글([스레드](glossary:thread))이 없음 |
| **giscus** | [GitHub Discussions](glossary:github-discussions) | 방문자가 GitHub 계정이 있어야 함                                |

읽는 사람이 대부분 개발자라 로그인 조건은 문제가 안 되고, 서버·DB 없이 Discussions를 저장소로 빌릴 수 있어 giscus로 정함. ([Disqus](glossary:disqus), [utterances](glossary:utterances))

- 템플릿의 `data/siteMetadata.js`에 `provider: 'giscus'`와 환경변수 4개 칸이 있고 [CSP](glossary:csp)에도 `giscus.app`이 열려 있었는데, 값이 비고 Discussions도 꺼져 있어서 아무것도 안 떴음

```js:data/siteMetadata.js
comments: {
  provider: 'giscus',
  giscusConfig: {
    repo: process.env.NEXT_PUBLIC_GISCUS_REPO,
    repositoryId: process.env.NEXT_PUBLIC_GISCUS_REPOSITORY_ID,
    category: process.env.NEXT_PUBLIC_GISCUS_CATEGORY,
    categoryId: process.env.NEXT_PUBLIC_GISCUS_CATEGORY_ID,
    mapping: 'pathname',
    // ...
  },
},
```

- [레포](glossary:repository) Settings → Features에서 Discussions를 켬(기본 카테고리가 바로 생김). [giscus 앱](glossary:github-app)은 **Only select repositories**로 블로그 레포 하나만 고름. All이면 private 레포까지 열림
- ID는 giscus.app이나 [GraphQL](glossary:graphql) 한 번([gh](glossary:github-cli))으로 받음. `id`가 레포 ID(`R_...`), 카테고리마다 `DIC_...`

```bash
gh api graphql -f query='{
  repository(owner: "seren-wib", name: "vercel-blog") {
    id
    discussionCategories(first: 10) { nodes { name id } }
  }
}'
```

- 카테고리는 처음엔 권장대로 Announcements(관리자와 앱만 새 토론 가능)로 했다가 환영 공지와 글별 댓글 토론이 섞여서 **General**로 옮김. 대가로 방문자도 새 토론을 열 수 있지만 이 규모에선 감수. 카테고리를 바꾸면 기존 토론도 옮겨야 함. giscus는 설정된 카테고리 안에서만 찾으므로 안 옮기면 그 글 댓글이 안 보이고 빈 토론이 새로 생김(Change category나 `updateDiscussion`)

## 10. 환경변수와 로딩 방식

| 이름                               | 값                      |
| ---------------------------------- | ----------------------- |
| `NEXT_PUBLIC_GISCUS_REPO`          | `seren-wib/vercel-blog` |
| `NEXT_PUBLIC_GISCUS_REPOSITORY_ID` | `R_...`                 |
| `NEXT_PUBLIC_GISCUS_CATEGORY`      | `General`               |
| `NEXT_PUBLIC_GISCUS_CATEGORY_ID`   | `DIC_...`               |

- 넷 다 브라우저로 내려가는 값이라 비밀이 아니고 `plain`으로 넣음. `NEXT_PUBLIC_` 값은 [빌드 타임](glossary:build-time)에 코드에 박혀서 [환경변수](glossary:environment-variable)만 저장하면 그대로이고 **Redeploy가 필요**
- 템플릿은 "Load Comments" 버튼을 눌러야 불러왔는데, pliny giscus 컴포넌트가 이미 `loading: "lazy"` [iframe](glossary:iframe)이라 스크롤해야 불러옴. 버튼과 상태를 지우고 바로 렌더링해도 첫 로딩은 같음. 글 아래 "Discuss on Twitter", "View on GitHub" 링크도 지움. 글이 길면 오른쪽 아래 말풍선 버튼이 `#comment`로 데려감

```tsx:components/Comments.tsx
export default function Comments({ slug }: { slug: string }) {
  if (!siteMetadata.comments?.provider) {
    return null
  }
  return <CommentsComponent commentsConfig={siteMetadata.comments} slug={slug} />
}
```

- `mapping: 'pathname'`이라 토론 제목이 `kr/blog/side-projects/devblog/...` 같은 경로. `/kr/`과 `/en/`이 다른 경로라 **한국어 글과 영어 글의 댓글은 따로** 달리는데, 읽는 사람이 다르다고 보고 둠(합치려면 접두사를 뺀 `term`을 넘기는 `specific` 매핑). [slug](glossary:slug)를 바꾸면 기존 댓글과 연결이 끊기므로 Discussions 토론 제목도 같이 고쳐야 함
