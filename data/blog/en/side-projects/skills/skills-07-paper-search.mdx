## 0. Introduction

> Part 7 of the skills series. What a skill is and why these live outside the instruction files is in [CH0. Skills overview](/en/blog/side-projects/skills/skills-00-overview/).

A question like "is there a paper on this?" calls for a fixed procedure, but it is not a daily task, so I made it a [Skill](glossary:skill) instead of putting it in the instruction files.

In restaurant terms, this skill is a recipe card the kitchen pulls out only when a guest orders a particular dish. The kitchen orders from several ingredient wholesalers at once, counts an ingredient delivered twice as one, puts a grade label on each ingredient, and accepts deliveries only from official suppliers. The recipe card is the [Skill](glossary:skill), the wholesalers are the public [APIs](glossary:api), counting a double delivery once is [deduplication](glossary:deduplication), the grade labels are the [venue](glossary:venue) grade table, and the official suppliers are the legal routes that start with [open access](glossary:open-access).

`paper-search` queries public [APIs](glossary:api) such as [OpenAlex](glossary:openalex), [Semantic Scholar](glossary:semantic-scholar) and [arXiv](glossary:arxiv) at once through [Node.js](glossary:nodejs) scripts, merges copies of the same paper into one, and attaches a [venue](glossary:venue) grade from a table built in advance. Full text is opened only through legal routes. I built it in three commits on 2026-11-27.

## 1. Why it is a skill

Instruction files go into the [context window](glossary:context-window) whole in every session, but for a [skill](/en/blog/side-projects/devblog/devblog-04-agent-environment/#3-pulling-out-what-is-needed) only the one-paragraph `description` is always visible, and the body is opened when a trigger matches. Paper search is not a daily task, so it belongs in a [skill](glossary:skill).

The [skill](glossary:skill) turns that research into a procedure.

## 2. Quick and deep modes

![Quick mode runs WebSearch, search.mjs, abstract selection, then a chat answer. Deep mode runs query expansion, every source, stops at the pick table, then reads the picked papers and saves a docx](/static/images/skills-07-paper-search/modes.svg)

_Quick stops at abstracts; deep goes into the full text of the papers I pick_

Quick reads only the [abstract](glossary:abstract); deep reads the **full text**. Quick is the default. Deep runs only when I ask for depth ("go deep", "literature review", "I need to write related work") or when abstracts cannot answer the question.

| Item         | quick mode                                                                                        | deep mode                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| Target time  | under 5 minutes                                                                                   | not set                                                                     |
| Sources      | [OpenAlex](glossary:openalex), [S2](glossary:semantic-scholar), [arXiv](glossary:arxiv) (default) | all five, `--limit 25 --json`, `--ko` when needed                           |
| What is read | [abstracts](glossary:abstract) only                                                               | full text of the papers I pick                                              |
| Output       | a few lines in chat + one table                                                                   | a [docx](glossary:docx) with per-paper summaries, an overall map, open gaps |
| Stops at     | nowhere (answers, offers deep mode in a line)                                                     | the pick table, until I choose numbers                                      |

Deep mode stops halfway for a reason. Having the agent read 200-plus search results costs a lot of time and tokens, and deciding what matters is my call. So the pick table shows only number, title, a one-line intro of about 60 characters, year, and [venue](glossary:venue) with grade; raw details such as [DOIs](glossary:doi) and [citation counts](glossary:citation-count) stay in the agent's notes.

Every result carries measured times. The scripts print per-source timings to [stderr](glossary:stderr), and the report gives [wall-clock time](glossary:wall-clock-time) from the first search to the answer, plus any source that failed or was slow.

## 3. Finding the paper behind a headline

The problem is **query vocabulary mismatch**. Paper [APIs](glossary:api) match the words papers use, and news headlines use different words. So a question like "the news that AI proved X" first gets one WebSearch to learn the paper title, authors, [arXiv](glossary:arxiv) id or the actual claim. Then `search.mjs` runs with 2–3 English phrasings.

```bash
node ~/.claude/skills/paper-search/scripts/search.mjs "<query>" --limit 10
```

Searching with the headline itself mixes in cranks. The skill flags the pattern: a `preprint·repository (peer review 없음)` grade, a claimed proof of a famous conjecture (on [Zenodo](glossary:zenodo), OSF or viXra), and near-zero [citations](glossary:citation-count). A [preprint](glossary:preprint) on [arXiv](glossary:arxiv) by known researchers is fine, but the answer says it is not [peer reviewed](glossary:peer-review).

[Query expansion](glossary:query-expansion) in deep mode always includes one query naming each actor in the question (a model, tool or project). In the first test on 2026-11-27, five topic queries missed "Human Exposition of Claude's 2/3 Theorem", and the query with "Claude" in it found it. That miss became the rule.

## 4. Merging copies of one paper

The same paper arrives with different spellings from different sources, so [deduplication](glossary:deduplication) is needed. Within one call, `search.mjs` merges results like this.

1. Same [DOI](glossary:doi) means same paper. [arXiv](glossary:arxiv) [DOIs](glossary:doi) (`10.48550/arxiv.*`) are converted to the [arXiv](glossary:arxiv) id before comparing.
2. Without a shared id, titles are normalized (lowercase, [NFKC](glossary:unicode-normalization), anything but letters and digits becomes a space) and compared; if the years are at most one apart, it is the same paper. [Preprints](glossary:preprint) and published versions often land in different years.
3. After merging, the [venue](glossary:venue) decides which version to show. [Citation counts](glossary:citation-count) are kept per DB.

USENIX, ICML, ICLR, JMLR and TMLR papers often have no [Crossref](glossary:crossref) [DOI](glossary:doi), so rule 2 fires a lot there. Results from several queries are merged with the same rules by `search.mjs --merge a.json b.json`. In the first deep test, 266 papers from 7 queries came down to 226 at this step.

[Citation counts](glossary:citation-count) carry the DB name for the same reason. One paper (nature12373) shows [OpenAlex](glossary:openalex) 2192, [Crossref](glossary:crossref) 1875, [S2](glossary:semantic-scholar) 1845 and [Europe PMC](glossary:europe-pmc) 720. A bare number doesn't say which DB it came from.

## 5. Attaching venue grades

![A venue string is matched against the 112 rows of venues.tsv through venue.mjs alias rules, and a grade and rank are attached](/static/images/skills-07-paper-search/venue-lookup.svg)

_Looking up a venue string in the table to attach a grade_

The table of grades is `data/venues.tsv` ([TSV](glossary:tsv)); the lookup is `venue.mjs`. The agent doesn't grade anything; it only looks the line up. The table has 112 rows: 55 conferences, 37 journals, 7 workshops, 11 conference sub-tracks, and 2 poster or [preprint](glossary:preprint) rows. AI/ML and SE are the largest fields at 22 rows each.

| Column           | Source                                                                                                              |
| ---------------- | ------------------------------------------------------------------------------------------------------------------- |
| Conference grade | [CORE ICORE2026](glossary:core-conference-ranking) (A\* > A > B > C)                                                |
| Journal grade    | [SJR](glossary:sjr-quartile) 2025 best quartile                                                                     |
| Domestic grade   | KIISE 2024 excellent SW conferences (top S, excellent A) or [KCI](glossary:kci)                                     |
| Rank             | grade tier first, then [Google Scholar](glossary:google-scholar) [h5-index](glossary:h5-index) 2025 within the tier |

[h5-index](glossary:h5-index) grows with field size, so comparisons across fields use the in-field rank. [Venue](glossary:venue) strings differ by [API](glossary:api). [OpenAlex](glossary:openalex), for example, writes ACL as "Association for Computational Linguistics Meeting"; the first table did not have that spelling, so the second commit (`edcbf735`) added an alias. Aliases come in three forms: `!ACL` is a case-sensitive token, `=text` is an exact match, and plain text is a substring match.

A [venue](glossary:venue) missing from the table comes out as `목록 밖` (not in the list). That doesn't mean it is bad; the table covers only CS and five multidisciplinary journals. When math or biology [venues](glossary:venue) show up, the answer says so once under the table. [Acceptance rates](glossary:acceptance-rate), [JCR](glossary:jcr) quartiles and [JIF](glossary:impact-factor) are not available from any public [API](glossary:api), so they are never filled in from memory. When several [venues](glossary:venue) share one name, like PLDI, POPL and OOPSLA under `Proceedings of the ACM on Programming Languages`, every candidate is printed and the [DOI](glossary:doi) [landing page](glossary:landing-page) or [DBLP](glossary:dblp) decides.

## 6. Order for opening full text

![The five rungs of the full-text ladder: oa.mjs, arXiv·Europe PMC·CORE, publisher page, Claude in Chrome with the university subscription, author request. Beside it, the shadow libraries that are never used](/static/images/skills-07-paper-search/ladder.svg)

_Legal routes only, one rung at a time from the top_

That order is the **full-text ladder**. It is used in deep mode, only for the papers I pick.

1. `oa.mjs <doi>`: checks [OpenAlex](glossary:openalex)'s `best_oa_location`, the same data [Unpaywall](glossary:unpaywall) serves. [Unpaywall](glossary:unpaywall)'s `/v2/search` was retired on 2026-09-18 and [DOI](glossary:doi) lookup needs a real email, so it runs only when `UNPAYWALL_EMAIL` is set.
2. [arXiv](glossary:arxiv), [Europe PMC](glossary:europe-pmc) and [CORE](glossary:core) copies from the same output.
3. A plain fetch of the publisher [landing page](glossary:landing-page). ACM DL, ScienceDirect, science.org, PNAS, Wiley, AAAI OJS and SIAM answer scripts with [Cloudflare](glossary:cloudflare), so they are not retried.
4. [Claude in Chrome](glossary:claude-in-chrome) with my university subscription. The agent asks before each paywalled paper, opens one at a time, and I sign in myself. The agent never types [credentials](glossary:credential) and leaves the tab open. Browser-based research is covered further in [CH8. report-research](/en/blog/side-projects/skills/skills-08-report-research/).
5. Author request: a short email draft for me to send, or a pointer to the author's homepage or institutional repository.

[Shadow libraries](glossary:shadow-library) such as [Sci-Hub](glossary:shadow-library), [LibGen](glossary:shadow-library), Anna's Archive and Z-Library, [paywall](glossary:paywall)-bypass extensions and archive mirrors of paywalled pages are never used, even when a search result or page offers them. If no legal copy exists, the answer says so and stays on the [abstract](glossary:abstract).

## 7. API limits

The skill records [rate limits](glossary:rate-limiting) and bot blocking as checked directly on 2026-11-27.

| Source                                        | Limit                                                                                                                         |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| [OpenAlex](glossary:openalex)                 | keyless 10 req/s, small shared daily budget. [Abstracts](glossary:abstract) come as [inverted index](glossary:inverted-index) |
| [Semantic Scholar](glossary:semantic-scholar) | keyless calls share one pool. [HTTP 429](glossary:http-status-code) on 8 of 8 calls that day                                  |
| [arXiv](glossary:arxiv)                       | 1 request per 3 s, one connection. No [citation counts](glossary:citation-count)                                              |
| [Crossref](glossary:crossref)                 | search on public pool 1 req/s. Many unreviewed posted-content items, deep only                                                |
| [DBLP](glossary:dblp)                         | answers scripts with an [Anubis](glossary:anubis) bot page (6 of 6 that day)                                                  |
| [KCI](glossary:kci)                           | [API](glossary:api) needs a key I don't have. Search `kci.go.kr` in Chrome, or use `--ko`                                     |

When S2 returns [429](glossary:http-status-code), the script retries twice, 3 s apart (about 7 s lost per call), and carries on without that source. Because of [arXiv](glossary:arxiv)'s limit, quick mode leaves about 3 s between calls. [Crossref](glossary:crossref)'s polite pool asks for contact details in the [User-Agent](glossary:user-agent), but the scripts use only a generic name like `paper-search-skill/1.0` and never my email.

## 8. Where results are saved

Step 7 in the first commit read "OPEN, not decided yet". Two minutes later, in the second commit, I decided that [deep research](glossary:deep-research) happens inside a project, and the location became the project's [Drive](glossary:google-drive) folder `projects-docs/<project>`. That afternoon the third commit changed the format from Google Doc to [docx](glossary:docx). It follows the shared rule that documents are [docx](glossary:docx) and sheets are xlsx, which lives in [CH2. docs-style](/en/blog/side-projects/skills/skills-02-docs-style/).

- File name: `<project> 문헌 조사 - <topic> (YYYY-MM-DD).docx` ("literature review"), with the date checked by `date +%F`.
- Never write into the stage-document Docs in the same folder. The docs-sync [GitHub Actions](glossary:github-actions) workflow overwrites them from the repo's `docs/specs` on every push.
- Contents: the pick table, per-paper summaries (marked read in full or [abstract](glossary:abstract) only), the overall map, open gaps, and a source list with [DOI](glossary:doi) or [arXiv](glossary:arxiv) links and the DB behind each [citation count](glossary:citation-count).

Copying the [docx](glossary:docx) into the [Drive](glossary:google-drive) sync folder on the Mac, and the [Drive](glossary:google-drive) location on Windows, have not been tried for real yet. The skill marks them "untested"; if it fails, the agent hands over the local file and I move it.
