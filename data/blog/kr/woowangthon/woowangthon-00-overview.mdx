> 2026 AI 우왕톤에 나간 18팀 왕가네식구들의 기록 시리즈 첫 글이다. 우리 프로젝트를 처음 보는 사람이 이 글 하나로 "무엇을, 왜, 어떻게"를 잡을 수 있게 썼다. 대회는 아직 진행 중이라(제출 마감 11월 15일) 이 글은 단계가 끝날 때마다 고친다. 마지막으로 고친 날은 11월 10일이다.

## 1. 우왕톤이 뭔가

멋쟁이사자처럼 충북대와 충북대 AI부트캠프사업단이 여는 3주짜리 해커톤이다. 주제는 하나다.

> **AI는 동료가 될 수 있을까?**

주최 측이 든 예시는 셋이다. 졸업 요건을 챙기는 동료, 어르신 안부를 묻는 동료, 불량품을 먼저 골라내는 동료. 셋 다 **AI가 먼저 거르고 제안하되, 마지막 결정은 사람이 한다**는 모양이다. 그리고 "이미 있는 것과 무엇이 다른가"를 묻는다.

| 날짜            | 일                                               |
| --------------- | ------------------------------------------------ |
| 10월 24일       | 온라인 킥오프                                    |
| 11월 15일 18:00 | 제출 마감. 이 시각의 `main` 브랜치 커밋으로 심사 |
| 11월 16~20일    | 사전 심사, 본선 10팀 선발                        |
| 11월 21일       | 본선 발표                                        |

규칙 중에 이 시리즈에 자주 나오는 것이 둘 있다. 하나는 **결과를 꾸미지 않는다**는 것이다. 가짜 데이터나 미리 만든 화면을 진짜처럼 보여 주면 안 되고, 꼭 써야 하면 코드에 표시하고 문서에 목록으로 올린다. 다른 하나는 **AI를 어디에 썼는지 밝힌다**는 것이다. 모델, 외부 API, 그리고 AI를 안 쓴 곳까지 문서에 적는다.

## 2. 우리가 푸는 문제

대상은 학생이다. 프로젝트 과목에서 웹 서비스를 만들면 배포는 각자 한다. Vercel, AWS, Cloudflare 같은 상용 클라우드에 올리고, 무료 한도를 넘으면 자기 돈을 낸다. 과목이 끝나면 서비스도 대개 같이 내려간다.

| 문제                     | 내용                                                                |
| ------------------------ | ------------------------------------------------------------------- |
| 클라우드 비용이 부담된다 | 무료 한도를 넘는 순간 학생 개인 카드에서 돈이 나간다                |
| 학교 컴퓨터는 남는다     | 실습실 PC는 수업 시간 말고는 꺼져 있거나 놀고 있다                  |
| 과목이 배포에서 끝난다   | 배포까지는 배우지만, 배포한 뒤 운영(장애, 모니터링)은 다루지 않는다 |

## 3. 우리가 만드는 것

**학교 PC를 묶어 만든 서버에, 학생이 자기 GitHub 레포를 올려 돌리는 배포 플랫폼**이다. 학생은 레포 주소만 내면 되고, 돈은 내지 않는다. 배포 전에는 AI가 코드의 보안 위험을 먼저 보고, 운영 중에 서비스가 이상해지면 AI가 원인을 쉬운 말로 풀어 준다.

학생 입장에서 배포 한 건은 이렇게 흘러간다.

1. 학생이 GitHub 계정으로 로그인하고, 공개 레포 주소와 유형(정적 웹 / 서버 / 웹+서버), DB를 쓰면 자기 DB의 접속 정보를 넣어 제출한다
2. **AI가 검토한다.** 레포를 읽기 전용으로 받아 비밀키 노출, 과한 공개 권한 같은 위험을 근거와 함께 찾는다. 고칠 것이 있으면 봇 계정이 수정 제안을 PR로 올린다
3. **운영자가 정한다.** 검토 요약을 보고 승인, 수정 요청, 차단 중 하나를 고른다
4. 승인된 코드만 학교 밖의 격리된 빌드 서버에서 컨테이너 이미지로 만든다
5. 학교 PC 클러스터가 그 이미지를 받아 실행한다. DB는 학생이 가져온 것에 그 접속 정보로 붙는다
6. 방문자는 `이름.stairnoworks.com` 주소로 들어온다
7. 운영 중에 메모리 초과나 재시작 반복 같은 이상이 생기면 규칙이 먼저 멈추거나 다시 띄우고, AI가 원인과 다음 행동을 설명하는 알림을 보낸다

## 4. AI가 하는 일, 사람이 정하는 일

대회 주제에 대한 우리 답이다. AI에게 결정을 넘기지 않는다.

| 상황              | AI가 하는 일                                             | 사람이 정하는 일                                 |
| ----------------- | -------------------------------------------------------- | ------------------------------------------------ |
| 배포 전 검토      | 코드와 설정에서 보안 위험을 찾아 근거와 함께 알린다      | 학생은 고치거나 반박하고, 운영자는 승인을 정한다 |
| 운영 중 지표 이상 | 이상의 원인을 추정해 쉬운 말로 설명하고 다음 행동을 제안 | 재시작, 중단, 롤백 같은 조치를 정한다            |

이미 있는 것과의 차이도 이 표에서 나온다. 상용 클라우드는 학생이 비용을 내고, 상용 AI 배포 도우미(Vercel Agent, AWS의 보안·운영 에이전트 같은 것)는 유료이고 기업용이다. 우리는 학교 PC에서 돌려 학생이 돈을 안 내고, 따로 설정하지 않아도 모든 배포에 검토와 이상 분석이 붙는다.

그리고 이 시리즈에는 AI 동료가 하나 더 나온다. 클러스터를 세우는 동안 내 옆에서 명령을 치고 계획서를 고친 [AI 코딩 에이전트](/kr/blog/devops/devops-00-basics/#ai-코딩-에이전트)(Claude Code)다. 잘한 것도 있고, 혼자 짐작한 전제 때문에 설계를 한 번 엇나가게 한 것도 있다. 그것도 숨기지 않고 적는다.

## 5. 전체 구조

플랫폼은 클라우드(AWS)에 두고, 학생 서비스만 학교 PC에서 돈다.

| 구역           | 구성요소              | 기술                                | 하는 일                                                            |
| -------------- | --------------------- | ----------------------------------- | ------------------------------------------------------------------ |
| 클라우드 (AWS) | User Page, Admin Page | React + TypeScript, S3 + CloudFront | 학생용 배포 화면, 운영자용 승인 화면                               |
|                | 플랫폼 서버           | Nest.js, EC2                        | 요청 접수, 빌드 요청, 학교 클러스터에 배포 지시                    |
|                | AI 서버               | FastAPI, EC2                        | 배포 전 검토, 이상 분석                                            |
|                | 빌드                  | AWS CodeBuild                       | 학생 코드를 이미지로 만든다. 학생 코드가 실행되는 유일한 외부 단계 |
|                | DB · 로그인           | Supabase                            | GitHub 로그인, 검토 결과와 배포 상태 저장                          |
|                | 메시지 큐             | Kafka                               | 배포 기록이 사라지지 않게 남긴다                                   |
| 외부           | 컨테이너 레지스트리   | GHCR                                | 빌드된 이미지 보관                                                 |
| 학교           | 클러스터              | k3s, 학교 PC 3대                    | 학생 서비스 실행                                                   |
| 학교 ↔ 바깥    | 사설망                | Tailscale                           | 플랫폼 서버와 운영자가 학교 PC에 닿는 길                           |
|                | 공개 터널             | Cloudflare Tunnel                   | 방문자가 학생 서비스에 닿는 길                                     |
| 학교           | 모니터링              | Prometheus, Grafana                 | 노드와 서비스 지표                                                 |

학교 PC 쪽에서 중요한 전제가 하나 있다. **학교로 들어오는 포트는 하나도 열지 않는다.** 학교 방화벽 안에 있는 PC라 바깥에서 먼저 연결을 걸 수 없다. 그래서 바깥과의 연결은 전부 학교 PC가 먼저 밖으로 건다. 운영자와 플랫폼 서버는 Tailscale 사설망으로, 방문자는 Cloudflare 터널로 들어온다.

클러스터는 이렇게 생겼다.

| PC   | 역할 | 하는 일                                                                   |
| ---- | ---- | ------------------------------------------------------------------------- |
| PC 1 | 리더 | 클러스터 제어, 공개 터널, 이미지 캐시, 지표 수집. 학생 서비스는 안 받는다 |
| PC 2 | 워커 | 학생 프로젝트 1개                                                         |
| PC 3 | 워커 | 학생 프로젝트 1개                                                         |

세 대는 우리가 산 스위치 하나에 랜선으로 묶여 있다. 워커 하나가 꺼지면 리더가 그 프로젝트를 남은 워커에 다시 띄우고. DB는 학생 것이라 클러스터 밖에 있어서 따라 옮길 데이터가 없다. 리더는 하나뿐이라 리더가 꺼지면 새 배포가 멈춘다. PC가 셋뿐이라 이건 감수한다.

## 6. 처음 보는 용어

| 용어                                       | 뜻                                                                                     |
| ------------------------------------------ | -------------------------------------------------------------------------------------- |
| 컨테이너 이미지                            | 프로그램과 그 프로그램이 돌 환경을 통째로 묶은 꾸러미. 어디서든 같은 모양으로 실행된다 |
| 쿠버네티스                                 | 여러 컴퓨터에 컨테이너를 나눠 띄우고, 죽으면 다시 띄워 주는 관리 프로그램              |
| k3s                                        | 쿠버네티스를 가볍게 줄인 배포판. 작은 컴퓨터 몇 대로 클러스터를 만들 때 쓴다           |
| 클러스터, 노드                             | 하나처럼 묶인 컴퓨터 무리가 클러스터, 그 안의 컴퓨터 한 대가 노드                      |
| 리더, 워커                                 | 리더는 무엇을 어디에 띄울지 정하는 노드, 워커는 실제로 서비스를 돌리는 노드            |
| Pod                                        | 쿠버네티스가 띄우는 가장 작은 단위. 컨테이너 하나 또는 몇 개                           |
| 네임스페이스                               | 클러스터 안을 나눈 칸. 학생 프로젝트마다 한 칸(`proj-<id>`)을 준다                     |
| Tailscale                                  | 여러 기기를 하나의 사설망처럼 묶어 주는 서비스. 방화벽 안 기기에도 밖에서 닿게 해 준다 |
| Cloudflare Tunnel                          | 안쪽 서버가 Cloudflare에 먼저 연결을 걸어 두고, 방문자 요청을 그 연결로 받는 방식      |
| ADR                                        | 기술 결정 하나를 이유와 함께 남기는 짧은 문서(Architecture Decision Record)            |
| [PR](/kr/blog/devops/devops-00-basics/#pr) | GitHub에서 "이 변경을 합쳐 달라"고 올리는 요청(Pull Request). 팀원이 보고 합친다       |

## 7. 팀과 내 역할

팀 이름은 **왕가네식구들**, 18팀이다. 레포 하나에 웹(`FE/`), 플랫폼 서버(`BE/`), AI 서버(`AI/`), 클러스터(`Infra/`)를 같이 둔다. 이 시리즈에서는 팀원을 GitHub 아이디로 부른다. 문서 구조와 웹·서버 초기 설정을 맡은 [TaeTaeJin](https://github.com/TaeTaeJin), AI 서버(배포 전 검토와 이상 분석)를 맡은 [suda5936](https://github.com/suda5936)이 나온다.

나([seren-wib](https://github.com/seren-wib))는 **학교 PC 클러스터**를 맡았다. PC 세 대를 받아서 학생 서비스를 띄울 수 있는 k3s 클러스터로 만들고, 플랫폼 서버와 방문자가 닿을 길을 내고, 대회가 끝나면 받은 상태 그대로 돌려놓는 일까지다. 이 시리즈의 2편부터는 대부분 이 이야기다.
