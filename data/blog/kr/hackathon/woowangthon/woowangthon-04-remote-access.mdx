## 0. 들어가며

> 시리즈 4편. 구축 2단계, 원격 접속이다. [disk image](glossary:disk-image)를 뜬 이야기는 [3편](/kr/blog/hackathon/woowangthon/woowangthon-03-disk-images/)에, 전체 그림은 [Woowangthon 0](/kr/blog/hackathon/woowangthon/woowangthon-00-overview/)에 있다.

학교 PC 세 대를 동아리방에 두고 집에서 다뤄야 했다. PC 앞에는 오래 있을 수 없어서, 원격으로 들어가는 길부터 만들어야 했다.

식당으로 비유하면 PC 세 대는 문이 잠긴 지점 주방 세 곳이고, 나는 집에서 그 주방들을 다뤄야 한다. 정문 경비(학교 [firewall](glossary:firewall))를 지나 주방까지 가는 통로, 비밀번호 대신 쓰는 열쇠, 정전이 나도 스스로 불이 켜지는 가스레인지가 있어야 한다. 통로는 [Tailscale](glossary:tailscale), 열쇠는 기기마다 따로 둔 [SSH key](glossary:ssh-key), 가스레인지는 [BIOS](glossary:bios)의 정전 후 자동 켜짐 설정이다.

그 전에 인터넷부터 됐어야 했는데, 하마터면 "학교가 인터넷을 막는다"고 잘못 결론 낼 뻔했다. 이 단계에서 한 일은 벽 [LAN](glossary:lan) [port](glossary:port)와 [switch](glossary:network-switch) 배선, [Tailscale](glossary:tailscale) 설치, 세 대에 [SSH key](glossary:ssh-key) 등록, [AI agent](glossary:ai-coding-agent)를 위한 [passwordless sudo](glossary:passwordless-sudo), 무인 재부팅 시험이다.

## 1. 현장에서는 원격이 안 되는 일만

PC 앞에 오래 있을 수는 없다. 그래서 할 일을 셋으로 나눴다.

| 묶음 | 어디서            | 하는 일                                                                                                                      |
| ---- | ----------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| A    | 세 대 앞에서 각각 | [disk image](glossary:disk-image)(3편), 유선 인터넷 확인, [SSH](glossary:ssh) 서버, [Tailscale](glossary:tailscale)          |
| B    | 노트북에서 한 번  | 세 대에 [public key](glossary:public-key) 등록, [passwordless sudo](glossary:passwordless-sudo). 반복문 한 줄로 세 대를 돈다 |
| C    | 다시 세 대 앞에서 | [BIOS](glossary:bios) 전원 설정, 무인 재부팅 시험                                                                            |

원칙은 "원격 접속이 생기기 전 일만 PC 앞에서 한다"이다. B부터는 노트북의 [AI coding agent](glossary:ai-coding-agent)([Claude Code](glossary:claude-code))가 [SSH](glossary:ssh)로 들어가서 한다. 그러려면 A에서 길을, B에서 열쇠를 먼저 만들어야 했다.

## 2. 스위치 배선과 벽 포트

동아리방 벽에는 [port](glossary:port)가 두 개 있었다. 처음에는 그중 하나에 [switch](glossary:network-switch)를 꽂았는데, 알고 보니 전화용으로 보이는 [port](glossary:port)였다. [LAN](glossary:lan) [port](glossary:port)는 다른 쪽이었고, 그 [port](glossary:port)는 동아리 와이파이 [router](glossary:router)가 이미 쓰고 있었다.

[port](glossary:port)는 하나, 쓸 곳은 둘이다. 그래서 벽 [port](glossary:port)를 우리 [switch](glossary:network-switch)에 물리고, 동아리 [router](glossary:router)를 [switch](glossary:network-switch) 아래로 옮겼다.

![스위치 포트마다 붙인 배선표](/static/images/woowangthon-04-remote-access/switch-wiring.webp)

_위에서부터 벽 [port](glossary:port), 동아리 [router](glossary:router), 워커 2, 워커 1, 리더. 나중에 누가 선을 뽑아도 다시 꽂을 수 있게 붙여 뒀다_

- [router](glossary:router)는 [switch](glossary:network-switch)에 **[WAN port](glossary:wan)**로 연결한다. [LAN](glossary:lan) [port](glossary:port)로 꽂으면 [router](glossary:router)가 학교망에 자기 주소를 나눠 주려 들 수 있다
- 벽으로 가는 선은 딱 한 줄이다. [switch](glossary:network-switch)에서 벽으로 두 줄이 가면 [network loop](glossary:network-loop)가 생겨 동아리방 망 전체가 먹통이 될 수 있다
- 이제 동아리 [router](glossary:router)도 우리 [switch](glossary:network-switch)에 달렸다. [switch](glossary:network-switch) 전원이 나가면 동아리 와이파이도 같이 끊긴다. 동아리 사람들에게 알려야 하는 일이다

## 3. 인터넷이 막힌 줄 알았다

[3편](/kr/blog/hackathon/woowangthon/woowangthon-03-disk-images/#7-이미지를-뜨고-나서-본-것)에서 본 것처럼 세 대 모두 와이파이 카드가 없다. 인터넷은 벽 [port](glossary:port) 하나뿐이다. 그리고 PC에는 학교가 정해 둔 [static IP](glossary:static-ip-address)가 이미 들어 있었다. 그 [static IP](glossary:static-ip-address) 그대로 이 벽 [port](glossary:port)에서 인터넷이 되는지가 문제였다.

최소 설치판이라 `ping`조차 없었다. 그래서 두 가지로 봤다.

```bash
ip neigh
curl -sSI -m 5 https://1.1.1.1
```

`ip neigh`는 같은 망의 기기 중 응답한 것들을 보여 준다. [gateway](glossary:gateway)가 응답했고, 그 장비 제조사는 학교 네트워크 장비였다. 선은 제대로 학교망에 붙어 있었다. 그런데 `curl`이 시간 초과로 끝났다. [port 80](glossary:port)도 마찬가지였다. [DNS](glossary:dns)는 한 번 응답하고 다른 이름에서는 시간 초과가 났다.

이 결과만 보면 "학교가 이 [IP](glossary:ip-address)의 바깥 인터넷을 막는다"처럼 보였다. 다음 계획까지 세웠다. 동아리 [router](glossary:router) 뒤에서 [DHCP](glossary:dhcp)로 받아 보고, 그것도 안 되면 학교에 문의한다.

그 전에 주소 하나만 바꿔 봤다.

```bash
curl -4 -sSI -m 8 https://tailscale.com | head -1
```

```text
HTTP/2 200
```

[Ubuntu](glossary:ubuntu) 패키지 서버도 200이 나왔다. **인터넷은 처음부터 됐다.** 막혀 있던 건 시험 대상으로 고른 `1.1.1.1`([Cloudflare](glossary:cloudflare)의 공개 [DNS](glossary:dns) 주소)이었다. [DNS](glossary:dns) 문제를 빼고 보려고 이름 대신 [IP](glossary:ip-address)로 직접 찔렀는데, 하필 그 [IP](glossary:ip-address)가 막혀 있었다.

교훈은 단순하다. **연결 시험의 대상이 틀리면 진단도 틀린다.** 이제 연결 확인은 실제로 쓸 서비스 주소(`tailscale.com`)로 한다. 그리고 결과를 적을 때 "인터넷 안 됨"과 "1.1.1.1에 안 닿음"을 구분해서 적는다. 앞의 것은 결론이고, 뒤의 것은 관찰이다.

## 4. 길: Tailscale

학교 PC는 [firewall](glossary:firewall) 안에 있어서 바깥에서 먼저 연결을 걸 수 없다. [Tailscale](https://tailscale.com)은 기기마다 프로그램을 깔고 같은 계정으로 로그인하면, 그 기기들을 하나의 [private network](glossary:private-network)처럼 묶어 준다. 각 기기가 [Tailscale](glossary:tailscale) 쪽으로 먼저 연결을 걸어 두는 방식이라 학교에 [port](glossary:port)를 열어 달라고 할 필요가 없다.

세 대에 각각 깔고 이름을 붙였다.

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up --hostname=k3s-leader
```

화면에 나온 로그인 주소를 노트북에서 열어 같은 계정으로 승인하면 끝이다. 한 대는 이름을 잘못 붙여(`k3s-w1-1`) 나중에 원격으로 고쳤다.

```bash
sudo tailscale set --hostname=k3s-w2
```

### 직접 연결이 아니라 중계

붙고 나서 경로를 보니 직접 연결이 아니었다. 학교 PC와 내 기기 사이를 [Tailscale](glossary:tailscale)의 도쿄 [relay server](glossary:relay-server)([DERP](glossary:derp))가 이어 주고 있었고, 왕복 [latency](glossary:latency)은 70~80ms였다. 학교망 쪽 [firewall](glossary:firewall)이나 [NAT](glossary:nat) 때문에 두 기기가 직접 연결을 맺지 못하고, [relay server](glossary:relay-server)를 거쳐 돌아오는 것으로 보인다.

원격 접속에는 이걸로 충분하다. 명령 몇 줄 치는 데 80ms는 티가 안 난다. [2편](/kr/blog/hackathon/woowangthon/woowangthon-02-network-design/#2-노드끼리는-스위치로-묶기)에서 노드끼리 연결을 [Tailscale](glossary:tailscale)(C안)이 아니라 [switch](glossary:network-switch)로 정한 이유가 여기서 확인된 셈이다. DB 쓰기마다 도쿄를 찍고 오면 못 쓴다. 다만 나중에 플랫폼 서버가 이 길로 배포를 지시할 때 [latency](glossary:latency)가 얼마나 되는지는 6단계에서 다시 잰다.

[Tailscale](glossary:tailscale) 기기 키는 기본값으로 180일 뒤 만료된다. 만료를 끄는 방법도 있지만 그대로 뒀다. 대회 기간보다 훨씬 길고, 반납하면 어차피 지운다.

## 5. 열쇠: 기기마다 따로 둔 SSH 키

나는 집의 Windows 데스크탑과 Mac 노트북 둘 다에서 작업한다. 두 기기 모두에서 세 대에 들어가야 한다.

규칙은 **기기마다 키를 따로 만들고, [private key](glossary:private-key)는 절대 복사하지 않는다**이다. [private key](glossary:private-key)를 한 기기에서 다른 기기로 옮기면, 한쪽을 잃어버렸을 때 어느 키를 지워야 할지 모른다. 기기마다 따로면 잃어버린 기기의 [public key](glossary:public-key) 한 줄만 지우면 된다.

```bash
ssh-keygen -t ed25519 -f ~/.ssh/wanggane_k3s -N "" -C "<기기 이름> wanggane-k3s"
```

접속 설정은 두 기기에 같은 블록을 넣었다. `HostName %h`는 [Tailscale](glossary:tailscale)이 기기 이름으로 주소를 찾아 주니([MagicDNS](glossary:magicdns)) 이름을 그대로 쓰겠다는 뜻이다.

```text:~/.ssh/config
Host k3s-leader k3s-w1 k3s-w2
  HostName %h
  User <학교 PC 계정>
  IdentityFile ~/.ssh/wanggane_k3s
  IdentitiesOnly yes
  ServerAliveInterval 30
```

[public key](glossary:public-key) 두 줄은 노트북에서 세 대에 한 번에 넣었다. 이때만 PC마다 비밀번호를 한 번씩 묻는다.

```bash
for h in k3s-leader k3s-w1 k3s-w2; do
  ssh -o PubkeyAuthentication=no "$h" \
    'umask 077; mkdir -p ~/.ssh; cat >> ~/.ssh/authorized_keys' < ~/.ssh/wanggane_k3s_all.pub
done
```

## 6. AI 에이전트를 위한 비밀번호 없는 sudo

여기서 AI 동료를 위한 준비가 하나 필요했다. **[AI agent](glossary:ai-coding-agent)에게는 비밀번호를 주지 않는다.** 비밀번호를 채팅에 붙여 넣으면 대화 기록에 남는다. 그런데 비밀번호 없이는 `sudo`가 들어간 줄마다 설치가 멈춘다.

그래서 세 대에 [passwordless sudo](glossary:passwordless-sudo)를 허용하는 파일을 하나씩 넣었다.

```bash
for h in k3s-leader k3s-w1 k3s-w2; do
  ssh -t "$h" 'echo "$USER ALL=(ALL) NOPASSWD:ALL" > /tmp/wanggane \
    && sudo visudo -cf /tmp/wanggane \
    && sudo install -m 440 -o root -g root /tmp/wanggane /etc/sudoers.d/wanggane; \
    rm -f /tmp/wanggane; sudo -k; sudo -n true && echo "NOPASSWD-OK"'
done
```

- `visudo -cf`로 문법 검사를 통과한 파일만 설치한다. [sudo](glossary:sudo) 설정 파일에 오타가 나면 [sudo](glossary:sudo) 자체가 안 돼서, 원격에서는 되돌릴 방법이 없다
- 설정이 이 파일 하나에만 있어서 반납할 때 이 파일만 지우면 된다
- 지우는 순서도 정해 뒀다. [Tailscale](glossary:tailscale)을 지우기 전에 이 파일부터 지우면 [Tailscale](glossary:tailscale) 제거가 비밀번호를 물어서 멈춘다. 반납 날의 순서는 계획서에 따로 있다

`NOPASSWD-OK`가 세 줄 나온 뒤로는 비밀번호를 칠 일이 없어졌다. 절전 끄기, 시간 동기화 확인, 세 대 사양 확인은 노트북의 에이전트가 원격으로 했다. 세 대 사양이 똑같다는 것도 이때 확인했다.

```bash
sudo systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target
```

절전을 끄는 이 줄은 무인 운영의 기본이다. 아무도 없는 동아리방에서 PC가 잠들면 원격 접속도 같이 잠든다.

## 7. 전원: 정전 뒤에도 다시 켜지게

마지막은 다시 PC 앞에서 했다. 정전이 나거나 누가 멀티탭을 뽑았다 꽂으면, 이 PC들은 꺼진 채로 있었다. [BIOS](glossary:bios)의 "Restore after AC Power Loss"가 `Power Off`였기 때문이다. 원격으로는 이걸 못 바꾼다.

세 대 모두 바꾸기 전 화면을 사진으로 찍고 `Power On`으로 바꿨다. [BIOS](glossary:bios)는 [disk image](glossary:disk-image)에 안 들어가서, 반납할 때 이 사진을 보고 되돌린다.

그다음이 **무인 재부팅 시험**이다. 저장하고 재부팅한 뒤 PC 앞에서 아무것도 하지 않고, 노트북에서 바로 접속해 봤다.

```bash
ssh k3s-leader 'uptime'
```

로그인하지 않은 상태에서도 세 대 모두 [Tailscale](glossary:tailscale)이 다시 붙고 [SSH](glossary:ssh)가 됐다. 인터넷, [Tailscale](glossary:tailscale), [SSH](glossary:ssh)가 전부 사람 손 없이 돌아온다는 뜻이다. 실제로 전원 코드를 뽑는 시험은 하지 않았다. 설정만 바꿨으니, 언젠가 정전 뒤에 PC가 안 켜져 있으면 이 설정부터 의심하면 된다.

그날 밤 집의 Windows 데스크탑에서도 세 대에 키로 접속되고 `sudo -n`이 되는 걸 확인했다. 그걸로 2단계가 끝났다.
