## 0. 들어가며

헷갈릴 때 보려고 정리한 개인 치트시트다. 명령어는 터미널에서 [Repository](glossary:repository) 폴더로 들어간 뒤 실행한다.

식당으로 비유하면 내 컴퓨터의 작업 폴더는 주방이고, [GitHub](glossary:github)에 올라간 [Repository](glossary:repository)는 본점 창고다. 한 접시를 완성해 사진으로 남기면 변경 기록 하나가 되고, 조리 중인 접시는 잠깐 서랍에 치워둔다. 즉 주방은 로컬 [Repository](glossary:repository), 본점 창고는 [Remote](glossary:remote)인 [Origin](glossary:origin), 사진 기록은 [Commit](glossary:commit), 서랍은 [Stash](glossary:stash)다.

이 글은 상태 확인, 변경사항을 잃지 않는 [Pull](glossary:pull), [Merge conflict](glossary:merge-conflict) 해결, [Commit](glossary:commit)과 [Push](glossary:push), 되돌리기 순으로 명령을 정리했다.

---

## 1. 지금 상태 보기

```bash
git status              # 어떤 파일이 바뀌었는지
git log --oneline -10   # 최근 커밋 10개
git fetch               # 원격 정보만 받아옴 (파일은 안 바뀜)
git log HEAD..@{u} --oneline   # 원격에 있는데 나한텐 없는 커밋
```

---

## 2. 변경사항 잃지 않고 pull 하기

2026-06-13에 했던 작업이다. 로컬에 수정 중인 파일이 있는데 [Remote](glossary:remote)에도 새 [Commit](glossary:commit)이 있을 때.
그냥 `git pull` 하면 겹치는 파일에서 멈추거나 거부됨. 안전 순서:

```bash
# 1. 로컬 변경을 서랍에 치워둠 (-u 는 새로 만든 untracked 파일까지 포함)
git stash push -u -m "pull 전 임시 보관"

# 2. 깨끗해진 상태에서 원격 받아오기
git pull --ff-only

# 3. 치워둔 변경 다시 꺼내기
git stash pop
```

- 겹치는 파일이 있으면 `stash pop`에서 **[Merge conflict](glossary:merge-conflict)**가 남 → 아래 3번으로.
- 데이터는 안 사라짐. [stash](glossary:stash)는 [Merge conflict](glossary:merge-conflict)가 나도 `git stash list`에 남아있음.

## 3. 충돌(conflict) 해결

[Merge conflict](glossary:merge-conflict)가 난 파일을 열면 이런 [Conflict marker](glossary:conflict-marker)가 들어있음:

```
<<<<<<< Updated upstream
원격(받아온 쪽) 내용
=======
내 로컬(stash) 내용
>>>>>>> Stashed changes
```

해결법:

1. 셋 중 살릴 내용만 남기고 **[Conflict marker](glossary:conflict-marker) 세 줄을 직접 지움** (`<<<`, `===`, `>>>`)
2. 양쪽 다 필요하면 둘 다 남기고 [Conflict marker](glossary:conflict-marker)만 지움
3. 정리한 파일을 [Staging area](glossary:staging-area)에 올림:

```bash
git add "파일경로"
```

**파일 삭제 vs 수정 [Merge conflict](glossary:merge-conflict)** (한쪽은 지우고 한쪽은 고친 경우):

```bash
git rm "파일경로"      # 삭제를 선택할 때
# 또는
git add "파일경로"     # 남기기를 선택할 때 (파일은 살아있음)
```

[Merge conflict](glossary:merge-conflict) 다 정리했으면 [stash](glossary:stash) 서랍 비우기:

```bash
git stash drop         # 방금 꺼낸 stash 삭제
git stash list         # 남은 stash 확인
```

---

## 4. 커밋하고 올리기

```bash
git add .                    # 모든 변경 스테이지 (또는 "파일명" 만)
git commit -m "메시지"        # 커밋
git push                     # 원격(GitHub)에 올리기
```

---

## 5. 되돌리기 (실수했을 때)

```bash
git restore "파일"           # 수정한 내용 버리고 마지막 커밋 상태로
git restore --staged "파일"  # add 한 걸 취소 (변경은 유지)
git stash list               # 치워둔 변경 목록
git stash pop                # 가장 최근 stash 다시 꺼내기
git reset --hard HEAD        # ⚠️ 모든 로컬 변경 버림 (되돌리기 불가, 주의)
```

---

## 6. 느낀 점

[stash](glossary:stash)는 [Merge conflict](glossary:merge-conflict)가 나도 `git stash list`에 남아서 데이터는 사라지지 않는다.
