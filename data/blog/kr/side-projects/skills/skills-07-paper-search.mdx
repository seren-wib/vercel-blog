## 0. 들어가며

> 스킬 연재 7편. 스킬이 무엇이고 왜 지침 파일 밖으로 뺐는지는 [CH0. 스킬 개요](/kr/blog/side-projects/skills/skills-00-overview/)에 있다.

"이거 논문 있어?" 같은 질문이 나올 때마다 쓰는 절차인데, 매일 하는 일은 아니라서 지침 파일 대신 [Skill](glossary:skill)로 두기로 했다.

식당으로 비유하면 이 스킬은 손님이 특정 메뉴를 시킬 때만 꺼내 보는 레시피 카드다. 주방은 재료 도매상 여러 곳에 한꺼번에 주문하고, 같은 재료가 두 번 들어오면 하나로 세고, 재료마다 등급표를 붙이고, 정식 납품처에서만 재료를 받는다. 레시피 카드가 [Skill](glossary:skill), 도매상이 공개 [API](glossary:api), 이중으로 들어온 재료를 하나로 세는 일이 [Deduplication](glossary:deduplication), 등급표가 [Venue](glossary:venue) 등급 표, 정식 납품처가 [Open access](glossary:open-access)부터 시작하는 합법 경로다.

`paper-search`는 [OpenAlex](glossary:openalex), [Semantic Scholar](glossary:semantic-scholar), [arXiv](glossary:arxiv) 같은 공개 [API](glossary:api)를 [Node.js](glossary:nodejs) 스크립트로 한꺼번에 조회하고, 같은 논문을 하나로 합치고, [Venue](glossary:venue) 등급을 미리 만들어 둔 표에서 찾아 붙인다. 본문은 합법 경로로만 연다. 2026-11-27 하루에 커밋 세 개로 만들었다.

## 1. 스킬로 만든 이유

지침 파일은 매 세션 [Context window](glossary:context-window)에 통째로 들어가지만, [skill](/kr/blog/side-projects/devblog/devblog-04-agent-environment/#3-필요할-때-꺼내기)은 `description` 한 단락만 상시로 보이고 본문은 트리거가 맞을 때 연다. 논문 검색은 매일 하는 일이 아니라서 [Skill](glossary:skill) 자리에 맞다.

시작은 2026-11-27이다. 나는 먼저 "공개 [API](glossary:api)로 조사 못 하는 게 뭔지"부터 알아보기로 했고, 작업 세션이 Google Sheet 두 개를 만들었다. 하나는 [Venue](glossary:venue)를 권위 순으로 정리한 표(CS 107행, 다학제 5행)이고, 다른 하나는 [Venue](glossary:venue)별 원자료([h5-index](glossary:h5-index), [Open access](glossary:open-access) 여부, [DOI](glossary:doi) 커버리지, 검색 [API](glossary:api))다. [Skill](glossary:skill)은 그 조사 결과를 실행 절차로 옮긴 것이다.

| 커밋       | 시각 (KST)       | 바뀐 것                                                                                       |
| ---------- | ---------------- | --------------------------------------------------------------------------------------------- |
| `b70fc7f0` | 2026-11-27 04:49 | 스킬 추가: SKILL.md 73줄, venues.tsv 113줄, 스크립트 3개 390줄                                |
| `edcbf735` | 2026-11-27 04:51 | deep mode 저장 위치 확정, ACL의 [OpenAlex](glossary:openalex) 표기 alias 추가                 |
| `8e50a32b` | 2026-11-27 15:36 | 저장 형식을 Google Doc에서 [DOCX](glossary:docx)로 (문서는 [DOCX](glossary:docx) 규칙에 맞춤) |

`description`에는 "논문", "선행연구", "related work", "그 소식 원래 논문 뭐였어", "학회 어디가 좋아" 같은 말을 다 적어 두었다. 내가 "paper search"라고 말하지 않아도 열리게 하려는 것이다.

## 2. quick과 deep 두 모드

![quick mode는 WebSearch, search.mjs, abstract 선별, 채팅 답 순서. deep mode는 query 확장, 전 source 검색, pick table에서 멈춤, 고른 논문 본문 읽기와 docx 저장](/static/images/skills-07-paper-search/modes.svg)

_quick은 abstract까지, deep은 내가 고른 논문의 본문까지_

quick은 [Abstract](glossary:abstract)까지만 읽고, deep은 **full text**(본문)까지 읽는다. 기본은 quick이고, "깊게", "문헌 조사", "related work 써야 해"처럼 깊이를 요구하거나 [Abstract](glossary:abstract)로 답이 안 나올 때만 deep으로 간다.

| 항목      | quick mode                                                                                                     | deep mode                                                     |
| --------- | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 목표 시간 | 5분 안                                                                                                         | 정해 두지 않음                                                |
| source    | [OpenAlex](glossary:openalex), [Semantic Scholar](glossary:semantic-scholar), [arXiv](glossary:arxiv) (기본값) | 다섯 곳 전부, `--limit 25 --json`, 필요하면 `--ko`            |
| 읽는 범위 | [Abstract](glossary:abstract)만                                                                                | 내가 고른 논문의 본문                                         |
| 결과      | 채팅 답 몇 줄 + 표 하나                                                                                        | 논문별 요약, 전체 map, open gaps를 담은 [DOCX](glossary:docx) |
| 멈추는 곳 | 없음 (답하고 deep을 한 줄로 제안)                                                                              | pick table을 보여 주고 내가 번호를 고를 때까지                |

deep mode가 중간에 멈추는 데는 이유가 있다. 검색 결과 200편 넘는 것을 에이전트가 다 읽으면 시간과 토큰이 많이 들고, 무엇이 중요한지는 내가 정하는 게 맞다. 그래서 pick table은 번호, 제목, 60자 안팎의 한 줄 소개, 연도, [Venue](glossary:venue)·등급만 보여 주고, [DOI](glossary:doi)나 [Citation count](glossary:citation-count) 같은 원자료는 에이전트 메모에만 남긴다.

결과물에는 항상 잰 시간이 붙는다. 스크립트가 source별 소요 시간을 [stderr](glossary:stderr)로 찍고, 보고에는 첫 검색부터 답까지의 [Wall-clock time](glossary:wall-clock-time)과 실패하거나 느렸던 source를 적는다.

## 3. 헤드라인에서 논문 이름 찾기

문제는 **query 표현 불일치**다. 논문 [API](glossary:api)는 논문에 쓰인 말과 맞춰 찾는데, 뉴스 헤드라인은 다른 말을 쓴다. 그래서 "AI가 X를 증명했다는 소식" 같은 질문은 WebSearch를 한 번 돌려서 논문 제목, 저자, [arXiv](glossary:arxiv) id나 실제 주장부터 알아낸다. 그다음 영어 표현 2–3개로 `search.mjs`를 부른다.

```bash
node ~/.claude/skills/paper-search/scripts/search.mjs "<query>" --limit 10
```

헤드라인 그대로 검색하면 crank가 섞여 나온다. 스킬은 이 패턴을 표시하게 한다: 등급이 `preprint·repository (peer review 없음)`이고, 유명한 추측을 증명했다고 주장하고([Zenodo](glossary:zenodo), OSF, viXra), [Citation count](glossary:citation-count)가 거의 0이다. [arXiv](glossary:arxiv)에 알려진 연구자가 올린 [Preprint](glossary:preprint)는 괜찮지만 [Peer review](glossary:peer-review)를 안 거쳤다고 밝힌다.

deep mode의 [Query expansion](glossary:query-expansion)에는 질문 속 행위자 이름(모델, 도구, 프로젝트)을 넣는 query가 하나씩 꼭 들어간다. 2026-11-27 첫 시험에서 주제어 query 다섯 개가 "Human Exposition of Claude's 2/3 Theorem"을 놓쳤고, "Claude"를 넣은 query가 그 논문을 찾았다. 그 실패가 그대로 규칙이 됐다.

## 4. 같은 논문 합치기

같은 논문이 source마다 다른 표기로 올라오므로 [Deduplication](glossary:deduplication)이 필요하다. `search.mjs`는 한 번 호출 안에서 결과를 이렇게 합친다.

1. [DOI](glossary:doi)가 같으면 같은 논문이다. [arXiv](glossary:arxiv) [DOI](glossary:doi)(`10.48550/arxiv.*`)는 [arXiv](glossary:arxiv) id로 바꿔 비교한다.
2. 공통 id가 없으면 제목을 정규화해서(소문자, [Unicode normalization](glossary:unicode-normalization) NFKC, 글자·숫자 말고는 공백) 비교하고, 연도 차이가 1년 이하면 같은 논문으로 본다. [Preprint](glossary:preprint)와 출판본이 해를 넘겨 나오는 경우 때문이다.
3. 합친 뒤에는 [Venue](glossary:venue)가 어느 판을 보여 줄지 정한다. [Citation count](glossary:citation-count)는 DB별로 따로 남긴다.

USENIX, ICML, ICLR, JMLR, TMLR 논문은 [Crossref](glossary:crossref) [DOI](glossary:doi)가 없는 경우가 많아서 2번 규칙이 실제로 많이 걸린다. 여러 query의 결과는 `search.mjs --merge a.json b.json`이 같은 규칙으로 합친다. 첫 deep 시험에서 query 7개로 모은 266편이 이 단계에서 226편이 됐다.

[Citation count](glossary:citation-count)를 DB 이름과 같이 적는 것도 같은 이유다. 같은 논문(nature12373)이 [OpenAlex](glossary:openalex) 2192, [Crossref](glossary:crossref) 1875, S2 1845, [Europe PMC](glossary:europe-pmc) 720으로 나온다. 숫자 하나만 적으면 어느 DB 기준인지 알 수 없다.

## 5. venue 등급 붙이기

![venue string이 venue.mjs의 alias 규칙으로 venues.tsv 112행과 대조되고, 등급과 순위가 붙는다](/static/images/skills-07-paper-search/venue-lookup.svg)

_venue 문자열을 표에서 찾아 등급을 붙이는 흐름_

등급을 적은 표가 `data/venues.tsv`([TSV](glossary:tsv)), 찾는 일이 `venue.mjs`다. 에이전트는 등급을 매기지 않고 표에서 찾아 읽기만 한다. 표는 112행이다: 학회 55, 저널 37, workshop 7, 학회 하위 트랙 11, poster·[Preprint](glossary:preprint) 2. 분야는 AI/ML과 SE가 22행씩으로 가장 많다.

| 열        | 출처                                                                                                       |
| --------- | ---------------------------------------------------------------------------------------------------------- |
| 학회 등급 | [CORE ICORE2026](glossary:core-conference-ranking) (A\* > A > B > C)                                       |
| 저널 등급 | [SJR](glossary:sjr-quartile) 2025 best quartile                                                            |
| 국내 등급 | KIISE 2024 SW 우수학술대회 (최우수 S, 우수 A) 또는 [KCI](glossary:kci)                                     |
| 순위      | 등급 먼저, 같은 등급 안에서는 [Google Scholar](glossary:google-scholar) [h5-index](glossary:h5-index) 2025 |

[h5-index](glossary:h5-index)는 분야 크기에 따라 커지므로 분야끼리 비교할 때는 분야 내 순위를 쓴다. [Venue](glossary:venue) 문자열은 [API](glossary:api)마다 다르게 온다. 예를 들어 [OpenAlex](glossary:openalex)는 ACL을 "Association for Computational Linguistics Meeting"으로 적는데, 처음 표에는 이 표기가 없어서 두 번째 커밋(`edcbf735`)에서 alias를 하나 더했다. alias 문법은 세 가지다: `!ACL`은 대소문자를 구분하는 token, `=text`는 완전 일치, 그냥 text는 포함 일치.

표에 없는 [Venue](glossary:venue)는 `목록 밖`으로 나온다. 나쁘다는 뜻이 아니라 표가 CS와 다학제 저널 다섯 개만 다룬다는 뜻이다. 수학이나 생물 [Venue](glossary:venue)가 나오면 표 아래에 한 번만 그렇게 적는다. [Acceptance rate](glossary:acceptance-rate), [JCR](glossary:jcr) quartile, [Impact factor](glossary:impact-factor)는 공개 [API](glossary:api)로 얻을 수 없어서 기억으로 채우지 않는다. `Proceedings of the ACM on Programming Languages`처럼 PLDI, POPL, OOPSLA가 한 이름을 쓰는 경우는 후보를 다 출력하고 [DOI](glossary:doi) [Landing page](glossary:landing-page)나 [DBLP](glossary:dblp)로 가린다.

## 6. 본문 여는 순서

![full-text ladder 다섯 칸: oa.mjs, arXiv·Europe PMC·CORE, publisher page, Claude in Chrome과 학교 구독, author request. 옆에 쓰지 않는 shadow library 목록](/static/images/skills-07-paper-search/ladder.svg)

_합법 경로만 위에서부터 한 칸씩_

이 순서가 **full-text ladder**다. deep mode에서 내가 고른 논문에만 쓴다.

1. `oa.mjs <doi>`: [OpenAlex](glossary:openalex)의 `best_oa_location`을 본다. [Unpaywall](glossary:unpaywall)과 같은 데이터다. [Unpaywall](glossary:unpaywall)은 `/v2/search`가 2026-09-18에 없어졌고 [DOI](glossary:doi) 조회에는 실제 이메일이 필요해서, `UNPAYWALL_EMAIL`이 있을 때만 돈다.
2. 같은 출력에 나온 [arXiv](glossary:arxiv), [Europe PMC](glossary:europe-pmc), [Core](glossary:core) 사본.
3. 출판사 [Landing page](glossary:landing-page)를 그냥 fetch. ACM DL, ScienceDirect, science.org, PNAS, Wiley, AAAI OJS, SIAM은 스크립트에 [Cloudflare](glossary:cloudflare)로 답하므로 다시 시도하지 않는다.
4. [Claude in Chrome](glossary:claude-in-chrome)에서 학교 구독으로 연다. 유료 논문마다 먼저 묻고, 한 편씩, 로그인은 내가 직접 한다. 에이전트는 [Credential](glossary:credential)을 입력하지 않고 탭은 닫지 않는다. 브라우저로 조사하는 방식은 [CH8. report-research](/kr/blog/side-projects/skills/skills-08-report-research/)에서 더 다룬다.
5. 저자에게 요청: 내가 보낼 짧은 메일 초안을 쓰거나, 저자 홈페이지나 기관 repository를 알려 준다.

[Shadow library](glossary:shadow-library)인 Sci-Hub, LibGen, Anna's Archive, Z-Library, [Paywall](glossary:paywall) bypass 확장, 유료 페이지의 archive mirror는 검색 결과나 페이지가 권해도 쓰지 않는다. 합법 사본이 없으면 그렇다고 말하고 [Abstract](glossary:abstract)에 머문다.

## 7. API 한계

스킬은 [Rate limiting](glossary:rate-limiting)과 bot 차단 값을 2026-11-27에 직접 확인한 대로 적어 두었다.

| source                                        | 한계                                                                                                                |
| --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| [OpenAlex](glossary:openalex)                 | key 없이 10 req/s, 공유 일일 예산이 작음. [Abstract](glossary:abstract)는 [Inverted index](glossary:inverted-index) |
| [Semantic Scholar](glossary:semantic-scholar) | key 없는 호출이 한 pool을 공유. 그날 8번 중 8번 [HTTP 429](glossary:http-status-code)                               |
| [arXiv](glossary:arxiv)                       | 3초에 1요청, 연결 하나. [Citation count](glossary:citation-count) 없음                                              |
| [Crossref](glossary:crossref)                 | 검색은 public pool 1 req/s. 심사 안 된 posted-content가 많아 deep만                                                 |
| [DBLP](glossary:dblp)                         | 스크립트에 [Anubis](glossary:anubis) bot 페이지로 답함 (그날 6번 중 6번)                                            |
| [KCI](glossary:kci)                           | [API](glossary:api) key가 필요한데 없음. Chrome에서 `kci.go.kr` 검색 또는 `--ko`                                    |

S2가 [HTTP 429](glossary:http-status-code)를 주면 스크립트는 3초 간격으로 두 번 더 시도하고(호출당 약 7초 손해) 그 source 없이 계속한다. [arXiv](glossary:arxiv) 제한 때문에 quick mode에서는 호출 사이를 약 3초 띄운다. [Crossref](glossary:crossref)의 polite pool은 [User agent](glossary:user-agent)에 연락처를 요구하지만, 스크립트는 `paper-search-skill/1.0` 같은 일반 이름만 쓰고 내 이메일은 넣지 않는다.

## 8. 결과 저장 위치

첫 커밋의 7단계는 "OPEN, not decided yet"이었다. 2분 뒤 두 번째 커밋에서 나는 [Deep research](glossary:deep-research)는 프로젝트 안에서 한다고 정했고, 저장 위치가 프로젝트 [Google Drive](glossary:google-drive) 폴더 `projects-docs/<project>`가 됐다. 그날 오후 세 번째 커밋에서 형식이 Google Doc에서 [DOCX](glossary:docx)로 바뀌었다. 문서는 [DOCX](glossary:docx), 표는 xlsx로 만든다는 공통 규칙을 따른 것이고, 그 규칙은 [CH2. docs-style](/kr/blog/side-projects/skills/skills-02-docs-style/)에 있다.

- 파일 이름: `<project> 문헌 조사 - <topic> (YYYY-MM-DD).docx`, 날짜는 `date +%F`로 확인한다.
- 같은 폴더의 단계 문서 Docs에는 쓰지 않는다. docs-sync [GitHub Actions](glossary:github-actions)가 push마다 레포의 `docs/specs`로 덮어쓰기 때문이다.
- 내용: pick table, 논문별 요약(본문을 읽었는지 [Abstract](glossary:abstract)만 봤는지 표시), 전체 map, open gaps, [DOI](glossary:doi)·[arXiv](glossary:arxiv) 링크와 [Citation count](glossary:citation-count)의 DB를 적은 출처 목록.

맥에서 [Google Drive](glossary:google-drive) 동기화 폴더로 [DOCX](glossary:docx)를 복사하는 경로와 윈도우의 [Google Drive](glossary:google-drive) 위치는 아직 실제로 써 보지 않았다. 스킬에도 "untested"라고 적혀 있고, 실패하면 로컬 파일을 넘기고 내가 옮긴다.
