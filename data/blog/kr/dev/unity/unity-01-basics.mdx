## 0. 들어가며

[Unity](glossary:unity)를 처음 열면 폴더, 화면, 코드가 어디서 만나는지 보이지 않아서 기본 구조부터 정리했다. 정리하다가 [Input System](glossary:input-system) 설정 때문에 이동 코드가 막혀서 그 해결도 같이 적었다.

식당으로 비유하면 영업 중인 홀 하나가 한 번에 열리는 공간이고, 홀 안의 자리 하나하나가 손님이든 직원이든 존재하는 대상이다. 각 자리에 역할을 붙여서 일을 시키고, 자주 쓰는 자리 구성은 카드로 저장해 둔다. 역할을 시키는 지시서는 따로 쓴다. 홀은 [Scene](glossary:scene), 자리는 [GameObject](glossary:gameobject), 역할은 [Component](glossary:component), 저장해 둔 카드는 [Prefab](glossary:prefab), 지시서는 [C#](glossary:c) Script다. 이 글에서는 폴더 구조, [Scene](glossary:scene)과 [GameObject](glossary:gameobject), [Component](glossary:component)와 Script, 배경 만드는 법을 정리하고 Input 오류를 고친다.

## 1. 프로젝트 폴더 구조

[Unity](glossary:unity) 프로젝트에서 직접 다루는 폴더는 `Assets` 안에 있다.

```
Assets/
├─ Scenes/
├─ Scripts/
├─ Sprites/
└─ Prefabs/
```

- `Scenes`: [Scene](glossary:scene) 파일. `.unity` 하나가 [Scene](glossary:scene) 하나다.
- `Scripts`: [C#](glossary:c) 코드 파일. 파일만으로는 실행되지 않고, [Unity Editor](glossary:unity-editor)에서 [GameObject](glossary:gameobject)에 [Component](glossary:component)로 붙여야 돈다.
- `Sprites`: 2D 이미지 [Sprite](glossary:sprite). 이미지일 뿐이라 움직임, 충돌, 체력 같은 기능은 없다. 화면에 보이려면 [GameObject](glossary:gameobject)에 [SpriteRenderer](glossary:spriterenderer)가 필요하다.
- `Prefabs`: [GameObject](glossary:gameobject) 구성을 재사용 가능한 원본으로 저장한 파일. 오브젝트를 `Prefabs` 폴더로 드래그하면 만들어진다.

[Prefab](glossary:prefab)은 Script와 이미지를 하나로 합치지 않는다. 붙어 있는 [Component](glossary:component) 목록, 각 설정값, 참조하는 [Asset](glossary:asset)(`player.png`, `PlayerMove.cs`)을 저장한다.

## 2. Project, Scene, GameObject

계층은 `Project` > `Scene` > `GameObject` > `Component`다. Project는 게임 전체이고 `Assets/`, `Packages/`, `ProjectSettings/`를 가진다.

[Scene](glossary:scene)은 한 번에 불러오는 오브젝트 묶음이다. 화면 이미지가 아니라 "어떤 오브젝트가 어디에 어떤 [Component](glossary:component)로 있는지"를 저장한 파일이다. 화면은 [Scene](glossary:scene) 안의 [Camera](glossary:camera)가 찍어서 [Game View](glossary:game-view)에 보여준다. 작은 게임은 `SampleScene` 하나에 전부 넣어도 되고, 커지면 `MainMenu`, `GameScene`, `GameOver`처럼 나눈다.

```
SampleScene
├─ Main Camera
├─ Player
├─ Enemy
└─ UI
```

`Player` 같은 오브젝트는 독립 파일이 아니라 [Scene](glossary:scene) 파일(`SampleScene.unity`) 안에 저장된다. 그래서 [VS Code](glossary:vs-code)에는 `Player.cs`가 없고 `PlayerMove.cs`만 코드 파일로 보인다.

[GameObject](glossary:gameobject)는 빈 껍데기이고 기능은 [Component](glossary:component)가 만든다. `Player`라는 이름은 필수가 아니라서 `Hero`로 바꿔도 되고, 중요한 건 어떤 [Component](glossary:component)가 붙어 있는지다.

## 3. Component 조합

오브젝트는 [Component](glossary:component)의 조합이다. `Player`는 이렇게 구성한다.

| [Component](glossary:component)                                    | 역할                                                                     |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| [Transform](glossary:transform)                                    | 위치, 회전, 크기. 모든 [GameObject](glossary:gameobject)에 기본으로 있다 |
| @@spriterenderer@@[Sprite](glossary:sprite)Renderer@@/@@           | 2D 이미지를 화면에 표시                                                  |
| [Rigidbody2D](glossary:rigidbody2d)                                | 2D [physics engine](glossary:2d-physics-engine)의 영향을 받게 함         |
| Box[Collider](glossary:collider)2D ([Collider](glossary:collider)) | 충돌 범위                                                                |
| PlayerMove.cs                                                      | 직접 쓴 이동 코드                                                        |

기능을 만드는 순서는 늘 같다. [GameObject](glossary:gameobject) 만들기, [Component](glossary:component) 붙이고 값 설정, [C#](glossary:c) Script 쓰기, Script를 [GameObject](glossary:gameobject)에 붙이기, 실행해서 확인.

## 4. Script가 붙는 방식

[MonoBehaviour](glossary:monobehaviour)를 상속한 클래스가 [GameObject](glossary:gameobject)에 [Component](glossary:component)로 붙는다.

```csharp
using UnityEngine;

public class PlayerMove : MonoBehaviour
{
    public float speed = 5f;

    void Update()
    {
        float x = Input.GetAxisRaw("Horizontal");
        float y = Input.GetAxisRaw("Vertical");

        Vector3 direction = new Vector3(x, y, 0).normalized;
        transform.position += direction * speed * Time.deltaTime;
    }
}
```

`Update()`는 매 [Frame](glossary:frame) 불린다. [Time.deltaTime](glossary:delta-time)을 곱해서 Frame 속도와 상관없이 같은 속도로 움직이게 한다. 코드의 `transform`은 이 Script가 붙은 [GameObject](glossary:gameobject)의 [Transform](glossary:transform)이다. 이름으로 오브젝트를 찾는 게 아니라 자기가 붙은 [GameObject](glossary:gameobject)를 기준으로 동작하므로, 같은 Script를 Enemy에 붙이면 Enemy가 움직인다.

## 5. Unity Editor와 VS Code 역할

@@unity-editor@@[Unity](glossary:unity) Editor@@/@@는 [Scene](glossary:scene) 편집, [GameObject](glossary:gameobject) 생성, [Component](glossary:component) 추가, [Sprite](glossary:sprite)·[Prefab](glossary:prefab)·[Collider](glossary:collider)·[Camera](glossary:camera) 설정, 실행 테스트를 맡는다. [VS Code](glossary:vs-code)는 [C#](glossary:c) Script와 게임 로직 작성을 맡는다.

## 6. 배경과 구조물

모든 걸 [GameObject](glossary:gameobject)로 만들지는 않는다.

| 종류                         | 방법                                                     |
| ---------------------------- | -------------------------------------------------------- |
| 움직이고 행동하는 것         | [GameObject](glossary:gameobject) + Script               |
| 반복 배치되는 바닥, 벽, 배경 | [Tilemap](glossary:tilemap)                              |
| 이미지로만 보이는 큰 배경    | @@spriterenderer@@[Sprite](glossary:sprite)Renderer@@/@@ |

바닥 타일 1000개를 [GameObject](glossary:gameobject) 1000개로 만들면 낭비라서, `Grid` 아래 `Ground Tilemap`, `Wall Tilemap`을 두고 [Tilemap](glossary:tilemap) 하나가 타일 데이터를 관리하게 한다. 벽 500개면 `Wall_001`~`Wall_500` [GameObject](glossary:gameobject) 500개 대신 [Tilemap](glossary:tilemap) [GameObject](glossary:gameobject) 하나다.

## 7. Input System 오류 해결

4번 코드를 실행하자 `UnityEngine.Input`을 읽는 줄에서 아래 오류가 났다.

```text
You are trying to read Input using the UnityEngine.Input class, but you have switched active Input handling to Input System package in Player Settings.
```

원인은 프로젝트가 [Input System](glossary:input-system) 패키지만 쓰도록 설정돼 있어서, 옛 [Input Manager](glossary:input-manager) 방식인 `UnityEngine.Input`이 꺼져 있었던 것이다. [Player Settings](glossary:player-settings)에서 Active Input Handling을 `Both`로 바꾸면 둘 다 쓸 수 있다.

1. `Edit` > `Project Settings` > `Player`를 연다.

   ![Player Settings 화면](/static/images/unity-err/player.png)

2. `Other Settings`로 이동한다.

   ![Other Settings 화면](/static/images/unity-err/other-setting.png)

3. `Active Input Handling` 값을 `Both`로 바꾼다.

   ![Active Input Handling 설정 화면](/static/images/unity-err/active-input.png)
