## 0. Introduction

> Part 3 of the skills series. What a [skill](glossary:agent-skill) is, and why these rules live in skills instead of the instruction file, is in [CH0. Skills overview](/en/blog/side-projects/skills/skills-00-overview/).

On 2026-10-11, after writing the [README](glossary:readme) for the agent-commonplace repo, I liked it enough to decide that every public repo [README](glossary:readme) would follow that format from then on.

In restaurant terms, this is every branch of a chain using the same menu layout. The order of the menu's boxes is the [README](glossary:readme)'s section order, the blank menu a new branch fills in is the template, the tasting before opening, where you cook the recipe from scratch once, is running the Quickstart in a throwaway environment, and the menu photos are terminal images drawn from a real command's [stdout](glossary:stdout).

The same day I stripped that [README](glossary:readme) down to a skeleton and made the `readme-style` [skill](glossary:agent-skill). The [skill](glossary:agent-skill) is three files, 241 lines (9,878 bytes), and it has not been changed since. Five of my public repos follow the format today, and the script that draws terminal images has produced 31 images across 9 blog posts.

## 1. What the skill does

![16 README sections in four groups: Landing, Why and Quickstart, How it works, Reference](/static/images/skills-03-readme-style/section-order.svg)

_16 [README](glossary:readme) sections in four groups: Landing, Why and Quickstart, How it works, Reference_

The [skill](glossary:agent-skill) fixes a [README](glossary:readme)'s **section order** and ships a **template**. The [skill](glossary:agent-skill) folder has three files.

- **`SKILL.md`**: the order of the 16 sections, image rules, and what to check before finishing (40 lines).
- **`template.md`**: a [README](glossary:readme) skeleton where only the placeholders (`<repo-name>`, `<owner>/<repo>`) need filling (144 lines).
- **`terminal-svg.js`**: a script that turns a command's real output into a terminal-window [SVG](glossary:svg) (57 lines).

The section order reads as four groups, as in the diagram. The top is where a first-time visitor looks (nav row, intro paragraph, [badges](glossary:badge)), the middle is what someone installing follows (Quickstart), and the bottom is where someone who got stuck comes looking (FAQ). The [README](glossary:readme) is written in English, and there is no logo unless asked. The rule about writing public documents in English lives in [CH2. docs-style](/en/blog/side-projects/skills/skills-02-docs-style/).

When the [skill](glossary:agent-skill) opens is written in its description: writing a [README](glossary:readme), rewriting one, or preparing a repo for publishing. The instruction file only lists the word "`readme-style`([README](glossary:readme))"; the body is read only at that point.

## 3. Rules for the first screen

The first screen of the [README](glossary:readme) is three things.

- **nav row**: one line right under the title, bold [anchor](glossary:anchor-link) links joined by `|`. It jumps straight to sections like Quickstart, How it works, Configuration and FAQ.
- **intro paragraph**: one paragraph. Bold what it does, who it is for, and the one-line difference from alternatives. No marketing filler.
- **[badges](glossary:badge)**: two rows of [shields.io](glossary:shieldsio) [badges](glossary:badge). The first row is project facts (stars, [CI](glossary:ci) status, version, [license](glossary:open-source-license), runtime version, platforms), the second is what it supports and [PRs](glossary:pull-request) welcome.

```md
# <repo-name>

[**Quickstart**](#quickstart) | [**How it works**](#how-it-works) | [**FAQ**](#faq)
```

The most important [badge](glossary:badge) rule is "only [badges](glossary:badge) that are true and won't render as broken or 0". A sponsors [badge](glossary:badge) with no sponsors, or a chat [badge](glossary:badge) with no chat room, leaves an empty spot on the first screen, so empty [badges](glossary:badge) are left out entirely. The star [badge](glossary:badge) and the [Star History](glossary:star-history) chart need the GitHub repo to exist, though, so they look empty before the first push, and the [skill](glossary:agent-skill) makes me say so in the report.

Below come `## Updates` (newest first, `[YYYY/MM/DD] **vX.Y.Z, summary.**`), the [Star History](glossary:star-history) chart, and the table of contents. Before finishing, I check that the [anchors](glossary:anchor-link) in the nav row and the table of contents match the real headings.

## 4. Follow the Quickstart yourself

The [README](glossary:readme)'s Quickstart is verified by running it literally in a **throwaway environment**. The [skill](glossary:agent-skill)'s "Before finishing" section requires it.

- Override `HOME` with a temporary folder so my real settings are untouched.
- If a remote is needed, create a local [bare repo](glossary:bare-repository) and use it instead.
- If a step fails, fix the [README](glossary:readme) or the code, and repeat until every step passes.
- At the end, report what was verified and what wasn't.

The shape of the Quickstart is fixed too. `### Requirements` comes first, then numbered steps like `### 1. …`, each with a command code block. The one thing people must not get wrong goes in a single `> [!IMPORTANT]` [alert](glossary:github-alert). The last step is "check it works", and that is where the terminal image goes.

The FAQ comes from the same idea. With headings like `### 1. <exact error message>`, someone who is stuck can copy the error and find it with in-page search. The cause and the fixing command sit under it.

Why these rules appeared, for example whether a [README](glossary:readme) once went out with a Quickstart that didn't work, is not recorded (no record). They were in the [skill](glossary:agent-skill)'s first commit.

## 5. Terminal images from real output only

![Making a terminal image: run the command, output.txt, terminal-svg.js, out.svg, headless render check](/static/images/skills-03-readme-style/terminal-pipeline.svg)

_Making a terminal image: run the command, output.txt, terminal-svg.js, out.svg, [headless](glossary:headless-browser) render check_

This pipeline captures a real command's **[stdout](glossary:stdout)** to a file and renders it as an [SVG](glossary:svg). The order is: run the command, `output.txt`, `terminal-svg.js`, [headless](glossary:headless-browser) browser render check.

1. Run the command for real. If needed, do it in the throwaway environment from section 4.
2. Save the output to a text file and replace home paths with `~`.
3. Draw it with `node ~/.claude/skills/readme-style/terminal-svg.js <output.txt> <out.svg> [title] [command]`.
4. On Windows, take a PNG with `msedge --headless=new --screenshot=<png>` and open it. Fix text that overflows its box or lines that overlap.

The script is 57 lines and uses only Node's built-in `fs`. What it does is simple. The window is a fixed 900 px wide with the height set by the line count, and the top bar gets three red, yellow and green dots like a macOS window. Then each line gets colour from a few [regular expressions](glossary:regular-expression).

- In lines shaped like `Label   value`, the label is blue.
- Words like `ok`, `passed`, `synced` and `done` are green.
- `error`, `failed` and `fatal` are red.
- An [ISO timestamp](glossary:iso-8601) at the start of a line is grey.
- Backslashes in Windows paths become `/`.

The image below is real output drawn with this script. It is the result of running `wc -l` in the [skill](glossary:agent-skill) folder, unchanged.

![wc -l output drawn with terminal-svg.js: SKILL.md 40 lines, template.md 144 lines, terminal-svg.js 57 lines, 241 total](/static/images/skills-03-readme-style/terminal-wc.svg)

_wc -l output drawn with terminal-svg.js: SKILL.md 40 lines, template.md 144 lines, terminal-svg.js 57 lines, 241 total_

The rule against inventing output is written into the [skill](glossary:agent-skill) as "Never invent output". An image in a [README](glossary:readme) is a promise that this is the screen a user will see when they type the same thing.

The diagram half of the same rule is there too. [README](glossary:readme) [SVGs](glossary:svg) go in `docs/images/`, and each one sits on a light grey background card (`#f6f8fa` fill, `#d0d7de` stroke, corner radius 16), so the text doesn't disappear into the background in GitHub's [dark mode](glossary:dark-mode). For [accessibility](glossary:accessibility) they get `role="img"` and an `aria-label`, and they are embedded centred.
