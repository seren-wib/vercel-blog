# 관계대수 한 장 (6장 전부)

[SQL](glossary:sql)은 "뭘 원하는지", [Relational algebra](glossary:relational-algebra)는 "어떤 순서로 꺼낼지". 답 쓸 땐 ← 로 한 줄씩 끊어 쓰는 게 안 틀림

## 1. 기호 한눈에

| 기호                                                                                     | 이름                                              | 하는 일                            | [SQL](glossary:sql)                                                                           |
| ---------------------------------------------------------------------------------------- | ------------------------------------------------- | ---------------------------------- | --------------------------------------------------------------------------------------------- |
| [σ](glossary:selection)<sub>조건</sub>(R)                                                | SELECT                                            | 조건 맞는 **행**                   | [WHERE](glossary:where)                                                                       |
| [π](glossary:projection)<sub>열</sub>(R)                                                 | [PROJECT](glossary:projection)                    | 적은 **열**만, 중복 지움           | [SELECT DISTINCT](glossary:select)                                                            |
| [ρ](glossary:rename)<sub>S(열…)</sub>(R)                                                 | [RENAME](glossary:rename)                         | 테이블·열 이름 바꾸기              | AS                                                                                            |
| R [∪](glossary:union) S, R [∩](glossary:intersection) S, [R − S](glossary:set-operation) | 집합 연산                                         | 합·교·차                           | [UNION](glossary:union), [INTERSECT](glossary:intersection), [EXCEPT](glossary:set-operation) |
| R × S                                                                                    | [CARTESIAN PRODUCT](glossary:cartesian-product)   | 모든 행 조합                       | FROM R, S (조건 없이)                                                                         |
| R [⋈](glossary:join)<sub>조건</sub> S                                                    | [JOIN](glossary:join)                             | 조건 맞는 행끼리 붙임              | [JOIN](glossary:join) ON                                                                      |
| R \* S                                                                                   | [NATURAL JOIN](glossary:natural-join)             | 같은 이름 열로 붙이고 그 열 하나만 | [NATURAL JOIN](glossary:natural-join)                                                         |
| R [⟕](glossary:outer-join) S, R [⟖](glossary:outer-join) S, R [⟗](glossary:outer-join) S | [OUTER JOIN](glossary:outer-join)                 | 짝 없어도 남김                     | LEFT / RIGHT / FULL [OUTER JOIN](glossary:outer-join)                                         |
| <sub>그룹열</sub>[ℱ](glossary:aggregate-function)<sub>함수 열</sub>(R)                   | [Aggregate function](glossary:aggregate-function) | 묶어서 COUNT·SUM…                  | [GROUP BY](glossary:group-by) + [Aggregate function](glossary:aggregate-function)             |
| R [÷](glossary:division) S                                                               | [DIVISION](glossary:division)                     | S 전부 가진 R 행                   | [NOT EXISTS](glossary:not-exists) … [EXCEPT](glossary:set-operation)                          |
| T ← 식                                                                                   | 대입                                              | 중간 결과에 이름                   | [Temporary table](glossary:temporary-table)                                                   |

## 2. 행 고르기 σ

**[σ](glossary:selection)<sub>조건</sub>(R)**: 조건 맞는 행만. 열은 그대로

- 조건은 `열 비교 값` / `열 비교 열`, AND·OR·NOT. 비교는 =, &lt;, ≤, >, ≥, ≠

[σ](glossary:selection)<sub>Dno=4</sub>(EMPLOYEE) → 4번 부서 직원 <br />
[σ](glossary:selection)<sub>(Dno=4 AND Salary>25000) OR (Dno=5 AND Salary>30000)</sub>(EMPLOYEE)

- [σ](glossary:selection)<sub>c1</sub>([σ](glossary:selection)<sub>c2</sub>(R)) = [σ](glossary:selection)<sub>c1 AND c2</sub>(R). 순서 상관없음
- 이름이 SELECT인데 [SQL](glossary:sql)의 **[WHERE](glossary:where)**임. [SQL](glossary:sql) SELECT 자리는 [π](glossary:projection)

## 3. 열 고르기 π

**[π](glossary:projection)<sub>열 목록</sub>(R)**: 적은 열만. 결과는 집합이라 **겹치는 행 지움**

[π](glossary:projection)<sub>Lname, Fname, Salary</sub>(EMPLOYEE) → 세 열 <br />
[π](glossary:projection)<sub>Sex, Salary</sub>(EMPLOYEE) → (M, 25000) 둘이면 하나로

## 4. 이어 쓰기와 이름 바꾸기 ρ

**둘 중 하나**: 괄호로 겹치기 / ← 로 끊기. 안쪽(아래 줄)부터 실행

[π](glossary:projection)<sub>Fname, Lname, Salary</sub>([σ](glossary:selection)<sub>Dno=5</sub>(EMPLOYEE))

DEP5_EMPS ← [σ](glossary:selection)<sub>Dno=5</sub>(EMPLOYEE) <br />
RESULT ← [π](glossary:projection)<sub>Fname, Lname, Salary</sub>(DEP5_EMPS)

| [ρ](glossary:rename) 쓰는 법                   | 바꾸는 것                      |
| ---------------------------------------------- | ------------------------------ |
| [ρ](glossary:rename)<sub>S(B1, B2, …)</sub>(R) | 테이블 이름 S, 열 이름 B1, B2… |
| [ρ](glossary:rename)<sub>S</sub>(R)            | 테이블 이름만                  |
| [ρ](glossary:rename)<sub>(B1, B2, …)</sub>(R)  | 열 이름만                      |
| R(B1, B2, …) ← 식                              | ← 왼쪽에 열 이름 붙여도 됨     |

R(First_name, Last_name, Salary) ← [π](glossary:projection)<sub>Fname, Lname, Salary</sub>(DEP5_EMPS)

## 5. 집합 연산 ∪ ∩ −

**조건**: 열 개수 같고 열마다 타입 같아야 ([type compatible](glossary:union-compatibility))

| 식                              | 결과                                | 예              |
| ------------------------------- | ----------------------------------- | --------------- |
| R [∪](glossary:union) S         | 둘 중 하나에라도 있는 행, 중복 지움 | 학생이거나 강사 |
| R [∩](glossary:intersection) S  | 둘 다에 있는 행                     | 학생이면서 강사 |
| [R − S](glossary:set-operation) | R엔 있고 S엔 없는 행. S − R과 다름  | 강사 아닌 학생  |

RESULT1 ← [π](glossary:projection)<sub>Ssn</sub>(DEP5_EMPS) <br />
RESULT2(Ssn) ← [π](glossary:projection)<sub>Super_ssn</sub>(DEP5_EMPS) <br />
RESULT ← RESULT1 [∪](glossary:union) RESULT2

- 5번 부서 직원이거나 그 직속 상사인 Ssn. 열 이름 달라서 RESULT2에 (Ssn) 붙임

## 6. 모든 조합 ×

**R × S**: R 행 하나마다 S 행 전부 붙임. 열 n + m, 행 |R| × |S|. 타입 안 맞아도 됨

- 혼자선 쓰레기. 뒤에 [σ](glossary:selection)로 짝 맞는 조합만 남김 → 그걸 합친 게 [JOIN](glossary:join)

FEMALE_EMPS ← [σ](glossary:selection)<sub>Sex='F'</sub>(EMPLOYEE) <br />
EMPNAMES ← [π](glossary:projection)<sub>Fname, Lname, Ssn</sub>(FEMALE_EMPS) <br />
EMP_DEPENDENTS ← EMPNAMES × DEPENDENT <br />
ACTUAL_DEPENDENTS ← [σ](glossary:selection)<sub>Ssn=Essn</sub>(EMP_DEPENDENTS) <br />
RESULT ← [π](glossary:projection)<sub>Fname, Lname, Dependent_name</sub>(ACTUAL_DEPENDENTS)

- 여직원과 부양가족 이름. 3행 × 7행 = 21행 만들고 [σ](glossary:selection)로 짝 맞는 것만

## 7. 붙이기 ⋈

**R [⋈](glossary:join)<sub>조건</sub> S** = [σ](glossary:selection)<sub>조건</sub>(R × S). 조건 맞는 R행·S행을 한 줄로

DEPT_MGR ← DEPARTMENT [⋈](glossary:join)<sub>Mgr_ssn=Ssn</sub> EMPLOYEE <br />
RESULT ← [π](glossary:projection)<sub>Dname, Lname, Fname</sub>(DEPT_MGR)

- 부서별 관리자 이름

| 종류                                                                 | 조건                             | 결과 열                                                |
| -------------------------------------------------------------------- | -------------------------------- | ------------------------------------------------------ |
| [THETA JOIN](glossary:theta-join) [⋈](glossary:join)<sub>A θ B</sub> | θ는 =, &lt;, ≤, >, ≥, ≠ 아무거나 | R 열 + S 열 전부                                       |
| [EQUIJOIN](glossary:equijoin) [⋈](glossary:join)<sub>A=B</sub>       | = 만                             | R 열 + S 열 전부. 값 같은 열 둘 다 남음 (Mgr_ssn, Ssn) |
| [NATURAL JOIN](glossary:natural-join) R \* S                         | 이름 같은 열끼리 =               | 같은 이름 열은 하나만                                  |

- [NATURAL JOIN](glossary:natural-join)은 열 이름이 같아야. 다르면 [ρ](glossary:rename)로 먼저 맞춤

DEPT ← [ρ](glossary:rename)<sub>(Dname, Dnum, Mgr_ssn, Mgr_start_date)</sub>(DEPARTMENT) <br />
PROJ_DEPT ← PROJECT \* DEPT

- PROJECT.Dnum과 맞추려고 Dnumber → Dnum

- 결과 행 수: 0 (하나도 안 맞음) ~ |R| × |S| (전부 맞음)

**[OUTER JOIN](glossary:outer-join)**: 짝 없는 행도 남기고 빈 칸 [NULL](glossary:null). [⟕](glossary:outer-join) 왼쪽 전부, [⟖](glossary:outer-join) 오른쪽 전부, [⟗](glossary:outer-join) 양쪽

TEMP ← EMPLOYEE [⟕](glossary:outer-join)<sub>Ssn=Mgr_ssn</sub> DEPARTMENT <br />
RESULT ← [π](glossary:projection)<sub>Fname, Minit, Lname, Dname</sub>(TEMP)

- 전 직원 + 관리하는 부서 이름. 관리자 아니면 Dname [NULL](glossary:null)

## 8. 세기 ℱ

**<sub>그룹 열</sub> [ℱ](glossary:aggregate-function) <sub>함수 열, …</sub>(R)**: 그룹 열 같은 행끼리 묶어 함수. 함수는 COUNT, SUM, AVERAGE, MAXIMUM, MINIMUM

<sub>Dno</sub> [ℱ](glossary:aggregate-function) <sub>COUNT Ssn, AVERAGE Salary</sub>(EMPLOYEE) -
부서별 직원 수·평균 급여. 결과 열 Dno, Count_ssn, Average_salary

[ℱ](glossary:aggregate-function) <sub>COUNT Ssn, AVERAGE Salary</sub>(EMPLOYEE)

- 그룹 열 없으면 전체 한 묶음 → 한 행

[ρ](glossary:rename)<sub>R(Dno, No_of_employees, Average_sal)</sub>(<sub>Dno</sub> [ℱ](glossary:aggregate-function) <sub>COUNT Ssn, AVERAGE Salary</sub>(EMPLOYEE))

- 열 이름 바꾸려면 [ρ](glossary:rename)로 감쌈

- 중복 안 지우고 셈 / [NULL](glossary:null)은 빼고 / 결과는 한 칸이라도 테이블

## 9. 전부 가진 것 찾기 ÷

**R [÷](glossary:division) S**: S에 있는 값을 **전부** 가진 R의 행. S 열은 R 열의 일부여야 하고, 결과 열 = R 열 − S 열

![R(A, B) ÷ S(A): S의 a1, a2, a3을 전부 가진 B 값만 남음](/static/images/database-systems-ch5-relational-algebra/ra-division.svg)

SMITH ← [σ](glossary:selection)<sub>Fname='John' AND Lname='Smith'</sub>(EMPLOYEE) <br />
SMITH_PNOS ← [π](glossary:projection)<sub>Pno</sub>(WORKS_ON [⋈](glossary:join)<sub>Essn=Ssn</sub> SMITH) <br />
SSN_PNOS ← [π](glossary:projection)<sub>Essn, Pno</sub>(WORKS_ON) <br />
SSNS(Ssn) ← SSN_PNOS [÷](glossary:division) SMITH_PNOS <br />
RESULT ← [π](glossary:projection)<sub>Fname, Lname</sub>(SSNS \* EMPLOYEE)

- Smith가 하는 프로젝트 전부에 참여하는 직원. SMITH_PNOS = \{1, 2\}면 1도 2도 하는 Essn만 남음

**[÷](glossary:division) 쓰는 틀**: ① "전부"의 목록 S 만들기([π](glossary:projection) 한 열) → ② 누가 뭘 하는지 R 만들기([π](glossary:projection) 두 열, S 열 포함) → ③ R [÷](glossary:division) S → ④ 이름 붙이려고 \* 로 원본과 붙이기

## 10. 완전 집합과 질의 트리

**[Complete set of operations](glossary:complete-set-of-operations) \{[σ](glossary:selection), [π](glossary:projection), [∪](glossary:union), [ρ](glossary:rename), −, ×\}**: 이 여섯으로 나머지 다 만듦

- R [∩](glossary:intersection) S = (R [∪](glossary:union) S) − (([R − S](glossary:set-operation)) [∪](glossary:union) (S − R))
- R [⋈](glossary:join)<sub>c</sub> S = [σ](glossary:selection)<sub>c</sub>(R × S)

**[Query tree](glossary:query-tree)**: 식을 나무로. 잎 = 테이블, 안쪽 = 연산, 잎부터 위로 실행

![Stafford 프로젝트 질의를 σ → ⋈ → ⋈ → π 순서로 그린 질의 트리](/static/images/database-systems-ch5-relational-algebra/ra-query-tree.svg)

## 11. 같은 질문, SQL 옆에 관계대수

| 질문                                  | [SQL](glossary:sql)                                                                                                  | [Relational algebra](glossary:relational-algebra)                                                                                                                                                          |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 5번 부서 직원 이름·급여               | `SELECT Fname, Lname, Salary FROM EMPLOYEE WHERE Dno = 5`                                                            | [π](glossary:projection)<sub>Fname, Lname, Salary</sub>([σ](glossary:selection)<sub>Dno=5</sub>(EMPLOYEE))                                                                                                 |
| Research 부서 직원 이름·주소          | `SELECT Fname, Lname, Address FROM EMPLOYEE, DEPARTMENT WHERE Dname = 'Research' AND Dnumber = Dno`                  | RESEARCH ← [σ](glossary:selection)<sub>Dname='Research'</sub>(DEPARTMENT) / RD ← RESEARCH [⋈](glossary:join)<sub>Dnumber=Dno</sub> EMPLOYEE / [π](glossary:projection)<sub>Fname, Lname, Address</sub>(RD) |
| 직원과 상사 이름                      | `… FROM EMPLOYEE AS E, EMPLOYEE AS S WHERE E.Super_ssn = S.Ssn`                                                      | S ← [ρ](glossary:rename)<sub>S(Sssn, Sfn, Sln, …)</sub>(EMPLOYEE) / EMPLOYEE [⋈](glossary:join)<sub>Super_ssn=Sssn</sub> S                                                                                 |
| 부서별 직원 수                        | `SELECT Dno, COUNT(*) FROM EMPLOYEE GROUP BY Dno`                                                                    | <sub>Dno</sub> [ℱ](glossary:aggregate-function) <sub>COUNT Ssn</sub>(EMPLOYEE)                                                                                                                             |
| 부양가족 없는 직원                    | `WHERE NOT EXISTS (SELECT * FROM DEPENDENT WHERE Ssn = Essn)`                                                        | ALL ← [π](glossary:projection)<sub>Ssn</sub>(EMPLOYEE) / HAS ← [π](glossary:projection)<sub>Essn</sub>(DEPENDENT) / [π](glossary:projection)<sub>Fname, Lname</sub>((ALL − HAS) \* EMPLOYEE)               |
| 5번 부서 프로젝트 전부에 참여         | `WHERE NOT EXISTS ((SELECT Pnumber FROM PROJECT WHERE Dnum = 5) EXCEPT (SELECT Pno FROM WORKS_ON WHERE Essn = Ssn))` | P5 ← [π](glossary:projection)<sub>Pnumber</sub>([σ](glossary:selection)<sub>Dnum=5</sub>(PROJECT)) / SP ← [π](glossary:projection)<sub>Essn, Pno</sub>(WORKS_ON) / SP [÷](glossary:division) P5            |
| 상사 없는 직원도 포함해서 직원 + 상사 | `LEFT OUTER JOIN`                                                                                                    | EMPLOYEE [⟕](glossary:outer-join)<sub>Super_ssn=Sssn</sub> S                                                                                                                                               |

## 12. 문제 문장 → 기호

| 문제에 이 말 나오면                              | 쓰는 것                                                                                               |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| ~인 (조건)                                       | [σ](glossary:selection)                                                                               |
| ~의 이름, 번호 (열 고르기)                       | [π](glossary:projection). 맨 마지막에                                                                 |
| 테이블 둘의 열                                   | [⋈](glossary:join)<sub>[FK](glossary:foreign-key)=[PK](glossary:primary-key)</sub>. 열 이름 같으면 \* |
| 직원과 그 상사                                   | [ρ](glossary:rename)로 EMPLOYEE 복사본 열 이름 바꾸고 [⋈](glossary:join)                              |
| ~이거나                                          | [∪](glossary:union) (열 맞춰서)                                                                       |
| ~이면서 (두 결과 다에)                           | [∩](glossary:intersection)                                                                            |
| ~가 아닌, ~가 없는                               | − (전체 − 있는 것)                                                                                    |
| 몇 명, 합, 평균                                  | [ℱ](glossary:aggregate-function)                                                                      |
| ~별, ~마다                                       | [ℱ](glossary:aggregate-function) 앞에 그룹 열                                                         |
| 전부에 참여하는, 모든 ~를                        | [÷](glossary:division)                                                                                |
| 짝 없는 것도 보여야                              | [⟕](glossary:outer-join) [⟖](glossary:outer-join) [⟗](glossary:outer-join)                            |
| 열 이름 안 맞아서 \* 못 씀 / 결과 열 이름 바꾸기 | [ρ](glossary:rename)                                                                                  |
