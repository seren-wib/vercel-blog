> 시리즈 17편이자 마지막 글. 대회 결과와 학교 PC 반납 이야기다. 제출 당일의 회귀 시험은 [16편](/kr/blog/woowangthon/woowangthon-16-regression-test/)에, 반납을 위해 처음에 떠 둔 디스크 이미지는 [3편](/kr/blog/woowangthon/woowangthon-03-disk-images/)에, 전체 그림은 [Woowangthon 0](/kr/blog/woowangthon/woowangthon-00-overview/)에 있다.

## 한 줄 요약

11월 15일 18:00 커밋으로 제출했고, 11월 21일 본선에서 팀 18이 최우수상(전기공학부장상)을 받았다. 나는 본선에서 질의응답 일부를 맡았다. 같은 날 저녁 학교 PC 세 대를 [3편](/kr/blog/woowangthon/woowangthon-03-disk-images/)에서 떠 둔 이미지로 덮어썼다. 그 전에 리더의 지표 데이터를 외장 디스크로 옮기고, 클라우드에 남은 터널 · 키 · 인증서를 지웠다. 11월 26일 관리 콘솔에서 세 대를 지우는 것으로 학교 쪽 반납이 끝났다.

## 1. 제출

| 날짜             | 일                                                   |
| ---------------- | ---------------------------------------------------- |
| 11월 15일 18:00  | 제출 마감. 이 시각 `main` 커밋으로 심사              |
| 11월 16~20일     | 사전 심사, 본선 10팀 선발                            |
| 11월 21일 13:00~ | 본선. 팀마다 발표 10분(시연 영상 포함), 질의응답 5분 |

제출 당일 오전에 새 `main`으로 데모 경로를 처음부터 끝까지 다시 돌렸고, 오후에 실패 둘을 고쳐 다시 통과시켰다. 그 이야기가 [16편](/kr/blog/woowangthon/woowangthon-16-regression-test/#6-제출-전에-고친-것)이다. 심사는 그 뒤 18:00의 커밋으로 받았다.

## 2. 본선

본선은 11월 21일(토) 13:00에 시작했다. 발표 뒤 질의응답에서 나는 클러스터 쪽 질문 일부에 답했다. 학교 PC 세 대로 학생 서비스를 돌린다는 구조라서, 리더가 꺼지면 어떻게 되는지, 학생 몇 명까지 받을 수 있는지 같은 질문이 나올 걸로 봤다. 그래서 팀 예상 질문 목록에서 인프라 쪽만 골라, 발표 직전에 휴대폰으로 볼 수 있는 문서 하나로 묶었다. 문서 정리는 Claude Code 세션이 했고, 어떤 질문을 남기고 뺄지, 어떤 답을 짧게 다시 쓸지는 내가 정했다. 남은 질문은 14개다.

## 5. 반납 순서

이사 나갈 때 집을 비우는 순서와 같다. 남길 짐부터 빼고, 내 이름으로 된 계약을 끊고, 집 안을 처음 사진대로 되돌리고, 마지막에 열쇠를 돌려준다. 여기서 짐은 리더의 지표 데이터, 계약은 클라우드의 터널 · 키 · 인증서, 처음 사진은 [3편](/kr/blog/woowangthon/woowangthon-03-disk-images/)의 디스크 이미지와 BIOS 사진, 열쇠는 Tailscale 관리 콘솔의 기기 등록이다.

![반납 순서. 11월 21일에 리더 데이터 백업, 클라우드 정리, Clonezilla restoredisk 세 대, BIOS 원복. 11월 26일에 관리 콘솔에서 세 대 제거](/static/images/woowangthon-17-finals-and-return/return-order.svg)

3편에서 "하나씩 지우기" 대신 디스크 이미지를 고른 이유가 여기서 돌아온다. 3주 동안 세 대에 깐 k3s, 학생 데이터, 공개키, sudo 설정, Tailscale을 목록대로 지울 필요가 없다. restoredisk 한 번이면 디스크가 11월 4일 이미지를 뜬 상태, 곧 받은 상태로 돌아간다.

대신 이미지가 못 지우는 것이 있다. 순서는 그걸로 정했다.

| 순서 | 무엇               | 앞에 와야 하는 이유                                              |
| ---- | ------------------ | ---------------------------------------------------------------- |
| 1    | 리더 데이터 백업   | restoredisk가 리더 디스크를 지운다. 남길 건 그 전에 빼야 한다    |
| 2    | 클라우드 정리      | 터널, 키, 인증서는 디스크 밖에 있다. 이미지로 덮어써도 살아 있다 |
| 3    | restoredisk ×3     | 디스크를 받은 상태로                                             |
| 4    | BIOS 원복          | BIOS 설정은 디스크가 아니라 메인보드에 있다                      |
| 5    | 관리 콘솔에서 제거 | 세 대가 다시는 안 붙는 걸 본 뒤에 지운다                         |

## 6. 덮어쓰기 전에 남긴 것

리더에는 11월 11일 밤부터 Prometheus가 모은 약 10일치 클러스터 지표가 있었다. 덮어쓰면 사라지니 먼저 뺐다.

| 파일                  | 크기    | 내용                                                            |
| --------------------- | ------- | --------------------------------------------------------------- |
| `prometheus-tsdb.tar` | 4.76 GB | Prometheus 데이터. 블록 17개, 11월 11일 22:54 ~ 11월 21일 18:39 |
| `grafana-data.tar`    | 58.6 MB | Grafana 대시보드와 설정                                         |
| `cluster-state.txt`   |         | 덮어쓰기 직전 클러스터 상태                                     |
| `prometheus-cr.yaml`  |         | Prometheus 설정                                                 |

Prometheus와 Grafana를 멈춘 뒤에 복사했다. 돌고 있는 중에 데이터 폴더를 묶으면 쓰다 만 블록이 들어갈 수 있다. 복사는 16초 걸렸고, 외장 디스크를 다시 마운트해서 SHA256을 비교했다. 세 파일 모두 같았다. 이 백업은 지금 외장 디스크 한 곳에만 있다.

## 7. 클라우드 쪽 정리

디스크 밖에 남는 것들이다. 이 작업은 Claude Code 세션에 맡겼고, 나는 지울 목록을 확인하고 진행을 정했다.

| 어디           | 지운 것                                                                                                    |
| -------------- | ---------------------------------------------------------------------------------------------------------- |
| Cloudflare     | DNS 레코드 4개(와일드카드, `api.`, `app.`, 인증서 검증용), 터널 2개(리더의 방문자 입구, EC2의 `api.` 터널) |
| AWS SSM        | 파라미터 8개. 터널 토큰, vLLM API 키, GoCD 자동 등록 키 · 관리자 비밀번호 · 알림 토큰, 서버 계정 접속 정보 |
| GoCD           | 리더 실행기를 replicas 0으로 내리고, 서버에서 리더 Agent를 끄고(disable) 지움(delete)                      |
| AWS ACM        | CloudFront에서 `app.` 주소와 인증서를 떼고, 쓰는 곳이 0이 된 뒤 인증서 삭제(18:47)                         |
| Tailscale      | EC2 기기 1대, 세 노드의 공유 6개(노드마다 팀원 1명 + 공유 링크 1개)                                        |
| AWS Elastic IP | 만든 적 없음 확인                                                                                          |

ACM 인증서는 바로 안 지워졌다. CloudFront 배포가 아직 그 인증서를 쓰고 있으면 삭제가 거부된다. 그래서 CloudFront에서 먼저 떼고, 그 변경이 배포된 뒤 인증서의 사용처(`InUseBy`)가 0이 된 걸 보고 지웠다.

학생 서비스 이미지(GHCR)와 레지스트리 쓰기 토큰은 봇 계정 소유라 그 계정 주인이 정리한다. Grafana 보기 전용 비밀번호는 리더 디스크와 함께 사라졌다.

## 8. 세 대 덮어쓰기

현장에서 한 대씩 Clonezilla USB로 부팅해 `restoredisk`를 돌렸다. 3편에서 뜬 이미지를 고르고, 대상은 내장 NVMe다.

| PC     | 이미지                       | 대상             | 확인                                                |
| ------ | ---------------------------- | ---------------- | --------------------------------------------------- |
| 워커 1 | `k3s-w1-orig-2026-11-04`     | `nvme0n1` 931.5G | 이미지 검사 3분 44초(9.00 GB/min), Cloning finished |
| 워커 2 | `k3s-w2-orig-2026-11-04`     | `nvme0n1` 931.5G | 복원 전 `lsblk`로 대상 확인                         |
| 리더   | `k3s-leader-orig-2026-11-04` | `nvme0n1` 931.5G | 복원 전 `lsblk`로 대상 확인                         |

이미지를 뜰 때와 같은 함정이 반대 방향으로 있다. [3편](/kr/blog/woowangthon/woowangthon-03-disk-images/#5-이미지-뜨기)에서 장치 이름이 PC마다 달랐다. 이번에 대상을 잘못 고르면 이미지가 든 외장 디스크를 덮어쓴다. 그래서 복원 전에 `lsblk`로 크기와 모델을 보고, 931.5G 내장 NVMe만 대상으로 골랐다.

워커 1은 검사 시간과 완료 화면까지 기록했다. 워커 2와 리더는 복원과 부팅이 끝난 것만 확인했고, 대상 디스크 화면과 검사 시간은 기록으로 남기지 못했다.

## 9. BIOS와 관리 콘솔

BIOS에서 바꾼 건 하나였다. [4편](/kr/blog/woowangthon/woowangthon-04-remote-access/#7-전원-정전-뒤에도-다시-켜지게)에서 정전 뒤에도 다시 켜지게 "Restore after AC Power Loss"를 `Power On`으로 바꿨다. 세 대 모두 3편의 사진대로 `Power Off`로 되돌리고 저장한 뒤, 평소대로 부팅해 받았을 때와 같은 화면이 나오는 걸 봤다.

덮어쓴 세 대는 Tailscale이 지워져 11월 21일부터 관리 콘솔에 오프라인으로 남아 있었다. 11월 26일 콘솔의 Machines에서 세 대를 지웠다. 노드용으로 만든 접근 규칙(ACL)의 `k3s-*` 항목과 팀원 공유 규칙도 같은 날 ACL을 새로 쓰면서 빠졌다. 반납 단계의 끝 기준, "세 대 모두 처음 뜬 이미지 상태 그대로, BIOS도 사진과 같음"은 여기서 닫혔다.

| 터널, 키, 인증서는 디스크 밖에 있다                   | 이미지가 못 지우는 목록은 따로 들고 간다                                         |
| 인증서는 쓰는 곳이 있으면 안 지워진다                 | 지우는 순서는 의존하는 쪽부터 떼는 순서다                                        |
| 복원 대상을 잘못 고르면 이미지가 든 디스크가 지워진다 | 이름이 아니라 `lsblk`의 크기와 모델로 고른다                                     |
| BIOS는 이미지에 안 들어간다                           | 바꾸기 전에 찍은 사진이 되돌리는 기준이다                                        |
