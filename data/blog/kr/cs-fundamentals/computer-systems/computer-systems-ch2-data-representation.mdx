# 2.1 비트와 비트 저장

표현 → 처리 → 저장 → 읽기

**컴퓨터는 정보를 비트패턴으로 표현하고, [Logic circuit](glossary:logic-circuit)으로 처리하며, 저장회로에 저장한다**

## 2.1.1 정보를 표현하는 최소 단위

1. [bit](glossary:bit): 최소단위(0, 1)
2. 1byte = 8bit
3. [bit](glossary:bit) pattern: 01010100 같은거
   - 같은 비트패턴이어도 어떻게 해석하느냐에 따라 의미가 달라짐.

## 2.1.2 비트를 처리하는 회로

1. [Boolean operation](glossary:boolean-operation)
   1. AND: 둘다 맞아야 참
   2. OR: 둘 중 하나만 맞아도 참
   3. [XOR](glossary:xor): 서로 달라야 참
   4. NOT: 그냥 반대

2. [Logic gate](glossary:logic-gate)

- [Boolean operation](glossary:boolean-operation)을 하드웨어로 구현한 회로

![논리 게이트 기호와 진리표](/static/images/computer-systems-ch2-data-representation/logic-gates.svg)

3. [Logic circuit](glossary:logic-circuit)
   - 게이트 여러 개를 연결한 회로
   - 값을 계산함
   - (A AND NOT B) OR (NOT A AND B) = [XOR](glossary:xor)

4. [CPU](glossary:cpu) 구성요소
   1. [control unit](glossary:control-unit)
   2. [ALU](glossary:alu): 여기서 연산
   3. [registers](glossary:register)
   4. [cache](glossary:cache)

   ![논리 게이트 < 논리 회로 < CPU](/static/images/computer-systems-ch2-data-representation/gate-circuit-cpu.svg)

## 2.1.3 비트를 저장하는 회로

1. [Flip-flop](glossary:flip-flop)
   - D(입력) / [Clock](glossary:clock-signal)(저장하라고 알리는 신호) / Q(출력)
   - 값을 저장(1비트만)
   - [Clock signal](glossary:clock-signal)이 들어올 때만 D가 Q에 저장되고, 그 사이에 D가 바뀌어도 Q는 그대로
   - 저장된 값은 변경 전까지 유지

2. [Register](glossary:register)
   - 여러비트를 저장
   - [Flip-flop](glossary:flip-flop) 여러개를 묶은거([Flip-flop](glossary:flip-flop)8개 = 8비트 [Register](glossary:register))

## 2.1.4 비트패턴을 간단히 쓰는 방법

1. [Hexadecimal](glossary:hexadecimal)
   - 2진법은 사람이 알아먹기 힘들어서 이걸로 보여줌. 주로 메모리주소, [Register](glossary:register) 값, 색상 헥스값.
   - 컴퓨터에는 2진법으로 저장됨
   - [Hexadecimal](glossary:hexadecimal) 한 자리 = 4비트
   - [Bit](glossary:bit)를 오른쪽부터 4개씩 끊기
   - 기호는 0–9랑 A–F, 0x 붙여서 표기.

# 2.2 기억 장치

## 2.2.1 실행 중인 정보의 저장

1. [Main memory](glossary:main-memory)
   - 실행할 프로그램의 명령어랑 처리할 데이터를 저장
   - 느리고 많이

2. [Register](glossary:register)
   - 지금당장 빨리 처리해야하는거
   - 빠르고 적게

3. [Memory cell](glossary:memory-cell)
   - [Memory cell](glossary:memory-cell): [Main memory](glossary:main-memory)를 일정한 크기로 나눈 한 칸(1바이트)
   - [Memory address](glossary:memory-address): [Memory cell](glossary:memory-cell)마다 붙은 번호

4. [메모리 읽기/쓰기](/kr/blog/cs-fundamentals/computer-systems/computer-systems-ch3-computer-organization/#311-컴퓨터-구조)

5. [RAM](glossary:ram) & [ROM](glossary:rom)
   - [ROM](glossary:rom)은 [SSD](glossary:ssd)나 [HDD](glossary:hdd)같은게 아니라 메인보드에 있는 아주 작은 메모리를 말함

   | 구분                                                         | [RAM](glossary:ram)                                         | [ROM](glossary:rom)                       |
   | ------------------------------------------------------------ | ----------------------------------------------------------- | ----------------------------------------- |
   | 이름                                                         | Random Access Memory                                        | Read-Only Memory                          |
   | [Memory address](glossary:memory-address)로 원하는 위치 접근 | 가능                                                        | 가능                                      |
   | 읽기                                                         | 가능                                                        | 가능                                      |
   | 쓰기                                                         | 자유롭게 가능                                               | 종류에 따라 불가능하거나 별도 절차로 가능 |
   | 전원을 끄면                                                  | 내용이 사라짐 ([Volatile memory](glossary:volatile-memory)) | 내용이 유지됨 (비휘발성)                  |
   | 주요 저장 내용                                               | 실행 중인 프로그램과 데이터                                 | 부팅·초기화에 필요한 기본 프로그램        |

6. 기억장치 용량
   - 2^10승씩 늘어남

## 2.2.2 장기간 데이터의 저장

1. [Secondary storage](glossary:secondary-storage)
   - 싸고 양많고 느리고 비휘발성
   - 프로그램이 실행될 때: [Secondary storage](glossary:secondary-storage) -> [Main memory](glossary:main-memory) -> [Register](glossary:register) -> [CPU](glossary:cpu)
   1. [HDD](glossary:hdd): 자기로 저장
   2. [SSD](glossary:ssd), USB: 반도체로 저장
   3. CD, DVD: 광학으로 저장

### HDD

- [Platter](glossary:platter): 원판
- [Track](glossary:track): 원판안에 새겨진 경로
- [Sector](glossary:sector): [Track](glossary:track)을 잘게 나눈 영역
- 헤드: 읽는 핀같은거
- [Seek time](glossary:seek-time): 헤드가 [Track](glossary:track)까지 이동하는 시간
- [Rotational latency](glossary:rotational-latency): 원판돌아서 [Sector](glossary:sector)가 원하는부분으로 오는 시간
- 전송시간: 실제로 읽거나 쓰는 시간

### 플래시 메모리

- 비휘발성 반도체 메모리
- [NAND](glossary:nand-flash)방식, 전하 넣고 빼서 0, 1표현
- 작고 가볍고 충격에 강함
- 쓰기 횟수에 한계
- 저장: 0, 비저장: 1(반대임)

### SSD

- [NAND](glossary:nand-flash) 플래시 + 컨트롤러
- 컨트롤러: 읽기, 쓰기, 저장위치를 관리, 수명 관리
- 작고, 조용하고 충격에 강하고 전력효율 좋지만 비싸고 쓰기수명제한있음

1. [SATA](glossary:sata): [HDD](glossary:hdd)때부터 써오던 인터페이스, 느림.
2. [NVMe](glossary:nvme): [SSD](glossary:ssd)용으로 설계된 통신규격, PCIe로 연결

- [M.2](glossary:m2): 크기, 연결 모양 규격. [M.2](glossary:m2)라고 다 [NVME](glossary:nvme)는 아님.

## 2.2.3 보조기억장치의 선택과 사용

1. 목적따라 원하는 저장장치 선택

# 2.3 비트패턴을 이용한 정보 표현

## 2.3.1 문자의 표현

1. [Character code](glossary:character-code)
   - 문자가 숫자로 저장됨
   - 주고받는 쪽이 같은 [Character code](glossary:character-code) 사용해야함
   - ex) [ASCII](glossary:ascii), [UNICODE](glossary:unicode)
2. [ASCII](glossary:ascii)
   - 2^7가지 저장.(7비트)
   - 컴퓨터에서는 앞에 0을 하나 더 붙여서 1바이트로 저장함.
   - 한글같은거 표현 불가
3. [UNICODE](glossary:unicode)

   | 구분                     | [Unicode](glossary:unicode)                                                 | [UTF-8](glossary:utf-8)                                                        |
   | ------------------------ | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
   | 하는 일                  | 전 세계 문자와 기호에 고유한 번호([Code point](glossary:code-point))를 부여 | [Code point](glossary:code-point)를 실제 [Byte](glossary:byte)로 변환 (인코딩) |
   | 표기                     | U+ 뒤에 [Hexadecimal](glossary:hexadecimal) (A → U+0041, 가 → U+AC00)       | [Byte](glossary:byte) 열 (가 → 11101010 10110000 10000000)                     |
   | [Byte](glossary:byte) 수 | 정하지 않음                                                                 | [Code point](glossary:code-point)에 따라 1~4바이트                             |

- 영어는 [ASCII](glossary:ascii)와 마찬가지로 1바이트. 옛날 영어파일과 호환.
- 한글은 한자리에 보통 3바이트. 이 [Byte](glossary:byte) 전환은 [utf-8](glossary:utf-8)에서 일어남

## 2.3.2 숫자의 표현

| 구분      | 문자열 "25"                                                    | 정수 25                        |
| --------- | -------------------------------------------------------------- | ------------------------------ |
| 구성      | 문자 '2'와 '5' 두 개                                           | 하나의 수                      |
| 저장 방법 | 문자마다 [Character code](glossary:character-code)로 따로 저장 | 수 전체를 이진수로 변환해 저장 |
| 저장 예   | 00110010 00110101 ('2' = 50, '5' = 53)                         | 00011001 (8비트)               |
| 산술 계산 | 그대로는 불가                                                  | 가능                           |
| 용도      | 화면 표시, 이름, 전화번호                                      | 덧셈·곱셈 같은 계산            |

### 정수

- 양수는 그대로 이진수로 표현
- 음수는 보통 [Two's complement](glossary:twos-complement)로 표현
- [Bit](glossary:bit) 수가 정해지면 표현 범위도 정해짐
- 8비트 범위
  - 부호 없음: 0~255
  - 부호 있음: -128~127
  - [Overflow](glossary:overflow): 계산 결과가 표현 범위를 벗어나는 것(양수에서 255 넘어가거나 음수에서 -129 넘어가는 것)

### 실수

- [Floating point](glossary:floating-point): 아주 크거나 작은 수를 표현하는 방법, 부호, 지수, [Mantissa](glossary:mantissa) 세 부분으로 나눠서 저장. [IEEE 754](glossary:ieee-754)가 표준(float, double)
- [Rounding error](glossary:rounding-error): 비트수가 한정되어서 나오는 오차. 가장 가까운 값으로 저장

## 2.3.3 이미지의 표현

대분류: [Raster image](glossary:raster-image) VS [Vector image](glossary:vector-image)

### 래스터 이미지

1. 이미지를 [Pixel](glossary:pixel) 격자로 표현
2. [Pixel](glossary:pixel)은 디지털 이미지를 이루는 가장작은 단위
3. [Pixel](glossary:pixel)마다 위치랑 색상값을 [Bit](glossary:bit)로 저장
4. 사진처럼 색이 복잡하게 바뀌는 이미지에 적합

### 픽셀

- [RGB](glossary:rgb)의 밝기를 섞어 색을 표현(성분 하나당 8비트)
- 한 [Pixel](glossary:pixel)의 크기 = 8\*3 = 24비트, 2^24가지 색을 표현 가능
- 1920*1080 이미지의 압축전 데이터 양 = 1920*1080\*24 = 49.8Mb = 6.2MB
- [Resolution](glossary:resolution): 이미지의 가로*세로 픽셀수, ex)1920*1080
- [Pixelation](glossary:pixelation): [Raster image](glossary:raster-image)를 확대하면 [Pixel](glossary:pixel) 경계가 보이는 현상

### 벡터 이미지

- 점, 선, 곡선, 도형을 수학적 정보로 표현
- [Pixel](glossary:pixel) 배열이 아니라 도형을 그리는 방법을 저장
- 확대하거나 줄여도 경계가 유지됨
- 로고에 어울림

### 래스터 vs 벡터

| 구분        | [Raster image](glossary:raster-image)                                                  | [Vector image](glossary:vector-image) |
| ----------- | -------------------------------------------------------------------------------------- | ------------------------------------- |
| 표현 방법   | [Pixel](glossary:pixel)의 색상값                                                       | 점·선·곡선·도형 정보                  |
| 확대        | [Pixel](glossary:pixel)이 보일 수 있음                                                 | 경계가 선명하게 유지                  |
| 적합한 대상 | 사진                                                                                   | 로고·아이콘·도형                      |
| 대표 형식   | [JPEG](glossary:jpeg), [PNG](glossary:png), [GIF](glossary:gif), [WebP](glossary:webp) | [SVG](glossary:svg)                   |

### 이미지 압축

- [Lossless compression](glossary:lossless-compression): 정보 손실이 없음(캡처, 경게가 뚜렷한 그림에 어울림)
- [Lossy compression](glossary:lossy-compression): 정보 손실이 있음(사진에 어울림)

### 대표 이미지 파일 형식

| 형식·확장자                         | 이미지 유형                           | 압축·표현 특징                                                                                                                | 주요 용도         |
| ----------------------------------- | ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ----------------- |
| [JPEG](glossary:jpeg) (.jpg, .jpeg) | [Raster image](glossary:raster-image) | [Lossy compression](glossary:lossy-compression), 투명도 미지원                                                                | 사진              |
| [PNG](glossary:png) (.png)          | [Raster image](glossary:raster-image) | [Lossless compression](glossary:lossless-compression), 투명도 지원                                                            | 그림·문서 화면    |
| [GIF](glossary:gif) (.gif)          | [Raster image](glossary:raster-image) | [Lossless compression](glossary:lossless-compression), 최대 256색, 애니메이션 지원                                            | 간단한 애니메이션 |
| [WebP](glossary:webp) (.webp)       | [Raster image](glossary:raster-image) | [Lossy compression](glossary:lossy-compression)·[Lossless compression](glossary:lossless-compression), 투명도·애니메이션 지원 | 웹 이미지         |
| [SVG](glossary:svg) (.svg)          | [Vector image](glossary:vector-image) | 도형 정보를 텍스트로 저장                                                                                                     | 로고·아이콘·도형  |

### 데이터 특징을 이용한 압축

| 방식                                                | 원리                                                       | 예                               | 효과적인 경우                                                                     |
| --------------------------------------------------- | ---------------------------------------------------------- | -------------------------------- | --------------------------------------------------------------------------------- |
| [Run-length encoding](glossary:run-length-encoding) | 같은 값이 연속되면 값과 반복 횟수로 표현                   | 0,0,0,0,0,1,1,1 → (0,5)(1,3)     | 동일한 색상이 반복되는 단순한 이미지                                              |
| [Huffman coding](glossary:huffman-coding)           | 자주 나타나는 값에 짧은 코드, 드물게 나타나는 값에 긴 코드 | geese: e=0, g=10, s=11 → 1000110 | 값의 출현 빈도 차이가 클 때                                                       |
| [Difference encoding](glossary:difference-encoding) | 값 자체보다 이전 값과의 차이를 저장                        | 23,24,25,25 → 23,1,1,0           | 인접한 [Pixel](glossary:pixel)의 색상값이 비슷할 때 (오디오·비디오 압축에도 활용) |

## 2.3.4 동영상의 표현

- 동영상 = 연속된 이미지
- [Frame](glossary:frame): 정지 이미지 1장
- 영상+오디오
- [Frame rate](glossary:frame-rate): 1초 동안 보여주는 [Frame](glossary:frame) 수, 단위: fps, 1초에 30장이면 30fps
- 압축 전 데이터양 = 가로 [Pixel](glossary:pixel) 수 × 세로 [Pixel](glossary:pixel) 수 × [Pixel](glossary:pixel)당 [Bit](glossary:bit) 수 × 초당 [Frame](glossary:frame) 수 × 재생 시간(초)

### 동영상 압축

1. 공간적 중복: [Frame](glossary:frame) 하나 안에서 반복되는 이웃 색깔 압축
2. 시간적 중복: 이전 [Frame](glossary:frame)에서 달라진 부분 중심으로 저장

### 코덱과 컨테이너

| 구분    | [Codec](glossary:codec)                                                                                                        | [Container format](glossary:container-format)          |
| ------- | ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------ |
| 정의    | 영상·오디오를 표현·압축하고 복원하는 규칙                                                                                      | 영상·오디오·자막과 재생 정보를 하나의 파일에 담는 형식 |
| 하는 일 | 데이터 압축·복원                                                                                                               | 여러 데이터의 재생 순서와 동기화 관리                  |
| 예      | 비디오: [H.264](glossary:h264), [H.265](glossary:h265), [AV1](glossary:av1) / 오디오: [AAC](glossary:aac), [MP3](glossary:mp3) | [MP4](glossary:mp4), MOV, MKV, WebM                    |

- [MP4](glossary:mp4) 파일이 만들어지는 과정
  1. 영상 데이터 → [H.264](glossary:h264)로 압축
  2. 오디오 데이터 → [AAC](glossary:aac)로 압축
  3. 자막·재생 시간 정보
  4. 1~3을 [MP4](glossary:mp4) [Container format](glossary:container-format)에 담음 → `video.mp4`
- 확장자가 같은 [MP4](glossary:mp4)여도 안에 든 [Codec](glossary:codec)은 다를수있다
  - `video1.mp4` → [H.264](glossary:h264) 영상 + [AAC](glossary:aac) 오디오
  - `video2.mp4` → [H.265](glossary:h265) 영상 + [AAC](glossary:aac) 오디오

## 2.3.5 오디오의 표현

- 오디오는 아날로그여서 디지털로 변환하는과정이 필요함

### 변환 4단계

1. 변환: 마이크가 소리를 연속적인 전기 신호로 바꿈
2. [Sampling](glossary:sampling): 일정한 시간 간격으로 신호의 크기를 잼
3. [Quantization](glossary:quantization): 잰 값을 정해진 구간의 숫자로 변경
4. 부호화 위 숫자를 [Bit](glossary:bit) 패턴으로 저장

### 품질과 데이터 양을 정하는 3가지

1. [Sampling rate](glossary:sampling-rate): 1초에 소리를 몇번 재는지(단위: Hz)
2. [Bit depth](glossary:bit-depth): 한 번 잰 값을 몇 [Bit](glossary:bit)로 표현 하는지
3. 채널: 독립적으로 저장하는 소리의 수

셋 다 커질수록 품질, 데이터 양이 늘음

압축 전 데이터양 = [Sampling rate](glossary:sampling-rate) × [Bit depth](glossary:bit-depth) × 채널 수 × 재생 시간(초)

### 오디오 파일 vs MIDI

- 오디오 파일은 녹음이고 [MIDI](glossary:midi)는 악보이다.

| 구분        | 오디오 파일             | [MIDI](glossary:midi) 파일             |
| ----------- | ----------------------- | -------------------------------------- |
| 저장 내용   | 실제 소리를 측정한 값   | 음표·악기·세기·시간 등의 연주 명령     |
| 재생 방법   | 저장된 소리를 복원      | 전자 악기가 명령에 따라 소리를 생성    |
| 재생 결과   | 녹음된 소리를 재생      | 재생 장치와 음원에 따라 달라질 수 있음 |
| 데이터양    | 상대적으로 큼           | 상대적으로 작음                        |
| 적합한 용도 | 음성·음악·환경음 녹음   | 전자음악 작곡·악기 연주 제어           |
| 대표 확장자 | .wav, .flac, .mp3, .m4a | .mid                                   |

### PCM과 저장 방식

- [PCM](glossary:pcm): 소리를 일정한 간격으로 재서 숫자로 표현한느 방식. 변환 4단계를 거친 데이터가 [PCM](glossary:pcm) 데이터
  | 저장 방식 | 압축 | 파일 | 주요 특징 |
  | --------- | ----------- | ---------- | ----------------------------------------- |
  | [PCM](glossary:pcm) | 주로 비압축 | [WAV](glossary:wav) (.wav) | 측정값을 주로 그대로 저장하여 용량이 큼 |
  | [FLAC](glossary:flac) | [Lossless compression](glossary:lossless-compression) | .flac | 파일 크기를 줄이면서 원본을 정확히 복원 |
  | [MP3](glossary:mp3) | [Lossy compression](glossary:lossy-compression) | .mp3 | 일부 정보를 줄여 파일 크기를 크게 감소 |
  | [AAC](glossary:aac) | [Lossy compression](glossary:lossy-compression) | .m4a, .mp4 | 효율적인 압축으로 동영상·스트리밍에 활용 |
- [PCM](glossary:pcm)은 파일 형식이나 압축 [Codec](glossary:codec)이 아니라 디지털 오디오 데이터의 표현 방식

# 2.4 숫자의 표현

## 2.4.1 2진수의 표현과 계산

- 2진수 → 10진수
- 10진수 → 2진수
- 2진수 덧셈

## 2.4.2 정수의 표현

### 2의 보수

- 요즘 컴퓨터가 부호 있는 정수를 표현하는 대표 방식
- [MSB](glossary:msb)가 0이면 0 또는 양수, 1이면 음수
- 음수 만드는 법
  1. 모든 [Bit](glossary:bit) 뒤집기(0 ↔ 1)
  2. 1을 더하기
  3. 원래 [Bit](glossary:bit) 수에 맞추기
  4. 표현 범위: 2^n개 0이 양수쪽에 들어가기에 음수쪽이 하나 더 많다.

  ```
  4비트로 −3 만들기
  3       0011
  뒤집기   1100
  +1      1101   →  −3 = 1101₂
  ```

  - 넘친 [Bit](glossary:bit)는 버린다
  - **연산 했을 떄 10진수 값이 음수면 뒤집고 +1 한번 더하고 [msb](glossary:msb)에 1 달아서 음수 표시하기**

  ```
   −1 + −2           1 + −2           −1 + 2
     1111              0001             1111
   + 1110            + 1110           + 0010
   ------            ------           ------
   (1)1101 = −3        1111 = −1      (1)0001 = 1
    ↑ 버림                              ↑ 버림
  ```

  - [Overflow](glossary:overflow): 계산 결과가 표현 범위를 벗어나는 것

  ```
  4비트에서 7 + 2
     0111  (+7)
   + 0010  (+2)
   ------
     1001  → −7로 해석됨 (9는 4비트 범위 −8~7 밖)
  ```

## 2.4.3 실수의 표현

- 2진 소수: 소수점 왼쪽은 2^-n
- [Normalization](glossary:normalization): 맨 앞자리가 1이 되도록 소수점을 옮기고, 옮긴 자리수만큼 2^n을 곱한다.
- [Fixed point](glossary:fixed-point): [Normalization](glossary:normalization) 하기 전 숫자.(단순하지만 표현범위가 좁음)
- [Floating point](glossary:floating-point): [Normalization](glossary:normalization) 한 후 숫자.(아주 큰 수 표현 가능하지만 오차 발생 가능)
- 예) 5.75 ([Fixed point](glossary:fixed-point)는 정수 4비트 + 소수 4비트로 가정)

  | 구분                                      | 5.75의 표현  | 소수점 위치           |
  | ----------------------------------------- | ------------ | --------------------- |
  | [Fixed point](glossary:fixed-point)       | 0101.1100₂   | 미리 정한 위치에 고정 |
  | [Floating point](glossary:floating-point) | 1.0111₂ × 2² | 지수에 따라 결정      |
  - [Fixed point](glossary:fixed-point) 표현 범위: 0 ~ 15.9375 (1111.1111₂), 간격 2⁻⁴ = 0.0625 → 16 이상이나 0.03처럼 간격에 안 맞는 값은 정확히 표현 불가
  - [Floating point](glossary:floating-point): 같은 유효숫자도 지수를 바꿔 소수점 이동 (1.0111₂ × 2² = 5.75, × 2¹⁰ = 1472, × 2⁻⁶ = 0.0224609375)

### 초과 표기법(바이어스)

- 지수가 음수일 수 있어서 실제 지수에 일정한 값([Exponent bias](glossary:exponent-bias))를 더해서 저장.
- 지수부에 부호 [Bit](glossary:bit)를 따로 안둔다.
- 저장지수 = 실제지수 + [Exponent bias](glossary:exponent-bias)
- float의 [Exponent bias](glossary:exponent-bias)는 127

  | 실제 지수 | 계산     | 저장 지수 | 8비트 표현 |
  | --------- | -------- | --------- | ---------- |
  | −2        | −2 + 127 | 125       | 01111101   |
  | 0         | 0 + 127  | 127       | 01111111   |
  | 2         | 2 + 127  | 129       | 10000001   |

### IEEE 754

| 구분          | 전체   | 부호  | 지수부 | 가수부(소수 부분) | 지수 [Exponent bias](glossary:exponent-bias) |
| ------------- | ------ | ----- | ------ | ----------------- | -------------------------------------------- |
| 단정도 float  | 32비트 | 1비트 | 8비트  | 23비트            | 127                                          |
| 배정도 double | 64비트 | 1비트 | 11비트 | 52비트            | 1,023                                        |

- [Normalization](glossary:normalization)한 수에서 맨 앞의 1은 저장하지 않음.
- double은 가수부가 길어서 더 정밀
- 지수부 특수 패턴
  - 지수부가 전부 0이면 0이거나 0에 아주 가까운 수
  - 지수부가 전부 1이면 무한대거나 [NaN](glossary:nan)
  - 따라서 정상적인 수는 그 사이 값만 사용(float의 경우 -126~127)

### float로 저장하는 4단계

- ex) 101.11₂를 32비트 float로

1. [Normalization](glossary:normalization) (1.0111₂ × 2²)
2. 부호비트 (양수이므로 0)
3. 지수부 (2+ 127 = 129 = 10000001)
4. 가수부 (첫째 자리 1을 빼고 01110000000000000000000)

- 최종: 0 10000001 01110000000000000000000
-      부호  지수(8)        [Mantissa](glossary:mantissa)(23)

* [Rounding error](glossary:rounding-error) 있을 시 가장 가까운 값으로 반올림해서 저장
