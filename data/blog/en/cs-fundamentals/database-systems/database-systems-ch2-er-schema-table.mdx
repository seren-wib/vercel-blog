# ER, Schema and Tables Through One COMPANY

The same COMPANY drawn as three layers. ① [ER](glossary:er-diagram) (ch2) → ② the converted [schema](glossary:relational-schema) (ch3 3.4) → ③ tables filled with data (ch3 3.1). The tables below only point to where each concept is in the three figures. The exam's "draw the RDB" = look at ① and draw ②

| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Rectangle / double rectangle                | [entity type](glossary:entity-type) / [weak entity type](glossary:weak-entity-type)                                                                                                                                                                                                                                                                                                                                                                                                  |
| Oval / underline / dashed underline         | [attribute](glossary:attribute) / key / [partial key](glossary:partial-key)                                                                                                                                                                                                                                                                                                                                                                                                          |
| Double oval / dashed oval / branching ovals | multivalued / derived / composite                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Diamond / double diamond                    | [relationship](glossary:relationship-type) / [identifying relationship](glossary:identifying-relationship). A double diamond is the [relationship](glossary:relationship-type) that ties a [weak entity](glossary:weak-entity-type) (double rectangle) to its [owner](glossary:owner-entity-type) [entity](glossary:entity). Without it you can't tell whose [weak entity](glossary:weak-entity-type) it is. In COMPANY there is one: DEPENDENTS_OF (employee–dependent) (section 6) |

## 2. Relational schema

![COMPANY relational schema: 6 tables, PKs underlined, FK arrows](/static/images/database-systems-ch2-er-schema-table/company-2-schema.svg)

- 6 tables = 4 rectangles + 1 [M:N](glossary:cardinality) diamond (WORKS_ON) + 1 double oval (DEPT_LOCATIONS)
- Every arrow is [FK](glossary:foreign-key) → [PK](glossary:primary-key). 7 arrows = 2 [1:N](glossary:cardinality) diamonds (Dno, Dnum) + 1 [1:1](glossary:cardinality) diamond (Mgr_ssn) + 1 [recursive](glossary:recursive-relationship) (Super_ssn) + 2 from [M:N](glossary:cardinality) (Essn, Pno) + 1 double diamond (DEPENDENT.Essn) + 1 double oval (Dnumber)
- The double diamond (DEPENDENTS_OF) gets no table of its own; it just adds the [owner](glossary:owner-entity-type)'s [PK](glossary:primary-key) (Essn) to the [weak entity](glossary:weak-entity-type) DEPENDENT. That Essn is an [FK](glossary:foreign-key) and also part of DEPENDENT's [PK](glossary:primary-key)
- Watch the renamed columns: Number → Dnumber/Pnumber, Name → Dname/Pname, EMPLOYEE.Ssn taken elsewhere becomes Essn, Mgr_ssn, Super_ssn

## 3. Tables (relation state)

![The 6 COMPANY tables filled with tuples](/static/images/database-systems-ch2-er-schema-table/company-3-tables.svg)

- Header row = [schema](glossary:relational-schema), the rows under it = state. Adding or deleting rows leaves the header unchanged
- A value in an [FK](glossary:foreign-key) cell must be a value that exists in the other table's [PK](glossary:primary-key), or [NULL](glossary:null). The five lines at the bottom right of the figure judge insert and delete violations

In [ER](glossary:er-diagram), an [entity](glossary:entity) without its [key attribute](glossary:key) can't be singled out                                                                                                                                                                                                                                  | ![](/static/images/database-systems-ch2-er-schema-table/sym/er-key.svg)                                                                                       | Underlined column                                                             | ![](/static/images/database-systems-ch2-er-schema-table/sym/tb-entity-integrity.svg) |
| **Referential integrity**                                          | An [FK](glossary:foreign-key) cell's value must actually exist in the other table's [PK](glossary:primary-key), or be [NULL](glossary:null). Dno = 7 with no department 7 is a violation. In [ER](glossary:er-diagram), the [entity](glossary:entity) across the diamond must actually exist                                                                                                                                                                                   | ![](/static/images/database-systems-ch2-er-schema-table/sym/er-1n.svg)                                                                                        | That value must exist at the arrow's end                                      | ![](/static/images/database-systems-ch2-er-schema-table/sym/tb-referential.svg)      |
| **Violation checks**                                               | Insert checks all three: Key, Entity and Referential. Delete only checks whether other rows point at the deleted row through an [FK](glossary:foreign-key).
