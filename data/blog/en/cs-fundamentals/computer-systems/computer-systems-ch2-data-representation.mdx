# 2.1 Bits and bit storage

Represent → process → store → read

**A computer represents information as [bit](glossary:bit) patterns, processes it with [logic circuits](glossary:logic-circuit), and stores it in storage circuits**

## 2.1.1 The smallest unit of information

1. [bit](glossary:bit): smallest unit (0, 1)
2. 1 [byte](glossary:byte) = 8 [bits](glossary:bit)
3. [bit](glossary:bit) pattern: something like 01010100
   - The same [bit](glossary:bit) pattern can mean different things depending on how it is interpreted.

## 2.1.2 Circuits that process bits

1. [Boolean operations](glossary:boolean-operation)
   1. AND: true only if both are true
   2. OR: true if either one is true
   3. [XOR](glossary:xor): true only if they differ
   4. NOT: just the opposite

2. [Logic gates](glossary:logic-gate)

- Circuits that implement [Boolean operations](glossary:boolean-operation) in hardware

![Logic gate symbols and truth tables](/static/images/computer-systems-ch2-data-representation/logic-gates.svg)

3. [Logic circuits](glossary:logic-circuit)
   - Circuits made by connecting several gates
   - Compute values
   - (A AND NOT B) OR (NOT A AND B) = [XOR](glossary:xor)

4. [CPU](glossary:cpu) components
   1. [control unit](glossary:control-unit)
   2. [ALU](glossary:alu) (arithmetic logic unit): operations happen here
   3. [registers](glossary:register)
   4. [cache](glossary:cache)

   ![Logic gate < logic circuit < CPU](/static/images/computer-systems-ch2-data-representation/gate-circuit-cpu.svg)

## 2.1.3 Circuits that store bits

1. [Flip-flop](glossary:flip-flop)
   - D (input) / [Clock](glossary:clock-signal) (signal telling it to store) / Q (output)
   - Stores a value (1 [bit](glossary:bit) only)
   - D is stored into Q only when the [clock](glossary:clock-signal) arrives; if D changes in between, Q stays the same
   - The stored value is kept until it is changed

2. [Register](glossary:register)
   - Stores multiple [bits](glossary:bit)
   - A bundle of several [flip-flops](glossary:flip-flop) (8 [flip-flops](glossary:flip-flop) = 8-[bit](glossary:bit) [register](glossary:register))

## 2.1.4 Writing bit patterns compactly

1. [Hexadecimal](glossary:hexadecimal) notation
   - Binary is hard for people to read, so values are shown this way. Mainly memory [addresses](glossary:memory-address), [register](glossary:register) values, color [hex](glossary:hexadecimal) values.
   - Stored in the computer as binary
   - 1 [hex](glossary:hexadecimal) digit = 4 [bits](glossary:bit)
   - Split the [bits](glossary:bit) into groups of 4 from the right
   - Symbols are 0–9 and A–F, written with a 0x prefix.

# 2.2 Storage devices

## 2.2.1 Storing information in use

1. [Main memory](glossary:main-memory)
   - Stores the instructions of the program to run and the data to process
   - Slow and large

2. [Registers](glossary:register)
   - What needs to be processed quickly right now
   - Fast and small

3. [Memory cell](glossary:memory-cell)
   - [Cell](glossary:memory-cell): one slot of [main memory](glossary:main-memory) divided into fixed-size units (1 [byte](glossary:byte))
   - [Address](glossary:memory-address): the number attached to each [cell](glossary:memory-cell)

4. [Memory read/write](/en/blog/cs-fundamentals/computer-systems/computer-systems-ch3-computer-organization/#311-computer-architecture)

5. [RAM](glossary:ram) & [ROM](glossary:rom)
   - [ROM](glossary:rom) doesn't mean something like an [SSD](glossary:ssd) or [HDD](glossary:hdd); it refers to a very small memory on the motherboard

   | Category                                                  | [RAM](glossary:ram)                                      | [ROM](glossary:rom)                                      |
   | --------------------------------------------------------- | -------------------------------------------------------- | -------------------------------------------------------- |
   | Name                                                      | Random Access Memory                                     | Read-Only Memory                                         |
   | Access any location by [address](glossary:memory-address) | Yes                                                      | Yes                                                      |
   | Read                                                      | Yes                                                      | Yes                                                      |
   | Write                                                     | Freely                                                   | Impossible or possible via a separate procedure, by type |
   | When power is off                                         | Contents are lost ([volatile](glossary:volatile-memory)) | Contents are kept (non-volatile)                         |
   | Main contents                                             | Running programs and data                                | Basic programs needed for booting and initialization     |

6. Memory capacity
   - Grows in steps of 2^10

## 2.2.2 Long-term data storage

1. [Secondary storage](glossary:secondary-storage)
   - Cheap, large, slow and non-volatile
   - When a program runs: [secondary storage](glossary:secondary-storage) -> [main memory](glossary:main-memory) -> [registers](glossary:register) -> [CPU](glossary:cpu)
   1. [HDD](glossary:hdd): stores magnetically
   2. [SSD](glossary:ssd), USB: stores with semiconductors
   3. CD, DVD: stores optically

### HDD

- [Platter](glossary:platter): the disk
- [Track](glossary:track): a path inscribed on the disk
- [Sector](glossary:sector): a small area that a [track](glossary:track) is divided into
- Head: the pin-like thing that reads
- [Seek time](glossary:seek-time): time for the head to move to the [track](glossary:track)
- [Rotational latency](glossary:rotational-latency): time for the disk to spin so the [sector](glossary:sector) comes to the desired spot
- Transfer time: time to actually read or write

### Flash memory

- Non-volatile semiconductor memory
- [NAND](glossary:nand-flash) type; represents 0 and 1 by putting in and removing charge
- Small, light and shock-resistant
- Limited number of writes
- Stored (charged): 0, not stored: 1 (it's reversed)

### SSD

- [NAND](glossary:nand-flash) flash + controller
- Controller: manages reads, writes and storage locations, and manages lifespan
- Small, quiet, shock-resistant and power-efficient, but expensive with a limited write lifespan

1. [SATA](glossary:sata): interface used since the [HDD](glossary:hdd) days, slow.
2. [NVMe](glossary:nvme): communication protocol designed for [SSDs](glossary:ssd), connected via PCIe

- [M.2](glossary:m2): a size and connector-shape standard. Not every [M.2](glossary:m2) is [NVMe](glossary:nvme).

## 2.2.3 Choosing and using secondary storage

1. Choose the storage device that fits the purpose
2. Steps to use a storage device
   1. [Partition](glossary:partition): divide the storage space into [partitions](glossary:partition)
   2. Format: create a [file system](glossary:file-system) in that area
   - [File system](glossary:file-system): the structure and rules for storing and finding files and folders

# 2.3 Representing information with bit patterns

## 2.3.1 Representing characters

1. [Character code](glossary:character-code)
   - Characters are stored as numbers
   - The sender and receiver must use the same [character code](glossary:character-code)
   - ex) [ASCII](glossary:ascii), [UNICODE](glossary:unicode)
2. [ASCII](glossary:ascii)
   - Stores 2^7 values (7 [bits](glossary:bit))
   - Computers add one leading 0 and store it as 1 [byte](glossary:byte).
   - Can't represent things like Korean (Hangul)
3. [UNICODE](glossary:unicode)

   | Category                         | [Unicode](glossary:unicode)                                                                            | [UTF-8](glossary:utf-8)                                                                   |
   | -------------------------------- | ------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------- |
   | What it does                     | Assigns a unique number ([code point](glossary:code-point)) to every character and symbol in the world | Converts [code points](glossary:code-point) into actual [bytes](glossary:byte) (encoding) |
   | Notation                         | U+ followed by [hex](glossary:hexadecimal) (A → U+0041, 가 → U+AC00)                                   | [Byte](glossary:byte) sequence (가 → 11101010 10110000 10000000)                          |
   | Number of [bytes](glossary:byte) | Not defined                                                                                            | 1–4 [bytes](glossary:byte) depending on the [code point](glossary:code-point)             |

- English is 1 [byte](glossary:byte), same as [ASCII](glossary:ascii). Compatible with old English files.
- A Korean character usually takes 3 [bytes](glossary:byte). This [byte](glossary:byte) conversion happens in [UTF-8](glossary:utf-8)

## 2.3.2 Representing numbers

| Category        | String "25"                                  | Integer 25                                      |
| --------------- | -------------------------------------------- | ----------------------------------------------- |
| Composition     | Two characters, '2' and '5'                  | A single number                                 |
| How it's stored | Each character stored separately by its code | The whole number converted to binary and stored |
| Storage example | 00110010 00110101 ('2' = 50, '5' = 53)       | 00011001 (8 [bits](glossary:bit))               |
| Arithmetic      | Not possible as is                           | Possible                                        |
| Use             | Display, names, phone numbers                | Calculations like addition and multiplication   |

### Integers

- Positive numbers are represented directly in binary
- Negative numbers are usually represented in [two's complement](glossary:twos-complement)
- Once the number of [bits](glossary:bit) is fixed, the range is fixed too
- 8-[bit](glossary:bit) range
  - Unsigned: 0~255
  - Signed: -128~127
  - [Overflow](glossary:overflow): when a result goes outside the representable range (going past 255 for unsigned, or past -129 for negatives)

### Real numbers

- [Floating point](glossary:floating-point): a way to represent very large or very small numbers, stored in three parts: sign, exponent, and [mantissa](glossary:mantissa) ([significand](glossary:mantissa)). [IEEE 754](glossary:ieee-754) is the standard (float, double)
- [Representation error](glossary:rounding-error): error from the limited number of [bits](glossary:bit). The closest value is stored

## 2.3.3 Representing images

Main division: [raster](glossary:raster-image) VS [vector](glossary:vector-image)

### Raster images

1. Represent an image as a grid of [pixels](glossary:pixel)
2. A [pixel](glossary:pixel) is the smallest unit of a digital image
3. Each [pixel](glossary:pixel)'s position and color value are stored as [bits](glossary:bit)
4. Suited to images with complex color changes, like photos

### Pixels

- Colors are made by mixing [RGB](glossary:rgb) brightness (8 [bits](glossary:bit) per component)
- Size of one [pixel](glossary:pixel) = 8\*3 = 24 [bits](glossary:bit), can represent 2^24 colors
- Uncompressed data size of a 1920*1080 image = 1920*1080\*24 = 49.8Mb = 6.2MB
- [Resolution](glossary:resolution): width*height [pixel](glossary:pixel) count of an image, ex) 1920*1080
- [Pixelation](glossary:pixelation): [pixel](glossary:pixel) edges becoming visible when a [raster](glossary:raster-image) image is enlarged

### Vector images

- Represent points, lines, curves and shapes as mathematical information
- Store how to draw the shapes, not an array of [pixels](glossary:pixel)
- Edges stay intact when enlarged or shrunk
- Good for logos

### Raster vs vector

| Category       | [Raster](glossary:raster-image) image                                                  | [Vector](glossary:vector-image) image |
| -------------- | -------------------------------------------------------------------------------------- | ------------------------------------- |
| Representation | [Pixel](glossary:pixel) color values                                                   | Point, line, curve, shape info        |
| Enlarging      | [Pixels](glossary:pixel) may show                                                      | Edges stay sharp                      |
| Suited for     | Photos                                                                                 | Logos, icons, shapes                  |
| Common formats | [JPEG](glossary:jpeg), [PNG](glossary:png), [GIF](glossary:gif), [WebP](glossary:webp) | [SVG](glossary:svg)                   |

### Image compression

- [Lossless](glossary:lossless-compression) compression: no information loss (good for screenshots and images with sharp edges)
- [Lossy](glossary:lossy-compression) compression: some information loss (good for photos)

### Common image file formats

| Format/extension                    | Image type                      | Compression/representation features                                                                                    | Main use                           |
| ----------------------------------- | ------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| [JPEG](glossary:jpeg) (.jpg, .jpeg) | [Raster](glossary:raster-image) | [Lossy](glossary:lossy-compression), no transparency                                                                   | Photos                             |
| [PNG](glossary:png) (.png)          | [Raster](glossary:raster-image) | [Lossless](glossary:lossless-compression), supports transparency                                                       | Drawings, screenshots of documents |
| [GIF](glossary:gif) (.gif)          | [Raster](glossary:raster-image) | [Lossless](glossary:lossless-compression), up to 256 colors, supports animation                                        | Simple animations                  |
| [WebP](glossary:webp) (.webp)       | [Raster](glossary:raster-image) | [Lossy](glossary:lossy-compression) and [lossless](glossary:lossless-compression), supports transparency and animation | Web images                         |
| [SVG](glossary:svg) (.svg)          | [Vector](glossary:vector-image) | Stores shape information as text                                                                                       | Logos, icons, shapes               |

### Compression using data characteristics

| Method                                                                                    | Principle                                                                  | Example                          | Effective when                                                                                     |
| ----------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- | -------------------------------- | -------------------------------------------------------------------------------------------------- |
| [Run-length encoding](glossary:run-length-encoding) ([RLE](glossary:run-length-encoding)) | Consecutive identical values are represented as the value and repeat count | 0,0,0,0,0,1,1,1 → (0,5)(1,3)     | Simple images with repeated identical colors                                                       |
| [Huffman code](glossary:huffman-coding)                                                   | Short codes for frequent values, long codes for rare values                | geese: e=0, g=10, s=11 → 1000110 | Large differences in value frequency                                                               |
| [Difference encoding](glossary:difference-encoding)                                       | Store the difference from the previous value instead of the value itself   | 23,24,25,25 → 23,1,1,0           | Adjacent [pixels](glossary:pixel) have similar color values (also used in audio/video compression) |

## 2.3.4 Representing video

- Video = a sequence of images
- [Frame](glossary:frame): one still image
- Video + audio
- [Frame rate](glossary:frame-rate): number of [frames](glossary:frame) shown per second, unit: fps; 30 [frames](glossary:frame) per second is 30fps
- Uncompressed data size = horizontal [pixels](glossary:pixel) × vertical [pixels](glossary:pixel) × [bits](glossary:bit) per [pixel](glossary:pixel) × [frames](glossary:frame) per second × duration (seconds)

### Video compression

1. Spatial redundancy: compress repeated neighboring colors within a single [frame](glossary:frame)
2. Temporal redundancy: store mainly the parts that changed from the previous [frame](glossary:frame)

### Codecs and containers

| Category     | [Codec](glossary:codec)                                                                                                      | [Container](glossary:container-format)                                  |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Definition   | Rules for representing, compressing and restoring video/audio                                                                | Format that holds video, audio, subtitles and playback info in one file |
| What it does | Compresses and restores data                                                                                                 | Manages playback order and synchronization of multiple data streams     |
| Examples     | Video: [H.264](glossary:h264), [H.265](glossary:h265), [AV1](glossary:av1) / Audio: [AAC](glossary:aac), [MP3](glossary:mp3) | [MP4](glossary:mp4), MOV, MKV, WebM                                     |

- How an [MP4](glossary:mp4) file is made
  1. Video data → compressed with [H.264](glossary:h264)
  2. Audio data → compressed with [AAC](glossary:aac)
  3. Subtitle and timing information
  4. Put 1–3 into an [MP4](glossary:mp4) [container](glossary:container-format) → `video.mp4`
- Even with the same [MP4](glossary:mp4) extension, the [codecs](glossary:codec) inside can differ
  - `video1.mp4` → [H.264](glossary:h264) video + [AAC](glossary:aac) audio
  - `video2.mp4` → [H.265](glossary:h265) video + [AAC](glossary:aac) audio

## 2.3.5 Representing audio

- Audio is analog, so it needs to be converted to digital

### 4 conversion steps

1. Transduction: a microphone turns sound into a continuous electrical signal
2. [Sampling](glossary:sampling): measure the signal's amplitude at fixed time intervals
3. [Quantization](glossary:quantization): map the measured values to numbers in fixed intervals
4. Encoding: store those numbers as [bit](glossary:bit) patterns

### 3 factors that set quality and data size

1. [Sampling frequency](glossary:sampling-rate): how many times per second the sound is measured (unit: Hz)
2. [Bit depth](glossary:bit-depth): how many [bits](glossary:bit) represent each measured value
3. Channels: number of independently stored sounds

The larger all three are, the higher the quality and the data size

Uncompressed data size = [sampling frequency](glossary:sampling-rate) × [bit depth](glossary:bit-depth) × number of channels × duration (seconds)

### Audio file vs MIDI

- An audio file is a recording; [MIDI](glossary:midi) is sheet music.

| Category          | Audio file                            | [MIDI](glossary:midi) file                                           |
| ----------------- | ------------------------------------- | -------------------------------------------------------------------- |
| Stored content    | Measured values of actual sound       | Performance commands such as notes, instruments, velocity and timing |
| Playback          | Restores the stored sound             | An electronic instrument generates sound from the commands           |
| Playback result   | Plays the recorded sound              | Can vary by playback device and sound source                         |
| Data size         | Relatively large                      | Relatively small                                                     |
| Suited for        | Recording voice, music, ambient sound | Electronic music composition, controlling instruments                |
| Common extensions | .wav, .flac, .mp3, .m4a               | .mid                                                                 |

### PCM and storage methods

- [PCM](glossary:pcm): a method that measures sound at regular intervals and represents it as numbers. Data that has gone through the 4 conversion steps is [PCM](glossary:pcm) data
  | Storage method | Compression | File | Main features |
  | --------- | ----------- | ---------- | ----------------------------------------- |
  | [PCM](glossary:pcm) | Mostly uncompressed | [WAV](glossary:wav) (.wav) | Mostly stores measured values as is, so files are large |
  | [FLAC](glossary:flac) | [Lossless](glossary:lossless-compression) | .flac | Reduces file size while restoring the original exactly |
  | [MP3](glossary:mp3) | [Lossy](glossary:lossy-compression) | .mp3 | Drops some information to greatly reduce file size |
  | [AAC](glossary:aac) | [Lossy](glossary:lossy-compression) | .m4a, .mp4 | Efficient compression, used for video and streaming |
- [PCM](glossary:pcm) is not a file format or compression [codec](glossary:codec) but a way of representing digital audio data

# 2.4 Representing numbers

## 2.4.1 Binary representation and arithmetic

- Binary → decimal
- Decimal → binary
- Binary addition

## 2.4.2 Representing integers

### Two's complement

- The standard way modern computers represent signed integers
- If the [MSB](glossary:msb) is 0, the number is 0 or positive; if 1, negative
- How to make a negative number
  1. Flip all [bits](glossary:bit) (0 ↔ 1)
  2. Add 1
  3. Fit to the original number of [bits](glossary:bit)
  4. Range: of the 2^n values, 0 falls on the positive side, so the negative side has one more.

  ```
  Making −3 in 4 bits
  3       0011
  flip    1100
  +1      1101   →  −3 = 1101₂
  ```

  - Overflowing [bits](glossary:bit) are discarded
  - **If the decimal value of a result is negative, flip it, add 1 again, and attach 1 at the [MSB](glossary:msb) to mark it negative**

  ```
   −1 + −2           1 + −2           −1 + 2
     1111              0001             1111
   + 1110            + 1110           + 0010
   ------            ------           ------
   (1)1101 = −3        1111 = −1      (1)0001 = 1
    ↑ discarded                         ↑ discarded
  ```

  - [Overflow](glossary:overflow): when a result goes outside the representable range

  ```
  7 + 2 in 4 bits
     0111  (+7)
   + 0010  (+2)
   ------
     1001  → interpreted as −7 (9 is outside the 4-bit range −8~7)
  ```

## 2.4.3 Representing real numbers

- Binary fractions: places to the left of the point are 2^-n
- [Normalization](glossary:normalization): move the point so the leading digit is 1, and multiply by 2^n for the number of places moved.
- [Fixed point](glossary:fixed-point): the number before [normalization](glossary:normalization). (Simple but narrow range)
- [Floating point](glossary:floating-point): the number after [normalization](glossary:normalization). (Can represent very large numbers but errors can occur)
- ex) 5.75 (assume [fixed point](glossary:fixed-point) uses 4 integer [bits](glossary:bit) + 4 fraction [bits](glossary:bit))

  | Category                                  | Representation of 5.75 | Point position          |
  | ----------------------------------------- | ---------------------- | ----------------------- |
  | [Fixed point](glossary:fixed-point)       | 0101.1100₂             | Fixed at a preset place |
  | [Floating point](glossary:floating-point) | 1.0111₂ × 2²           | Set by the exponent     |
  - [Fixed-point](glossary:fixed-point) range: 0 ~ 15.9375 (1111.1111₂), step 2⁻⁴ = 0.0625 → values of 16 or more, or values like 0.03 that don't fit the step, can't be represented exactly
  - [Floating point](glossary:floating-point): the same significant digits move the point by changing the exponent (1.0111₂ × 2² = 5.75, × 2¹⁰ = 1472, × 2⁻⁶ = 0.0224609375)

### Excess notation (bias)

- Since the exponent can be negative, a fixed value ([bias](glossary:exponent-bias)) is added to the actual exponent before storing.
- No separate sign [bit](glossary:bit) for the exponent field.
- Stored exponent = actual exponent + [bias](glossary:exponent-bias)
- The [bias](glossary:exponent-bias) for float is 127

  | Actual exponent | Calculation | Stored exponent | 8-[bit](glossary:bit) representation |
  | --------------- | ----------- | --------------- | ------------------------------------ |
  | −2              | −2 + 127    | 125             | 01111101                             |
  | 0               | 0 + 127     | 127             | 01111111                             |
  | 2               | 2 + 127     | 129             | 10000001                             |

### IEEE 754

| Category                | Total                   | Sign                  | Exponent                | [Mantissa](glossary:mantissa) ([fraction](glossary:mantissa) part) | Exponent [bias](glossary:exponent-bias) |
| ----------------------- | ----------------------- | --------------------- | ----------------------- | ------------------------------------------------------------------ | --------------------------------------- |
| Single-precision float  | 32 [bits](glossary:bit) | 1 [bit](glossary:bit) | 8 [bits](glossary:bit)  | 23 [bits](glossary:bit)                                            | 127                                     |
| Double-precision double | 64 [bits](glossary:bit) | 1 [bit](glossary:bit) | 11 [bits](glossary:bit) | 52 [bits](glossary:bit)                                            | 1,023                                   |

- The leading 1 of a [normalized](glossary:normalization) number is not stored.
- double has a longer [mantissa](glossary:mantissa), so it is more precise
- Special exponent patterns
  - If the exponent field is all 0s, the number is 0 or very close to 0
  - If the exponent field is all 1s, it is infinity or [NaN](glossary:nan)
  - So normal numbers only use the values in between (-126~127 for float)

### 4 steps to store as a float

- ex) 101.11₂ as a 32-[bit](glossary:bit) float

1. Normalize (1.0111₂ × 2²)
2. Sign [bit](glossary:bit) (positive, so 0)
3. Exponent (2+ 127 = 129 = 10000001)
4. [Mantissa](glossary:mantissa) (drop the leading 1: 01110000000000000000000)

- Final: 0 10000001 01110000000000000000000
-      sign  exponent(8)    [mantissa](glossary:mantissa)(23)

* If there is [representation error](glossary:rounding-error), round to the nearest value and store
