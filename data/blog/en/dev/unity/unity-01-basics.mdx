## 0. Introduction

When I first opened [Unity](glossary:unity), I could not see where folders, screens and code meet, so I wrote down the basic structure. Along the way an [Input System](glossary:input-system) setting blocked my movement code, so the fix is here too.

In restaurant terms, one open dining hall is the space opened at once, and each seat in it is something that exists there, guest or staff. You attach duties to each seat so it does work, and you save frequently used seat setups as cards. The instructions for those duties are written separately. The hall is a [Scene](glossary:scene), a seat is a [GameObject](glossary:gameobject), a duty is a [Component](glossary:component), a saved card is a [Prefab](glossary:prefab), and the instructions are a [C#](glossary:c) Script. This post covers the folder structure, [Scene](glossary:scene) and [GameObject](glossary:gameobject), [Component](glossary:component) and Script, how to make backgrounds, and then fixes the Input error.

## 1. Project Folder Structure

The folders you work with in a [Unity](glossary:unity) project are inside `Assets`.

```
Assets/
├─ Scenes/
├─ Scripts/
├─ Sprites/
└─ Prefabs/
```

- `Scenes`: [Scene](glossary:scene) files. One `.unity` file is one [Scene](glossary:scene).
- `Scripts`: [C#](glossary:c) code files. A file does not run by itself; it runs only after being attached to a [GameObject](glossary:gameobject) as a [Component](glossary:component) in the [Unity Editor](glossary:unity-editor).
- `Sprites`: 2D images, [Sprite](glossary:sprite). Just an image, with no movement, collision or health. To show it on screen, the [GameObject](glossary:gameobject) needs a [SpriteRenderer](glossary:spriterenderer).
- `Prefabs`: a [GameObject](glossary:gameobject)'s configuration saved as a reusable source file. You create one by dragging the object into the `Prefabs` folder.

A [Prefab](glossary:prefab) does not merge scripts and images into one. It stores the list of attached [Components](glossary:component), each setting, and the referenced [Assets](glossary:asset) (`player.png`, `PlayerMove.cs`).

## 2. Project, Scene and GameObject

The hierarchy is `Project` > `Scene` > `GameObject` > `Component`. A Project is the whole game and holds `Assets/`, `Packages/` and `ProjectSettings/`.

A [Scene](glossary:scene) is a bundle of objects loaded at once. It is not a screen image but a file that stores which objects exist, where, and with which [Components](glossary:component). The [Camera](glossary:camera) in the [Scene](glossary:scene) captures the picture and shows it in the [Game View](glossary:game-view). A small game can put everything in one `SampleScene`; as it grows you split into `MainMenu`, `GameScene` and `GameOver`.

```
SampleScene
├─ Main Camera
├─ Player
├─ Enemy
└─ UI
```

An object like `Player` is not a standalone file; it is stored inside the [Scene](glossary:scene) file (`SampleScene.unity`). That is why [VS Code](glossary:vs-code) shows no `Player.cs`, only the code file `PlayerMove.cs`.

A [GameObject](glossary:gameobject) is an empty shell and [Components](glossary:component) provide the functionality. The name `Player` is not required (`Hero` works too); what matters is which [Components](glossary:component) are attached.

## 3. Component Combinations

An object is a combination of [Components](glossary:component). `Player` is configured like this.

| [Component](glossary:component)                                    | Role                                                                                  |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| [Transform](glossary:transform)                                    | Position, rotation, scale. Every [GameObject](glossary:gameobject) has one by default |
| @@spriterenderer@@[Sprite](glossary:sprite)Renderer@@/@@           | Displays a 2D image on screen                                                         |
| [Rigidbody2D](glossary:rigidbody2d)                                | Subjects it to the 2D [physics engine](glossary:2d-physics-engine)                    |
| Box[Collider](glossary:collider)2D ([Collider](glossary:collider)) | Collision area                                                                        |
| PlayerMove.cs                                                      | Movement code written by hand                                                         |

Building a feature always follows the same order: create a [GameObject](glossary:gameobject), attach [Components](glossary:component) and set values, write a [C#](glossary:c) Script, attach the Script to the [GameObject](glossary:gameobject), run and check.

## 4. How a Script Gets Attached

A class inheriting [MonoBehaviour](glossary:monobehaviour) attaches to a [GameObject](glossary:gameobject) as a [Component](glossary:component).

```csharp
using UnityEngine;

public class PlayerMove : MonoBehaviour
{
    public float speed = 5f;

    void Update()
    {
        float x = Input.GetAxisRaw("Horizontal");
        float y = Input.GetAxisRaw("Vertical");

        Vector3 direction = new Vector3(x, y, 0).normalized;
        transform.position += direction * speed * Time.deltaTime;
    }
}
```

`Update()` is called every [frame](glossary:frame). Multiplying by [Time.deltaTime](glossary:delta-time) keeps the speed the same regardless of frame rate. `transform` in the code is the [Transform](glossary:transform) of the [GameObject](glossary:gameobject) the Script is attached to. It does not look objects up by name but works relative to its own [GameObject](glossary:gameobject), so attaching the same Script to Enemy makes Enemy move.

## 5. Roles of Unity Editor and VS Code

The @@unity-editor@@[Unity](glossary:unity) Editor@@/@@ handles editing [Scenes](glossary:scene), creating [GameObjects](glossary:gameobject), adding [Components](glossary:component), configuring [Sprites](glossary:sprite), [Prefabs](glossary:prefab), [Colliders](glossary:collider) and [Cameras](glossary:camera), and test runs. [VS Code](glossary:vs-code) handles [C#](glossary:c) Scripts and game logic.

## 6. Backgrounds and Structures

Not everything becomes a [GameObject](glossary:gameobject).

| Kind                                         | Method                                                   |
| -------------------------------------------- | -------------------------------------------------------- |
| Things that move and act                     | [GameObject](glossary:gameobject) + Script               |
| Floors, walls, backgrounds placed repeatedly | [Tilemap](glossary:tilemap)                              |
| Large backgrounds that are only an image     | @@spriterenderer@@[Sprite](glossary:sprite)Renderer@@/@@ |

Making 1000 floor tiles into 1000 [GameObjects](glossary:gameobject) is wasteful, so under a `Grid` you put `Ground Tilemap` and `Wall Tilemap`, and one [Tilemap](glossary:tilemap) manages the tile data. For 500 walls that means one [Tilemap](glossary:tilemap) [GameObject](glossary:gameobject) instead of `Wall_001` to `Wall_500`.

## 7. Fixing the Input System Error

Running the code from section 4 failed on the line reading `UnityEngine.Input` with this error.

```text
You are trying to read Input using the UnityEngine.Input class, but you have switched active Input handling to Input System package in Player Settings.
```

The cause: the project was set to use only the [Input System](glossary:input-system) package, so the old [Input Manager](glossary:input-manager) API `UnityEngine.Input` was disabled. Setting Active Input Handling to `Both` in [Player Settings](glossary:player-settings) enables both.

1. Open `Edit` > `Project Settings` > `Player`.

   ![Player Settings screen](/static/images/unity-err/player.png)

2. Go to `Other Settings`.

   ![Other Settings screen](/static/images/unity-err/other-setting.png)

3. Change the `Active Input Handling` value to `Both`.

   ![Active Input Handling settings screen](/static/images/unity-err/active-input.png)

At first you only need to understand this loop: create a [GameObject](glossary:gameobject), attach [Components](glossary:component), write and attach a Script, reuse it as a [Prefab](glossary:prefab), test it in the [Scene](glossary:scene).
