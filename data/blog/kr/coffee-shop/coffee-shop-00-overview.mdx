> 소프트웨어공학 텀 프로젝트로 만든 커피 원두 쇼핑몰 `coffee-shop` 연재의 첫 글이다. 처음 보는 사람이 이 글 하나로 "무엇을, 왜, 어떻게"를 잡을 수 있게 썼다. 뒤의 여섯 편은 레포 커밋 이력을 파트별로 나눠 따라간다. 이 연재는 Claude Code가 커밋·PR·작업 기록을 읽고 썼다.

## 1. 무엇을 만들었나

원두를 파는 작은 온라인 쇼핑몰이다. 손님은 원두를 고르고, 용량과 분쇄도를 정해 장바구니에 담고, 주문하고, 결제하고, 배송을 조회한다. 관리자는 원두와 재고를 관리하고 주문을 준비·발송·취소 처리한다.

| 누가   | 할 수 있는 것                                                |
| ------ | ------------------------------------------------------------ |
| 비회원 | 원두 목록·상세 보기, 검색과 필터, 회원가입, 로그인           |
| 회원   | 장바구니, 주문, 결제, 주문 목록·취소, 배송 조회, 배송지 관리 |
| 관리자 | 원두·옵션·재고 등록과 수정, 판매 중지, 주문 상태 처리        |
| 운영자 | 서버 설치, 배포, 관리자 계정 생성, 백업 확인                 |

결제는 토스페이먼츠 **테스트 모드**다. 진짜 돈은 오가지 않는다. 레포는 공개 [seren-wib/coffee-shop](https://github.com/seren-wib/coffee-shop)이다.

## 2. 왜 이렇게 오래 문서를 썼나

과목이 소프트웨어공학이라 평가 대상이 코드보다 문서다. 강의계획서 기준으로 요구사항 명세서(SRS)와 설계 명세서(SDD)가 각각 10%다. 그래서 프로젝트 전반부 두 달은 거의 문서만 썼다.

건물로 치면 앞의 두 달은 설계도를 그리고 심사받는 기간이었고, 뒤의 열흘이 시공이었다.

## 3. 어떻게 만들었나

구조는 단순하다. 브라우저의 React 화면이 Django REST API를 부르고, 데이터는 SQLite 파일 하나에 있다. 운영 서버는 AWS EC2 한 대고, 앞에 Cloudflare가 선다.

![시스템 구성 다이어그램. 브라우저의 React SPA가 Cloudflare 프록시를 거쳐 EC2의 nginx로 들어오고, nginx가 정적 파일과 /api/를 gunicorn·Django로 나눈다. Django는 SQLite 파일에 쓰고, 결제 승인과 취소는 토스페이먼츠 API를 부른다. 결제창은 브라우저가 직접 연다](/static/images/coffee-shop-00-overview/architecture.svg)

| 영역       | 선택                                      | 이유                                                                                            |
| ---------- | ----------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 백엔드     | Django 6.1, Django REST Framework         | ORM·마이그레이션·인증이 기본으로 있어 구현 범위가 줄고, 테스트 러너가 내장이다                  |
| DB         | SQLite(WAL, IMMEDIATE 트랜잭션)           | 서버 한 대, 사용자는 시연 인원뿐이라 DB 서버를 따로 둘 이유가 없다. 동시 주문은 스파이크로 확인 |
| 프론트엔드 | React 19, Vite 8, Tailwind CSS 4          | 화면 16개짜리 SPA. Vite 개발 서버가 `/api`를 Django로 넘겨 로컬 구성이 한 줄이다                |
| 결제       | 토스페이먼츠 결제창 SDK 2.10.0, 테스트 키 | 국내 테스트 결제가 가입만으로 된다                                                              |
| 운영       | EC2 t3.micro, nginx, gunicorn, systemd    | 월 약 $14.96(추정, SPMP 4.1). 관리할 서버가 하나뿐이다                                          |
| 자동화     | GitHub Actions(ci, docs-sync, deploy)     | 시크릿 없이 OIDC로 Google·AWS에 붙는다                                                          |

## 6. 문서는 어디에 있나

단계 문서 여섯 개가 레포 [`docs/specs/`](https://github.com/seren-wib/coffee-shop/tree/main/docs/specs)에 있다. 프로젝트 계획서(SPMP), 요구사항 명세서(SRS), 설계 명세서(SDD), 테스트 계획서(STP), 설치 계획서(SIP), 유지보수 계획서(SMP)다. `main`에 머지될 때마다 Google Docs 사본을 덮어쓰는 구조는 2편에 있다.

Google Drive 쪽 사본(동기화 Doc과 과제 제출본)은 지금 공개 링크로 열리지 않아서 여기엔 레포 링크만 둔다. 같은 내용이고, 레포 쪽이 원본이다.
