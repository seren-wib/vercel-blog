> How I built **random-idea**, a Claude skill that draws a few technologies at random from a list and turns the combination into project ideas with Claude. The repo is [seren-wib/random-idea-generator](https://github.com/seren-wib/random-idea-generator).

## 1. Why I built it

- Side-project ideas always start from technologies I already know, so I rarely get to touch anything new
- I wanted to **draw a few at random** from my list of technologies and come up with ideas from that combination together with Claude
- The catch: if you ask a model to "pick at random", it is not really random. It keeps drifting toward familiar names like React, Docker and PostgreSQL
- So a script does the drawing, and Claude only proposes ideas from the result

### Is there something like this already?

What I looked at before building it (as of 2026-11-17)

- **StackRoulette** (⭐12): web stacks only, no updates since 2023-02
- **random-stack-style repos**: small repos with 0 to 2 stars
- **Hack Club What Should I Build?**, **onemillionideas**: sites that show project ideas
- **IdeaXApi**, **Pickproject**: idea generation with an LLM attached
- I could not find anything that **draws a set number per category** ("one AI, one hardware, two frontend"), so I built it

## 2. What I built

- `random-idea`, a Claude skill that is also a Claude Code plugin. Public repo, MIT license, v0.1.0
- Node 18 or later, zero dependencies. Runs on Windows, macOS and Linux

### The technology list

- **2,763 technologies** in **17 categories** in `skills/random-idea/assets/techs.json`
- Each entry has five fields: `name`, `category`, `what` (what it is), `uses` (typical uses) and `hw` (hardware flag)
- The hardware flag is separate from the category and is set on **203 entries**. For example, I2C is in Protocol/Standard but carries the hardware flag

### The draw: `scripts/pick.mjs`

- It draws with **mulberry32**, a seeded random number generator. The same seed gives the same result on any machine and any Node version
- The output is a Markdown table plus one line with the seed. Pass the seed back in to repeat the draw

```bash
node scripts/pick.mjs [options]
```

| Option                        | What it does                                                    |
| ----------------------------- | --------------------------------------------------------------- |
| `-n`, `--count N`             | Draw N from the whole list. Default 4                           |
| `--from "AI/ML=1,Frontend=2"` | Draw a set count from each category. Names are case-insensitive |
| `--seed S`                    | Repeat an earlier draw                                          |
| `--categories`                | List the categories and their sizes                             |
| `-h`, `--help`                | Show the options                                                |

- `-n` and `--from` cannot be used together

### What Claude does

1. Turns the request ("give me an idea with one AI and one hardware") into options and runs `pick.mjs`
2. Shows the drawn table and the seed
3. Proposes three ideas. Each says where every drawn technology is used, the smallest version you can finish in a weekend, and the part most likely to get stuck

- **No swapping.** The skill tells Claude not to drop or replace a drawn technology even if the combination looks awkward. Extra pieces such as a database or hosting go on a separate "also needed" line
- **The list never enters the conversation.** Only the script reads the 500 KB `techs.json`; only the drawn rows reach the conversation. So one draw costs a few hundred tokens

### Installation

Add the marketplace in Claude Code and install the plugin

```bash
claude plugin marketplace add seren-wib/random-idea-generator
```

```bash
claude plugin install random-idea@seren-wib
```

- Open a new session, or run `/reload-plugins` in an open one
- The skill runs `node`, so `node --version` has to work in your terminal

## 3. Decisions that changed along the way

- **A CLI, no web page.** I did not build a drawing screen. The ideas come out of a conversation with Claude anyway
- **One skill instead of a CLI repo.** Instead of a separately installed CLI tool, everything lives in one skill folder (`SKILL.md`, the script, the list)
- **Dropped the "known" field.** I was going to mark whether I knew each technology and draw by a ratio of known to unknown, then dropped the field
- **Private → public, in English.** The repo started private, then went public with the README and the list written in English
