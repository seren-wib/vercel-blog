교재 4장 "[VirtualBox](glossary:virtualbox) 기반 [HTCondor](glossary:htcondor) 클러스터 생성"을 따라 [VM](glossary:vm) 3대를 만들고 [SSH](glossary:ssh) [Public key authentication](glossary:public-key-authentication)까지 설정한 과제다. 문제는 내 노트북이 **Apple M3([ARM64](glossary:arm64)) 맥**이라는 거였다. x86용 [VirtualBox](glossary:virtualbox) [VM](glossary:vm)을 그대로 쓸 수 없어서 [Hypervisor](glossary:hypervisor)를 **[KVM](glossary:kvm)/[libvirt](glossary:libvirt)**로 바꿔서 진행했다.

# 0. 실습 환경

```text
macOS (Apple M3)
└─ UTM (Apple Virtualization, 중첩 가상화)
   └─ Ubuntu 24.04 ARM64   (호스트 yoosung-vm, 강의의 "Ubuntu 호스트")
      └─ KVM + libvirt     (VirtualBox 대체)
         ├─ main    Rocky Linux 10.2   192.168.56.101    main.cloud.org
         ├─ work1   Rocky Linux 10.2   192.168.56.102    work1.cloud.org
         └─ work2   Rocky Linux 10.2   192.168.56.103    work2.cloud.org
```

교재([VirtualBox](glossary:virtualbox))와 바꾼 부분은 이렇다.

| 교재 ([VirtualBox](glossary:virtualbox))                                  | 이 환경 ([KVM](glossary:kvm)/[libvirt](glossary:libvirt))                                                                  |
| ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| [Host-only](glossary:host-only-network) 어댑터 vboxnet0 (192.168.56.0/24) | [libvirt](glossary:libvirt) 격리 네트워크 cloud56 ([Network bridge](glossary:network-bridge) virbr56, 호스트 192.168.56.1) |
| [NAT](glossary:nat) 어댑터                                                | [libvirt](glossary:libvirt) default [NAT](glossary:nat) 네트워크 (192.168.122.0/24)                                        |
| `VBoxManage clonevm`                                                      | `virt-clone --auto-clone`                                                                                                  |
| 인터페이스 enp0s3 / enp0s8                                                | enp1s0 ([NAT](glossary:nat)) / enp2s0 (사설 [Static IP address](glossary:static-ip-address))                               |

**[kernel argument](glossary:kernel-parameter) `pci=nomsi`**: [Nested virtualization](glossary:nested-virtualization)에서는 게스트 [virtio](glossary:virtio) 장치의 [MSI](glossary:msi) [interrupt](glossary:interrupt)가 전달되지 않아 Rocky 부팅이 멈췄다. [kernel argument](glossary:kernel-parameter)에 `pci=nomsi`를 넣어 예전 [INTx](glossary:intx) [interrupt](glossary:interrupt)를 쓰게 해서 해결했다(자세한 건 [맨 아래](#부록-중첩-가상화에서-rocky-부팅이-멈춘-문제)). GRUB_TIMEOUT=0으로 바꾸면 [GRUB](glossary:grub) 메뉴에서 [kernel argument](glossary:kernel-parameter)를 손으로 넣을 수 없게 되니까, 이 인자를 [Bootloader](glossary:bootloader)에 먼저 영구 반영하고 나서 타임아웃을 0으로 바꿨다.

**작업 순서**: 원본 [VM](glossary:vm) `rocky-base`에 GRUB_TIMEOUT=0을 설정하고 → 3대로 복제한 다음 → 각 [VM](glossary:vm)에 [Static IP address](glossary:static-ip-address)·[Hostname](glossary:hostname)과 `/etc/hosts`를 설정했다. 실제로는 (b) → (c) → (a) 순서였지만 아래는 과제 항목 순서대로 정리했다.

# 1. HTCondor 클러스터용 VM 만들기

## (a) 사설 고정 IP 지정

사설 네트워크 인터페이스 `enp2s0`에 [NetworkManager](glossary:networkmanager)로 [Static IP address](glossary:static-ip-address)(192.168.56.101~103/24)를 줬다. 외부로 안 나가는 내부망이라 게이트웨이는 지정하지 않았다. [Hostname](glossary:hostname)도 같이 바꿨다.

```bash
sudo nmcli con mod enp2s0 ipv4.method manual ipv4.addresses 192.168.56.101/24 connection.autoconnect yes
sudo nmcli con up enp2s0
sudo hostnamectl set-hostname main.cloud.org
```

work1, work2도 IP를 `.102`, `.103`으로, [Hostname](glossary:hostname)을 `work1.cloud.org`, `work2.cloud.org`로 바꿔서 똑같이 실행했다.

## (b) 부팅 타임아웃 0 (GRUB_TIMEOUT=0)

복제 전에 원본 [VM](glossary:vm)(`rocky-base`)에서 `/etc/default/grub`의 `GRUB_TIMEOUT`을 0으로 바꾸고 `grub2-mkconfig`로 `/boot/grub2/grub.cfg`를 다시 만들었다.

`/etc/default/grub`은 grub.cfg를 만들 때 쓰는 설정 파일이고, 부팅할 때 [GRUB](glossary:grub)이 실제로 읽는 건 `grub.cfg`다. 그래서 고친 다음 꼭 다시 생성해야 한다.

```bash
sudo sed -i 's/^GRUB_TIMEOUT=.*/GRUB_TIMEOUT=0/' /etc/default/grub
sudo grub2-mkconfig -o /boot/grub2/grub.cfg
sudo reboot
```

_GRUB_TIMEOUT=0, [kernel argument](glossary:kernel-parameter)에 pci=nomsi 유지_

## (c) 명령어로 VM 3대 복제

`VBoxManage clonevm` 대신 [libvirt](glossary:libvirt)의 `virt-clone`을 썼다. 원본을 끈 상태에서 실행해야 한다. `--auto-clone`은 디스크 파일([qcow2](glossary:qcow2))과 [UEFI](glossary:uefi) 변수 파일(VARS.fd)을 새 이름으로 복사하고 [MAC address](glossary:mac-address)를 새로 만든다.

```bash
sudo virsh shutdown rocky-base
sudo virt-clone --original rocky-base --name main --auto-clone
sudo virt-clone --original rocky-base --name work1 --auto-clone
sudo virt-clone --original rocky-base --name work2 --auto-clone
virsh list --all
```

![virt-clone으로 3대 생성](/static/images/cloud-computing-hw2-kvm-vm-cluster/11.webp)

_virt-clone으로 main·work1·work2 생성, `virsh list --all`에 4대가 보인다._

진행 표시에서 `main_VARS.fd`가 "0 B"로 나오지만, 아래 `ls -l`을 보면 4개 파일 모두 67,108,864바이트(64MB)로 제대로 복사됐다. 진행률 표시만 0으로 찍힌 거다.

## (d) 복제된 VM에 GRUB_TIMEOUT=0이 남아 있는지 확인

복제는 디스크 전체를 복사하니까 [GRUB](glossary:grub) 설정도 그대로 따라온다. 세 [VM](glossary:vm) 모두에서 설정 파일과 실제 부트 설정을 확인했다.

```bash
grep GRUB_TIMEOUT /etc/default/grub
sudo grep -n "set timeout=" /boot/grub2/grub.cfg
```

## (g) VM끼리 호스트네임으로 ping

각 [VM](glossary:vm)에서 `ping -c 2 main / work1 / work2`를 실행했다. 별칭이 `/etc/hosts`대로 `main.cloud.org(192.168.56.101)` 등으로 변환돼서 응답이 왔다.

자기 자신한테는 약 0.1~0.4ms, 다른 [VM](glossary:vm)으로는 약 3~9ms가 나왔다. [Nested virtualization](glossary:nested-virtualization)을 거치는 만큼 [VM](glossary:vm) 사이 지연이 더 크다.

## (h) SSH로 복제된 VM에 접속

호스트에서 세 [VM](glossary:vm)에 비밀번호로 [SSH](glossary:ssh) 접속하고 `hostname`으로 맞는 [VM](glossary:vm)인지 확인했다. 첫 접속이라 [host key](glossary:ssh-host-key) 확인 질문이 나와서 `yes`로 [known_hosts](glossary:known_hosts)에 등록했다.

![비밀번호 SSH 접속](/static/images/cloud-computing-hw2-kvm-vm-cluster/22.webp)

_호스트 → main·work1·work2 [SSH](glossary:ssh) 접속 (비밀번호 인증)_

> **세 [VM](glossary:vm)의 [host key](glossary:ssh-host-key)가 똑같다.** [ED25519](glossary:ed25519) [host key](glossary:ssh-host-key) [Fingerprint](glossary:fingerprint)가 모두 `SHA256:C+o0I1…`로 같다. [virt-clone](glossary:virt-clone)은 디스크를 그대로 복사하니까 `/etc/ssh/ssh_host_*` 키까지 복제되기 때문이다. 그래서 두 번째 접속부터 "이 키는 다른 이름으로도 알려져 있다"는 메시지가 나온다. 실습엔 문제없지만 실제 운영에서는 복제 후 [host key](glossary:ssh-host-key)를 다시 만들어야 서버를 구별할 수 있다.

# 2. SSH 키 인증 (Ch04-Extra)

## (a) 호스트에서 개인키로 세 VM에 접속

호스트에서 [ED25519](glossary:ed25519) 키 쌍을 만들고, `ssh-copy-id`로 [public key](glossary:public-key-authentication)를 세 [VM](glossary:vm)의 `~/.ssh/authorized_keys`에 등록했다. 이후 접속은 호스트의 [private key](glossary:public-key-authentication)(`~/.ssh/id_ed25519`)로 인증되니까 비밀번호를 묻지 않는다. [private key](glossary:public-key-authentication)는 호스트 밖으로 안 나가고 [VM](glossary:vm)에는 [public key](glossary:public-key-authentication)만 복사된다.

```bash
ssh-keygen -t ed25519
ssh-copy-id yoosung@192.168.56.101
ssh-copy-id yoosung@192.168.56.102
ssh-copy-id yoosung@192.168.56.103
```

![ed25519 키 쌍 생성](/static/images/cloud-computing-hw2-kvm-vm-cluster/23.webp)

_호스트에서 [ed25519](glossary:ed25519) 키 쌍 생성 ([private key](glossary:public-key-authentication) id_ed25519, [public key](glossary:public-key-authentication) id_ed25519.pub)_

![ssh-copy-id](/static/images/cloud-computing-hw2-kvm-vm-cluster/24.webp)

_ssh-copy-id로 [public key](glossary:public-key-authentication) 등록. [VM](glossary:vm)마다 "Number of key(s) added: 1"_

![키 인증 접속](/static/images/cloud-computing-hw2-kvm-vm-cluster/25.webp)

_호스트 → 세 [VM](glossary:vm) [Public key authentication](glossary:public-key-authentication) 접속. 비밀번호 없이 각 [hostname](glossary:hostname)이 출력된다._

## (b) VM끼리 개인키로 접속

세 [VM](glossary:vm)에서 각자 [ED25519](glossary:ed25519) 키 쌍을 만들고, 나머지 두 [VM](glossary:vm)에 [Hostname](glossary:hostname)으로 [public key](glossary:public-key-authentication)를 등록했다. 총 6방향(3대 × 2)이다. [VM](glossary:vm)마다 자기 [private key](glossary:public-key-authentication)를 따로 가지니까 한 대의 키가 유출돼도 다른 [VM](glossary:vm)의 키는 영향을 안 받는다.

```bash
ssh-keygen -t ed25519
ssh-copy-id work1
ssh-copy-id work2
```

main 기준이고, work1은 main·work2, work2는 main·work1로 대상만 바꿔서 실행했다.

![main에서 work1, work2](/static/images/cloud-computing-hw2-kvm-vm-cluster/26.webp)

_main → work1, work2 (비밀번호 없이 접속)_

_work1 → main, work2_

## 복제하면서 겪은 문제

- **시리얼 로그 경로 충돌**: 복제된 [VM](glossary:vm)이 원본의 시리얼 로그 경로(`/var/log/rocky-base-serial.log`)까지 그대로 물려받아서, 두 번째 [VM](glossary:vm)을 켤 때 "Device or resource busy"로 실패했다. `virsh dumpxml`로 설정을 꺼내 경로를 [VM](glossary:vm) 이름별로 바꾸고 `virsh define`으로 다시 등록해서 해결했다.
- **같은 [host key](glossary:ssh-host-key)**: 위 (h)에서 말한 것처럼 디스크 복제 때문에 [SSH](glossary:ssh) [host key](glossary:ssh-host-key)가 세 대 모두 같다.

# 부록. 중첩 가상화에서 Rocky 부팅이 멈춘 문제

가장 오래 막혔던 건 [Rocky Linux](glossary:rocky-linux) 게스트가 커널 부팅 7~8초 지점에서 멈추는 현상이었다. 결론부터 말하면 [Nested virtualization](glossary:nested-virtualization) 환경에서 **[MSI](glossary:msi) [interrupt](glossary:interrupt)가 게스트에 전달되지 않아서** 생긴 문제였고, 게스트 [kernel argument](glossary:kernel-parameter) `pci=nomsi` 한 줄로 해결했다. [KVM](glossary:kvm)을 끄지 않고 해결해서 구성도 바꿀 필요가 없었다.

## 증상

[Rocky Linux](glossary:rocky-linux) 10.2 [aarch64](glossary:arm64) 게스트를 [KVM](glossary:kvm)으로 올리면 커널 부팅 7~8초 지점에서 멈추고 더 진행하지 않았다. 도메인 상태는 running이고 cpu.time도 계속 올라갔다. [VM](glossary:vm)은 켜져 있고 CPU도 쓰는데 부팅만 안 되는 상태다. 2코어로 돌리면 60초 뒤 [RCU stall](glossary:rcu-stall) 경고까지 찍혔다.

```text
[     7.300568] pcieport 0000:00:01.1: PME: Signaling with IRQ 51
[    67.306241] rcu: INFO: rcu_preempt detected stalls on CPUs/tasks:
[    67.346763] rcu:     Possible timer handling issue on cpu=0 timer-softirq=151
[    67.354764] rcu: rcu_preempt kthread starved for 6002 jiffies!
[    67.434740] rcu: Sending NMI from CPU 1 to CPUs 0:
```

그래픽 콘솔에서는 `Display output is not active`로만 보여서 원인을 알 수가 없었다. [Serial console](glossary:serial-console) 출력을 파일로 남기도록 바꾸고 나서야 위 로그를 얻었다. 부팅이 어디까지 갔는지는 시리얼 로그 파일 크기로 비교했다. 정상 부팅이면 설치 프로그램 화면까지 로그가 계속 늘어난다.

## 먼저 해결한 두 문제

부팅 정지를 보기 전에 다른 문제 두 개가 먼저 나왔다.

**① [Secure Boot](glossary:secure-boot) 펌웨어**

`virt-install`에 `--boot uefi`만 주면 [libvirt](glossary:libvirt)가 Microsoft 키가 등록된 `AAVMF_CODE.ms.fd`를 고른다. 이 펌웨어는 서명 안 된 커널을 거부해서 이런 오류가 났다.

```text
error: ../../grub-core/loader/efi/linux.c:723:failed to install protocols.
Failed to boot both default and fallback entries.
```

[Secure Boot](glossary:secure-boot)가 꺼진 펌웨어를 직접 지정해서 해결했다. 게스트 커널 로그에 `secureboot: Secure boot disabled`가 찍히는 것도 확인했다.

```text
--boot loader=/usr/share/AAVMF/AAVMF_CODE.no-secboot.fd,loader.readonly=yes,loader.type=pflash,loader.secure=no,nvram.template=/usr/share/AAVMF/AAVMF_VARS.fd
```

**② 그래픽 콘솔이 안 뜸**

[aarch64](glossary:arm64) 게스트는 [SPICE](glossary:spice) 콘솔에 화면이 안 뜨고 `Display output is not active`만 보인다. 게다가 `--cdrom`으로는 [kernel argument](glossary:kernel-parameter)를 넘길 수 없다. 설치 방식을 이렇게 바꿨다.

- `--location <ISO>`: ISO에서 vmlinuz와 initrd.img를 꺼내 직접 부팅한다. [GRUB](glossary:grub)을 안 거쳐서 ①의 오류도 같이 피한다.
- `--graphics none` + `--extra-args "console=ttyAMA0,115200 inst.text"`: 설치 프로그램을 시리얼 텍스트 모드로 띄운다.
- `--serial pty,log.file=<경로>`: 시리얼 출력을 파일로 남긴다. `virsh console`은 접속 시점에 따라 초기 출력을 놓쳐서 빈 화면으로 보일 때가 많다. 파일로 남겨야 부팅 로그를 처음부터 볼 수 있었다.

이 두 개를 해결하고 나서야 7~8초에서 멈추는 문제를 제대로 볼 수 있었다.

## 원인 분석

조건을 하나씩 바꿔 가며 네 번 돌려서 원인을 좁혔다.

| 실험 | 바꾼 것                                                                  | 시리얼 로그 크기 | 결과        |
| ---- | ------------------------------------------------------------------------ | ---------------- | ----------- |
| 1    | [vCPU](glossary:vcpu) 2 (기준)                                           | 46,222 B         | 7.30초 정지 |
| 2    | [vCPU](glossary:vcpu) 1                                                  | —                | 8.22초 정지 |
| 3    | `--virt-type qemu` ([TCG](glossary:tcg) [Emulation](glossary:emulation)) | 115,139 B        | 정상 진입   |
| 4    | [KVM](glossary:kvm) 유지 + `pci=nomsi`                                   | 98,182 B         | 정상 진입   |

**가설 1. 중첩 환경의 타이머 문제 (틀림)**

처음엔 [RCU stall](glossary:rcu-stall) 메시지의 `Possible timer handling issue on cpu=0`을 보고 타이머 전달 실패를 의심했다. L1([Ubuntu](glossary:ubuntu))의 dmesg에서 `kvm [1]: Hyp nVHE mode initialized successfully`도 찾았다. 보통 ARM 하드웨어에서 [KVM](glossary:kvm)은 [VHE](glossary:vhe) 모드로 올라오는데 여기선 [nVHE](glossary:vhe)였다. Apple 가상화가 중첩용 EL2는 주지만 [VHE](glossary:vhe) 기능은 안 준다는 뜻이라 타이머에도 문제가 있을 수 있다고 봤다.

하지만 실험 1과 2는 멈춘 줄이 서로 달라서 특정 드라이버 하나의 문제로 보기 어려웠다. 그리고 두 번 다 멈추기 직전에 [PCI](glossary:pci) 장치를 깨우고 있었다. 그래서 [RCU stall](glossary:rcu-stall)은 [interrupt](glossary:interrupt)를 못 받은 뒤에 따라 나온 증상으로 보고 이 가설을 버렸다.

**가설 2. 중첩 [KVM](glossary:kvm) 자체의 문제 (범위를 좁힘)**

같은 ISO·커널·펌웨어에서 `--virt-type qemu`로 [KVM](glossary:kvm) 없이 [TCG](glossary:tcg) [Emulation](glossary:emulation)으로 돌렸더니 설치 프로그램까지 정상으로 들어갔다(실험 3). 바꾼 게 [KVM](glossary:kvm) 하나뿐이니 문제는 [Nested virtualization](glossary:nested-virtualization) 쪽이다. 다만 [TCG](glossary:tcg)는 10~20배 느려서 실습에는 못 쓰고 원인을 가리는 데만 썼다.

**가설 3. [MSI](glossary:msi) [interrupt](glossary:interrupt) 전달 실패 (실제 원인)**

두 번 다 [PCI](glossary:pci) 장치에서 멈췄으니 [interrupt](glossary:interrupt) 경로를 의심했다. ARM에서 [PCI](glossary:pci) 장치는 [MSI](glossary:msi)-X로 [interrupt](glossary:interrupt)를 보내고 [interrupt](glossary:interrupt) 컨트롤러([GIC](glossary:gic))가 받는다. L1의 dmesg에서 이걸 확인했다.

```text
GICv2m: range[mem 0x1fff0000-0x1fff0fff], SPI[128:255]
kvm [1]: GICv3: no GICV resource entry
kvm [1]: disabling GICv2 emulation
```

L1에는 [MSI](glossary:msi)를 처리하는 [ITS](glossary:gic)가 없고 예전 방식인 [GICv2m](glossary:gic)을 쓰고 있었다. 이 구성에서는 [MSI](glossary:msi)가 게스트까지 안 가서, [virtio](glossary:virtio)-pci 장치가 보낸 [interrupt](glossary:interrupt)를 게스트가 못 받고 그 자리에서 멈춘 걸로 보인다.

## 해결

게스트 [kernel argument](glossary:kernel-parameter)에 `pci=nomsi` 하나를 추가했다. 이러면 게스트가 [MSI](glossary:msi) 대신 예전 방식인 [INTx](glossary:intx)로 [interrupt](glossary:interrupt)를 받아서 문제 있는 경로를 아예 안 쓴다.

```text
--extra-args "console=ttyAMA0,115200 inst.text pci=nomsi"
```

| 조건                             | 시리얼 로그 | 결과                    |
| -------------------------------- | ----------- | ----------------------- |
| [KVM](glossary:kvm), 인자 없음   | 46,222 B    | 7~8초 정지              |
| [KVM](glossary:kvm), `pci=nomsi` | 98,182 B    | 설치 프로그램 정상 진입 |

이 방법을 고른 이유

- [KVM](glossary:kvm)을 끄지 않아도 된다. [TCG](glossary:tcg)처럼 느려지지 않는다.
- 구성을 안 바꾼다. 추가한 건 게스트 [kernel argument](glossary:kernel-parameter) 한 줄뿐이다.
- 단점은 I/O가 조금 느려지는 정도다. [INTx](glossary:intx)는 [MSI](glossary:msi)보다 효율이 떨어지지만 [VM](glossary:vm) 3대짜리 실습에서는 문제없었다.

## 재현에 필요한 설정

| 항목                                         | 값                                           | 이유                                                                          |
| -------------------------------------------- | -------------------------------------------- | ----------------------------------------------------------------------------- |
| 펌웨어                                       | `AAVMF_CODE.no-secboot.fd`                   | [Secure Boot](glossary:secure-boot) 펌웨어는 서명 없는 커널을 거부            |
| 부팅 방식                                    | `--location <ISO>`                           | [kernel argument](glossary:kernel-parameter)를 넘기려고 직접 부팅             |
| 콘솔                                         | `--graphics none` + `--serial pty,log.file=` | [aarch64](glossary:arm64)는 그래픽 콘솔이 안 뜸, 초기 로그 보존               |
| [kernel argument](glossary:kernel-parameter) | `pci=nomsi`                                  | 중첩 환경에서 [MSI](glossary:msi)가 전달되지 않는 문제 회피                   |
| 패키지                                       | `qemu-efi-aarch64` 포함                      | [aarch64](glossary:arm64)는 BIOS가 없어서 [UEFI](glossary:uefi) 펌웨어가 필요 |
