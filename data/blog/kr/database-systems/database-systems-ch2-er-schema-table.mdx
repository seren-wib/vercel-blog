# COMPANY 하나로 보는 ER · 스키마 · 테이블

같은 COMPANY를 세 층으로 그린 것. ① ER(ch2) → ② 변환한 스키마(ch3 3.4) → ③ 데이터 든 테이블(ch3 3.1). 아래 표는 개념마다 세 그림의 어디인지만 가리킴. 시험 "RDB 그리기" = ①을 보고 ② 그리기

## 1. ER 다이어그램

![COMPANY ER: 개체 4, 관계 6, (min,max)까지](/static/images/database-systems-ch2-er-schema-table/company-1-er.svg)

| 기호                                 | 뜻                                                                    |
| ------------------------------------ | --------------------------------------------------------------------- |
| 사각형 / 이중 사각형                 | entity type / weak entity type                                        |
| 타원 / 밑줄 / 점선 밑줄              | attribute / key / partial key                                         |
| 이중 타원 / 점선 타원 / 가지 친 타원 | multivalued / derived / composite                                     |
| 마름모 / 이중 마름모                 | relationship / identifying relationship                               |
| 선 한 줄 / 두 줄                     | partial / total participation                                         |
| 1, N, M                              | cardinality ratio (상대편 최대 몇 개)                                 |
| 보라 (min,max)                       | 이 개체 하나가 관계에 최소·최대 몇 번. min 0 = 한 줄, min ≥ 1 = 두 줄 |

## 2. 관계형 스키마

![COMPANY 관계형 스키마: 테이블 6개, PK 밑줄, FK 화살표](/static/images/database-systems-ch2-er-schema-table/company-2-schema.svg)

- 테이블 6개 = 사각형 4 + M:N 마름모 1(WORKS_ON) + 이중 타원 1(DEPT_LOCATIONS)
- 화살표는 전부 FK → PK. 화살표 7개 = 1:N 마름모 2(Dno, Dnum) + 1:1 마름모 1(Mgr_ssn) + 재귀 1(Super_ssn) + M:N 2(Essn, Pno) + 약한 개체 1(Essn) + 이중 타원 1(Dnumber)
- 이름 바뀜 주의: Number → Dnumber/Pnumber, Name → Dname/Pname, EMPLOYEE.Ssn을 가져가면 Essn·Mgr_ssn·Super_ssn

## 3. 테이블 (relation state)

![COMPANY 테이블 6개에 튜플 넣은 모습](/static/images/database-systems-ch2-er-schema-table/company-3-tables.svg)

- 머리줄 = schema, 그 아래 행들 = state. 행 추가·삭제해도 머리줄은 그대로
- FK 칸 값은 반드시 상대 테이블 PK에 있는 값이거나 NULL. 그림 오른쪽 아래 다섯 줄이 삽입·삭제 위반 판정
