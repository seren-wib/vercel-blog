교재 11·12장의 [KVM](glossary:kvm) 실습을 따라 했다. 앞부분은 [KVM](glossary:kvm)을 설치하고 [Rocky Linux](glossary:rocky-linux) [VM](glossary:vm)을 만들어 `virsh`로 다루고 복제하는 기본 실습이고, 뒷부분은 [KVM](glossary:kvm) 호스트 역할을 하는 [Rocky](glossary:rocky-linux) [VM](glossary:vm) 두 대를 만들어 그 안에서 돌아가는 [CirrOS](glossary:cirros) [VM](glossary:vm)을 한쪽에서 다른 쪽으로 실행 중인 채로 옮기는 [Live migration](glossary:live-migration)이다.

# 0. 실습 환경

HW2부터 쓰던 [Ubuntu](glossary:ubuntu) 호스트(Apple M3 맥의 [UTM](glossary:utm) 위 [Ubuntu](glossary:ubuntu) 24.04 [aarch64](glossary:arm64))에서 했다. 호스트가 [aarch64](glossary:arm64)라서 [Rocky Linux](glossary:rocky-linux) ISO와 [CirrOS](glossary:cirros) 이미지는 [aarch64](glossary:arm64)판을 썼고, 슬라이드와 명령이 달라진 곳은 해당 그림 아래에 적었다.

[Live migration](glossary:live-migration)은 슬라이드처럼 VirtualBox [VM](glossary:vm) 두 대 대신, [Ubuntu](glossary:ubuntu) 호스트의 [KVM](glossary:kvm) 위에 [Rocky](glossary:rocky-linux) 두 대를 만들어 진행했다. 그 두 대가 각각 [KVM](glossary:kvm) 호스트가 되고, [CirrOS](glossary:cirros)는 그 안에서 한 번 더 중첩된 [VM](glossary:vm)이다.

```text
Ubuntu 호스트 (KVM)
├─ servera Rocky 10.2   192.168.56.101   ── CirrOS ──┐   virsh migrate --live
└─ serverb Rocky 10.2   192.168.56.102   ◀───────────┘
```

# 1. KVM 실습

## KVM 설치

`cpu-checker`의 `kvm-ok`로 `/dev/kvm`이 있고 [KVM](glossary:kvm) 가속을 쓸 수 있는지 먼저 확인했다. [UTM](glossary:utm)에서 [Nested virtualization](glossary:nested-virtualization)을 켜 둬서 [Ubuntu](glossary:ubuntu) 호스트 안에서도 [KVM](glossary:kvm)이 된다.

![kvm-ok](/static/images/cloud-computing-hw6-kvm-live-migration/01.webp)

_cpu-checker 설치 후 kvm-ok — /dev/kvm이 있고 [KVM](glossary:kvm) 가속을 쓸 수 있음_

```bash
sudo apt install -y qemu-kvm qemu-utils libvirt-daemon-system libvirt-clients bridge-utils virt-manager virtinst
sudo systemctl enable --now libvirtd
systemctl status libvirtd --no-pager | head -5
```

![KVM 패키지 설치](/static/images/cloud-computing-hw6-kvm-live-migration/02.webp)

_KVM 패키지 설치와 libvirtd 활성화·상태 확인_

![이미지 디렉터리와 브리지](/static/images/cloud-computing-hw6-kvm-live-migration/03.webp)

_이미지 디렉터리 VM/instances 생성, [Rocky](glossary:rocky-linux) ISO 준비, nmcli c로 virbr0 [Network bridge](glossary:network-bridge) 확인_

일반 사용자로 [Network bridge](glossary:network-bridge)를 쓰도록 `/etc/qemu/bridge.conf`에 `allow all`을 넣고 `qemu-bridge-helper`에 [setuid](glossary:setuid)를 줬다. [libvirt](glossary:libvirt) 접속 주소는 사용자 세션(`qemu:///session`)으로 맞췄다.

```bash
sudo mkdir -p /etc/qemu; echo "allow all" | sudo tee /etc/qemu/bridge.conf
sudo chmod u+s /usr/lib/qemu/qemu-bridge-helper
export LIBVIRT_DEFAULT_URI=qemu:///session
sudo systemctl restart libvirtd
```

![bridge.conf와 qemu-bridge-helper](/static/images/cloud-computing-hw6-kvm-live-migration/04.webp)

_/etc/qemu/bridge.conf, qemu-bridge-helper [setuid](glossary:setuid), LIBVIRT_DEFAULT_URI=qemu:///session 설정과 libvirtd 재시작_

## KVM에 Rocky 가상머신 설치

```bash
virt-install --name rocky10-1 --ram 3072 --disk path=VM/instances/rocky10-1.img,size=20 \
  --vcpus 2 --cpu host-passthrough --network bridge=virbr0 --graphics none \
  --console pty,target_type=serial --location Rocky-10.2-aarch64-minimal.iso \
  --extra-args "inst.text console=ttyAMA0,115200 pci=nomsi" \
  --boot loader=/usr/share/AAVMF/AAVMF_CODE.no-secboot.fd,\
loader.readonly=yes,loader.type=pflash,loader.secure=no,\
nvram.template=/usr/share/AAVMF/AAVMF_VARS.fd \
  --osinfo detect=on,require=off
```

슬라이드 8쪽 명령에서 [aarch64](glossary:arm64) 때문에 바꾼 곳은 네 군데다.

- ISO는 [aarch64](glossary:arm64)판을 썼다.
- [Serial console](glossary:serial-console)은 `ttyS0` 대신 `ttyAMA0`이다.
- [Nested virtualization](glossary:nested-virtualization)에서 [MSI](glossary:msi) 인터럽트가 전달되지 않아 `pci=nomsi`를 붙였다.
- 기본 [UEFI](glossary:uefi) 펌웨어([Secure Boot](glossary:secure-boot))에서는 설치된 [GRUB](glossary:grub)이 실행되지 않아 [Secure Boot](glossary:secure-boot)가 없는 펌웨어를 `--boot`로 지정했다.

뒤의 두 가지는 HW2에서 [중첩 가상화에서 Rocky 부팅이 멈춘 문제](/kr/blog/cs-fundamentals/cloud-computing/cloud-computing-hw2-kvm-vm-cluster/#부록-중첩-가상화에서-rocky-부팅이-멈춘-문제)를 풀면서 찾은 설정이다. `--boot` 값은 경로가 중간에 끊기지 않게 `\`로 세 줄에 나눴다. 이어지는 줄을 들여쓰면 셸이 공백에서 옵션 값을 쪼개므로 들여쓰지 않았다.

## 많이 사용하는 virsh 명령어

```bash
virsh list --all
virsh shutdown rocky10-1
virsh start rocky10-1
virsh reboot rocky10-1
virsh destroy rocky10-1
virsh console rocky10-1
```

`shutdown`은 [Guest OS](glossary:guest-os)에 종료 요청을 보내 정상 종료시키고, `destroy`는 전원을 뽑듯이 바로 끈다. `destroy`라는 이름과 달리 정의나 디스크는 지우지 않는다.

## KVM 복제

복제는 원본이 꺼진 상태에서 한다. `virt-clone`이 디스크 이미지와 [UEFI](glossary:uefi) 변수 파일(`_VARS.fd`)을 같이 복사하고 새 정의를 만든다.

```bash
virsh shutdown rocky10-1
virt-clone --original rocky10-1 --name rocky10-2 --file VM/instances/rocky10-2.img
virsh undefine rocky10-2 --nvram
```

![virt-clone](/static/images/cloud-computing-hw6-kvm-live-migration/15.webp)

## 가상화 패키지 설치와 복제

servera·serverb의 원본이 될 [Rocky](glossary:rocky-linux) [VM](glossary:vm)(rocky-base)에 가상화 패키지를 설치하고 libvirtd를 켰다. 마이그레이션 때 두 호스트가 서로 접속해야 하므로 실습 환경에서는 [firewalld](glossary:firewalld)를 끄고 [SELinux](glossary:selinux)를 Permissive로 바꿨다.

```bash
dnf install -y qemu-kvm libvirt python3-libvirt virt-install
systemctl enable libvirtd; systemctl start libvirtd
systemctl disable firewalld; systemctl stop firewalld
setenforce 0; getenforce
```

## 가상머신 환경설정

두 대의 두 번째 네트워크([Ubuntu](glossary:ubuntu) 호스트의 virbr2, 192.168.56.0/24) 주소 192.168.56.101·102를 확인하고, `/etc/hosts`에 서로의 이름을 넣은 뒤 호스트 이름을 바꿨다. 복제 전 원본에서 쓰던 이름이 남아 있어서 프롬프트가 바꾸기 전엔 `root@main`, `root@work1`로 보인다.

```bash
printf "192.168.56.101 servera.cloud.org servera\n192.168.56.102 serverb.cloud.org serverb\n" >> /etc/hosts
hostnamectl set-hostname servera   # serverb에서는 serverb
```

![servera 설정](/static/images/cloud-computing-hw6-kvm-live-migration/21.webp)

_servera — IP 192.168.56.101 확인, /etc/hosts, 호스트 이름 servera_

![serverb 설정](/static/images/cloud-computing-hw6-kvm-live-migration/22.webp)

_serverb — IP 192.168.56.102, /etc/hosts, 호스트 이름 serverb_

`virsh migrate`는 servera에서 serverb의 [libvirt](glossary:libvirt)에 [SSH](glossary:ssh)(`qemu+ssh://`)로 접속하므로, servera root가 비밀번호 없이 serverb root로 들어갈 수 있어야 한다. servera에서 키를 만들어 serverb에 복사했다.

```bash
ssh-keygen -t ed25519 -f /root/.ssh/cloudkey -N "" -q
ssh-copy-id -i ~/.ssh/cloudkey yoosung@serverb
```

![키 생성과 복사](/static/images/cloud-computing-hw6-kvm-live-migration/23.webp)

_servera root에서 키 cloudkey 생성, [ssh-copy-id](glossary:ssh-key)로 serverb에 복사_

`ssh-copy-id`는 일반 사용자 계정에 키를 넣으므로 serverb에서 그 키를 root의 `authorized_keys`로 옮겼다. 사용자 쪽 파일에는 [Ubuntu](glossary:ubuntu) 호스트의 접속 키도 들어 있어서, 파일을 통째로 옮기지 않고 servera 키 줄만 추가했다.

```bash
grep root@servera /home/yoosung/.ssh/authorized_keys >> /root/.ssh/authorized_keys
chown root:root .ssh/authorized_keys; chmod 600 .ssh/authorized_keys
```

![authorized_keys](/static/images/cloud-computing-hw6-kvm-live-migration/24.webp)

_serverb — servera의 키를 root의 [authorized_keys](glossary:ssh-key)에 등록, 소유자 root·권한 600_

```text:~/.ssh/config
Host serverb
    HostName serverb.cloud.org
    User     root
    Port     22
    IdentityFile ~/.ssh/cloudkey
```

![ssh serverb](/static/images/cloud-computing-hw6-kvm-live-migration/25.webp)

_servera [~/.ssh/config](glossary:ssh-config) 작성 후 [ssh](glossary:ssh) serverb — 비밀번호 없이 serverb root로 접속_

## KVM 가상머신 생성 및 라이브 마이그레이션

공유 저장소 없이 디스크까지 복사하는 마이그레이션이라 받는 쪽(serverb)에도 같은 경로의 [Storage pool](glossary:storage-pool)이 있어야 한다.

```bash
virsh pool-define-as --name default --type dir --target /var/lib/libvirt/images/
virsh pool-autostart default; virsh pool-build default; virsh pool-start default
```

![저장소 풀](/static/images/cloud-computing-hw6-kvm-live-migration/26.webp)

_serverb에 이미지 [Storage pool](glossary:storage-pool) default 생성_

```bash
wget -q --show-progress https://download.cirros-cloud.net/0.5.2/cirros-0.5.2-aarch64-disk.img
mv cirros-0.5.2-aarch64-disk.img /var/lib/libvirt/images/
```

![CirrOS 이미지](/static/images/cloud-computing-hw6-kvm-live-migration/27.webp)

_servera에서 [CirrOS](glossary:cirros) 0.5.2 이미지([aarch64](glossary:arm64)판) 내려받아 /var/lib/libvirt/images/로 이동_

[Rocky](glossary:rocky-linux) [VM](glossary:vm) 안에는 `/dev/kvm`이 없어서 슬라이드 32쪽대로 `--virt-type qemu`([Software emulation](glossary:software-emulation))를 썼다. 슬라이드와 다르게 디스크가 [virtio](glossary:virtio)로 붙도록 `--osinfo linux2022`를, [Software emulation](glossary:software-emulation) 속도를 위해 `--cpu cortex-a57`을 지정했다.

```bash
virt-install --name cirros --ram 512 \
  --disk path=/var/lib/libvirt/images/cirros-0.5.2-aarch64-disk.img,format=qcow2 \
  --osinfo linux2022 --virt-type qemu --cpu cortex-a57 --tpm none \
  --nographics --import --noautoconsole
```

![CirrOS 생성](/static/images/cloud-computing-hw6-kvm-live-migration/28.webp)

_CirrOS [VM](glossary:vm) 생성 — --virt-type [qemu](glossary:qemu), --osinfo linux2022([virtio](glossary:virtio) 디스크), --cpu cortex-a57_

![CirrOS 로그인](/static/images/cloud-computing-hw6-kvm-live-migration/29.webp)

_virsh console cirros — 부팅 후 cirros 계정으로 로그인_

마이그레이션 중에도 프로세스가 살아 있는지 보려고, [CirrOS](glossary:cirros) 안에 1초마다 Count를 올리며 찍는 스크립트를 만들었다.

```sh:test.sh
#!/bin/sh
count=0
while :
do
        count=$((count+1))
        echo "Testing Live Migration.. Press Ctrl+C to stop..."
        echo "Count =" $count
        date
        sleep 1
done
```

![test.sh 작성](/static/images/cloud-computing-hw6-kvm-live-migration/30.webp)

_CirrOS 안에 작업 파일 test.sh(1초마다 Count 증가) 작성, 실행 권한 부여_

`./test.sh`를 실행해 둔 채로 `Ctrl+]`로 콘솔만 빠져나왔다. [VM](glossary:vm)과 스크립트는 계속 돈다.

![test.sh 실행](/static/images/cloud-computing-hw6-kvm-live-migration/31.webp)

_./test.sh 실행(Count 1~6, 02:46:27~02:46:33 UTC) 중에 Ctrl+]로 콘솔만 빠져나옴 — servera에서 cirros running_

```bash
virsh migrate --verbose --copy-storage-all --persistent --live cirros qemu+ssh://root@serverb/system
```

- `--live`: [VM](glossary:vm)을 끄지 않고 메모리를 복사하면서 옮긴다.
- `--copy-storage-all`: 공유 저장소가 없으니 디스크 이미지까지 함께 복사한다.
- `--persistent`: serverb에 정의를 영구로 남긴다.

![virsh migrate](/static/images/cloud-computing-hw6-kvm-live-migration/32.webp)

_virsh migrate — Migration 100%, servera에서는 더 이상 실행되지 않음(정의만 shut off로 남음)_

![serverb에서 이어진 Count](/static/images/cloud-computing-hw6-kvm-live-migration/33.webp)

_serverb에서 cirros running, 콘솔에 접속하면 같은 test.sh가 Count 238부터 계속 출력 — 프로세스가 종료되지 않고 serverb로 옮겨짐_

마이그레이션 전 servera에서 시작한 test.sh가 종료되지 않고 serverb에서 Count가 이어졌다. Count가 1로 초기화되지 않았으니 [VM](glossary:vm)이 실행 상태를 유지한 채 다른 호스트로 옮겨진 것이다([Live migration](glossary:live-migration)). `--copy-storage-all`로 공유 저장소 없이 디스크 이미지까지 함께 복사했다.

마지막으로 servera에 남은 정의를 지우고 serverb의 cirros를 껐다.

## Ch11-5. hellocloud.c와 가상 메모리 레이아웃

> hellocloud.c를 작성하여 수행하고, [pmap](glossary:pmap) 등을 이용하여 [Virtual memory](glossary:virtual-memory)의 [Memory layout](glossary:memory-layout)을 도식화하라.

각 메모리 영역에 하나씩 놓이도록 전역 변수(초기화한 것, 안 한 것), 문자열 상수, 지역 변수, [malloc](glossary:malloc) 영역을 만들고 그 주소를 출력한 뒤, 프로그램이 Enter를 기다리는 동안 다른 터미널에서 `pmap`과 `/proc/<pid>/maps`로 [Memory layout](glossary:memory-layout)을 확인했다.

```c:hellocloud.c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int g_init = 2026;          /* .data : 초기화된 전역 변수 */
int g_uninit;               /* .bss  : 초기화 안 된 전역 변수 */
const char *msg = "Hello, Cloud!";   /* 문자열 리터럴은 .rodata */

int main(void)
{
    int local = 1;                          /* stack */
    char *heap = malloc(4096);              /* heap (4 KiB, brk 영역) */

    printf("%s  pid=%d\n", msg, getpid());
    printf("text   (main)     : %p\n", (void *)main);
    printf("rodata (msg)      : %p\n", (void *)msg);
    printf("data   (g_init)   : %p\n", (void *)&g_init);
    printf("bss    (g_uninit) : %p\n", (void *)&g_uninit);
    printf("heap   (malloc)   : %p\n", (void *)heap);
    printf("libc   (printf)   : %p\n", (void *)printf);
    printf("stack  (local)    : %p\n", (void *)&local);
    printf("press Enter to exit...\n");
    getchar();
    free(heap);
    return 0;
}
```

- `main`(0x…909d8)과 문자열 `msg`(0x…90b38)는 실행 파일의 첫 매핑(r-x)에 있다. 코드와 읽기 전용 데이터가 같은 페이지에 들어갔다.
- `g_init`([.data](glossary:data-segment))과 `g_uninit`([.bss](glossary:bss))은 실행 파일의 쓰기 가능 매핑(rw-) 한 페이지 안에 붙어 있다. 그 아래 r-- 페이지는 재배치가 끝난 뒤 읽기 전용으로 바뀌는 영역([RELRO](glossary:relro))이다.
- `malloc(4096)`은 실행 파일 바로 위의 [heap](132K)에서 나왔다. [Heap](glossary:heap)은 [brk](glossary:brk)로 높은 주소 쪽으로 늘어난다. 128 KiB 이상을 요청하면 [Heap](glossary:heap) 대신 [mmap](glossary:mmap) 영역에 따로 매핑된다.
- `printf`는 [mmap](glossary:mmap) 영역의 libc.so.6 코드에 있고, [Dynamic linker](glossary:dynamic-linker) ld-linux-aarch64.so.1와 커널이 넣어 주는 [vvar]·[vdso]도 이 영역에 있다.
- 지역 변수 `local`은 사용자 주소 공간 맨 위의 [stack](132K)에 있고, [Stack](glossary:stack)은 낮은 주소 쪽으로 자란다.
- [ASLR](glossary:aslr) 때문에 실행할 때마다 주소는 바뀌지만 영역의 순서와 권한은 같다.

## Ch11-9. Memory Ballooning

> Memory Ballooning 기법에 대해 조사하고 설명하라.

[Memory ballooning](glossary:memory-ballooning)은 [Hypervisor](glossary:hypervisor)가 실행 중인 [VM](glossary:vm)의 메모리를 회수하거나 되돌려 주는 기법이다. [Guest OS](glossary:guest-os) 안에 벌룬 드라이버([KVM](glossary:kvm)에서는 `virtio_balloon`)를 두고, [Hypervisor](glossary:hypervisor)가 이 드라이버에 목표 크기를 알려 주면 드라이버가 [Guest OS](glossary:guest-os) 메모리를 풍선처럼 부풀리거나 줄인다.

- **필요한 이유**: [Hypervisor](glossary:hypervisor)는 [Guest OS](glossary:guest-os)가 자기 메모리 중 어떤 페이지를 실제로 쓰는지 알지 못한다(의미적 차이). 호스트 메모리가 부족할 때 [Hypervisor](glossary:hypervisor)가 직접 [Guest OS](glossary:guest-os) 페이지를 골라 스왑하면, [Guest OS](glossary:guest-os) 커널이 자주 쓰는 페이지를 내보내 성능이 크게 떨어질 수 있다. [Memory ballooning](glossary:memory-ballooning)은 어떤 페이지를 내놓을지를 [Guest OS](glossary:guest-os)가 고르게 한다.
- **회수(inflate)**: [Hypervisor](glossary:hypervisor)가 목표 크기를 줄이면 벌룬 드라이버가 [Guest OS](glossary:guest-os) 커널에 페이지를 할당받아 붙잡고, 그 물리 페이지 번호를 [Hypervisor](glossary:hypervisor)에 알린다. [Guest OS](glossary:guest-os) 입장에서는 드라이버가 메모리를 쓰고 있는 것이므로 다른 프로세스가 그 페이지를 쓰지 않는다. [Hypervisor](glossary:hypervisor)는 그 페이지를 다른 [VM](glossary:vm)에 넘길 수 있다. [Guest OS](glossary:guest-os)에 여유 메모리가 없으면 [Guest OS](glossary:guest-os)가 스스로 캐시를 비우거나 자기 [Swap space](glossary:swap-space)로 페이지를 내보낸다.
- **반환(deflate)**: 목표 크기를 다시 늘리면 드라이버가 붙잡고 있던 페이지를 [Guest OS](glossary:guest-os) 커널에 돌려주고, [Guest OS](glossary:guest-os)는 그 메모리를 다시 쓴다.
- **효과**: [VM](glossary:vm)을 멈추지 않고 메모리 크기를 바꿀 수 있어 [Memory overcommit](glossary:memory-overcommit)([VM](glossary:vm)들에 준 메모리 합이 실제 메모리보다 큼)을 안전하게 운영할 수 있다. [KVM](glossary:kvm)에서는 설정한 최대 메모리(`memory`) 안에서 `virsh setmem <vm> <크기>`로 현재 메모리(`currentMemory`)를 바꾸면 벌룬 드라이버가 동작한다.
- **한계**: [Guest OS](glossary:guest-os)에 벌룬 드라이버가 설치되어 있고 [Guest OS](glossary:guest-os)가 협조해야 한다. 회수가 [Guest OS](glossary:guest-os)의 페이지 회수 속도에 묶여 즉각적이지 않고, 너무 많이 부풀리면 [Guest OS](glossary:guest-os) 안에서 [Swap space](glossary:swap-space)나 [OOM](glossary:oom)이 생길 수 있다. 최대 메모리보다 크게 늘릴 수는 없다. 그래서 실제 시스템에서는 [Memory ballooning](glossary:memory-ballooning)을 [KSM](glossary:ksm)(같은 내용의 페이지 공유), [Hypervisor](glossary:hypervisor) 스와핑과 함께 쓴다.
