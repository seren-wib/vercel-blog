# Relational Algebra on One Page (all of chapter 6)

[SQL](glossary:sql) says "what you want", [relational algebra](glossary:relational-algebra) says "in what order to pull it out". When writing answers, breaking them into one line per step with ← keeps you from going wrong

## 1. Symbols at a glance

| Symbol                                                                                   | Name                                            | What it does                                      | [SQL](glossary:sql)                                                                           |
| ---------------------------------------------------------------------------------------- | ----------------------------------------------- | ------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| [σ](glossary:selection)<sub>condition</sub>(R)                                           | SELECT                                          | **Rows** that meet the condition                  | [WHERE](glossary:where)                                                                       |
| [π](glossary:projection)<sub>columns</sub>(R)                                            | [PROJECT](glossary:projection)                  | Only the listed **columns**, duplicates removed   | [SELECT DISTINCT](glossary:select)                                                            |
| [ρ](glossary:rename)<sub>S(columns…)</sub>(R)                                            | [RENAME](glossary:rename)                       | Renames tables and columns                        | AS                                                                                            |
| R [∪](glossary:union) S, R [∩](glossary:intersection) S, [R − S](glossary:set-operation) | Set operations                                  | Union, intersection, difference                   | [UNION](glossary:union), [INTERSECT](glossary:intersection), [EXCEPT](glossary:set-operation) |
| R × S                                                                                    | [CARTESIAN PRODUCT](glossary:cartesian-product) | Every combination of rows                         | FROM R, S (no condition)                                                                      |
| R [⋈](glossary:join)<sub>condition</sub> S                                               | [JOIN](glossary:join)                           | Joins rows that meet the condition                | [JOIN](glossary:join) ON                                                                      |
| R \* S                                                                                   | [NATURAL JOIN](glossary:natural-join)           | Joins on same-named columns and keeps one of each | [NATURAL JOIN](glossary:natural-join)                                                         |
| R [⟕](glossary:outer-join) S, R [⟖](glossary:outer-join) S, R [⟗](glossary:outer-join) S | [OUTER JOIN](glossary:outer-join)               | Keeps rows even without a match                   | LEFT / RIGHT / FULL [OUTER JOIN](glossary:outer-join)                                         |
| <sub>grouping columns</sub>[ℱ](glossary:aggregate-function)<sub>function column</sub>(R) | [Aggregation](glossary:aggregate-function)      | Groups, then COUNT, SUM…                          | [GROUP BY](glossary:group-by) + [aggregates](glossary:aggregate-function)                     |
| R [÷](glossary:division) S                                                               | [DIVISION](glossary:division)                   | R rows that have all of S                         | [NOT EXISTS](glossary:not-exists) … [EXCEPT](glossary:set-operation)                          |
| T ← expression                                                                           | Assignment                                      | Names an intermediate result                      | [Temporary table](glossary:temporary-table)                                                   |

## 2. Picking rows σ

**[σ](glossary:selection)<sub>condition</sub>(R)**: only the rows that meet the condition. Columns unchanged

- Conditions are `column op value` / `column op column`, with AND, OR, NOT. Comparisons are =, &lt;, ≤, >, ≥, ≠

[σ](glossary:selection)<sub>Dno=4</sub>(EMPLOYEE) → employees in department 4 <br />
[σ](glossary:selection)<sub>(Dno=4 AND Salary>25000) OR (Dno=5 AND Salary>30000)</sub>(EMPLOYEE)

- [σ](glossary:selection)<sub>c1</sub>([σ](glossary:selection)<sub>c2</sub>(R)) = [σ](glossary:selection)<sub>c1 AND c2</sub>(R). Order doesn't matter
- It's called SELECT but it's [SQL](glossary:sql)'s **[WHERE](glossary:where)**. [SQL](glossary:sql)'s SELECT slot is [π](glossary:projection)

## 3. Picking columns π

**[π](glossary:projection)<sub>column list</sub>(R)**: only the listed columns. The result is a set, so **duplicate rows are removed**

[π](glossary:projection)<sub>Lname, Fname, Salary</sub>(EMPLOYEE) → three columns <br />
[π](glossary:projection)<sub>Sex, Salary</sub>(EMPLOYEE) → two (M, 25000) rows become one

## 4. Chaining and renaming ρ

**Either way**: nest with parentheses / break with ←. Runs from the inside (the lower line) first

[π](glossary:projection)<sub>Fname, Lname, Salary</sub>([σ](glossary:selection)<sub>Dno=5</sub>(EMPLOYEE))

DEP5_EMPS ← [σ](glossary:selection)<sub>Dno=5</sub>(EMPLOYEE) <br />
RESULT ← [π](glossary:projection)<sub>Fname, Lname, Salary</sub>(DEP5_EMPS)

| How to write [ρ](glossary:rename)              | What it renames                           |
| ---------------------------------------------- | ----------------------------------------- |
| [ρ](glossary:rename)<sub>S(B1, B2, …)</sub>(R) | Table name S, column names B1, B2…        |
| [ρ](glossary:rename)<sub>S</sub>(R)            | Table name only                           |
| [ρ](glossary:rename)<sub>(B1, B2, …)</sub>(R)  | Column names only                         |
| R(B1, B2, …) ← expression                      | Column names can also go on the left of ← |

R(First_name, Last_name, Salary) ← [π](glossary:projection)<sub>Fname, Lname, Salary</sub>(DEP5_EMPS)

## 5. Set operations ∪ ∩ −

**Requirement**: same number of columns and the same type in each column ([type compatible](glossary:union-compatibility))

| Expression                      | Result                                           | Example                           |
| ------------------------------- | ------------------------------------------------ | --------------------------------- |
| R [∪](glossary:union) S         | Rows in at least one of them, duplicates removed | Students or instructors           |
| R [∩](glossary:intersection) S  | Rows in both                                     | Students who are also instructors |
| [R − S](glossary:set-operation) | Rows in R but not in S. Not the same as S − R    | Students who aren't instructors   |

RESULT1 ← [π](glossary:projection)<sub>Ssn</sub>(DEP5_EMPS) <br />
RESULT2(Ssn) ← [π](glossary:projection)<sub>Super_ssn</sub>(DEP5_EMPS) <br />
RESULT ← RESULT1 [∪](glossary:union) RESULT2

- Ssns of employees in department 5 or their direct supervisors. The column names differ, so (Ssn) is added to RESULT2

## 6. Every combination ×

**R × S**: attaches every S row to each R row. n + m columns, |R| × |S| rows. Types don't need to match

- Junk on its own. Follow it with [σ](glossary:selection) to keep only matching combinations → the two together are a [JOIN](glossary:join)

FEMALE_EMPS ← [σ](glossary:selection)<sub>Sex='F'</sub>(EMPLOYEE) <br />
EMPNAMES ← [π](glossary:projection)<sub>Fname, Lname, Ssn</sub>(FEMALE_EMPS) <br />
EMP_DEPENDENTS ← EMPNAMES × DEPENDENT <br />
ACTUAL_DEPENDENTS ← [σ](glossary:selection)<sub>Ssn=Essn</sub>(EMP_DEPENDENTS) <br />
RESULT ← [π](glossary:projection)<sub>Fname, Lname, Dependent_name</sub>(ACTUAL_DEPENDENTS)

- Female employees and their dependents' names. Build 3 rows × 7 rows = 21 rows, then keep only the matches with [σ](glossary:selection)

## 7. Joining ⋈

**R [⋈](glossary:join)<sub>condition</sub> S** = [σ](glossary:selection)<sub>condition</sub>(R × S). Puts an R row and an S row that meet the condition on one line

DEPT_MGR ← DEPARTMENT [⋈](glossary:join)<sub>Mgr_ssn=Ssn</sub> EMPLOYEE <br />
RESULT ← [π](glossary:projection)<sub>Dname, Lname, Fname</sub>(DEPT_MGR)

- Manager name for each department

| Kind                                                                 | Condition                       | Result columns                                                               |
| -------------------------------------------------------------------- | ------------------------------- | ---------------------------------------------------------------------------- |
| [THETA JOIN](glossary:theta-join) [⋈](glossary:join)<sub>A θ B</sub> | θ is any of =, &lt;, ≤, >, ≥, ≠ | All R columns + all S columns                                                |
| [EQUIJOIN](glossary:equijoin) [⋈](glossary:join)<sub>A=B</sub>       | = only                          | All R columns + all S columns. Both equal-valued columns stay (Mgr_ssn, Ssn) |
| [NATURAL JOIN](glossary:natural-join) R \* S                         | = on same-named columns         | Only one of each same-named column                                           |

- [NATURAL JOIN](glossary:natural-join) needs the column names to match. If they don't, align them with [ρ](glossary:rename) first

DEPT ← [ρ](glossary:rename)<sub>(Dname, Dnum, Mgr_ssn, Mgr_start_date)</sub>(DEPARTMENT) <br />
PROJ_DEPT ← PROJECT \* DEPT

- Dnumber → Dnum to match PROJECT.Dnum

- Number of result rows: 0 (nothing matches) to |R| × |S| (everything matches)

**[OUTER JOIN](glossary:outer-join)**: keeps rows without a match too, with [NULL](glossary:null) in the empty cells. [⟕](glossary:outer-join) all left, [⟖](glossary:outer-join) all right, [⟗](glossary:outer-join) both

TEMP ← EMPLOYEE [⟕](glossary:outer-join)<sub>Ssn=Mgr_ssn</sub> DEPARTMENT <br />
RESULT ← [π](glossary:projection)<sub>Fname, Minit, Lname, Dname</sub>(TEMP)

- Every employee + the name of the department they manage. Dname is [NULL](glossary:null) for non-managers

## 8. Counting ℱ

**<sub>grouping columns</sub> [ℱ](glossary:aggregate-function) <sub>function column, …</sub>(R)**: groups rows with equal grouping columns and applies the functions. The functions are COUNT, SUM, AVERAGE, MAXIMUM, MINIMUM

<sub>Dno</sub> [ℱ](glossary:aggregate-function) <sub>COUNT Ssn, AVERAGE Salary</sub>(EMPLOYEE) -
Employee count and average salary per department. Result columns Dno, Count_ssn, Average_salary

[ℱ](glossary:aggregate-function) <sub>COUNT Ssn, AVERAGE Salary</sub>(EMPLOYEE)

- Without grouping columns everything is one group → one row

[ρ](glossary:rename)<sub>R(Dno, No_of_employees, Average_sal)</sub>(<sub>Dno</sub> [ℱ](glossary:aggregate-function) <sub>COUNT Ssn, AVERAGE Salary</sub>(EMPLOYEE))

- Wrap it in [ρ](glossary:rename) to rename the columns

- Counts without removing duplicates / skips [NULLs](glossary:null) / the result is a table even if it's a single cell

## 9. Finding what has all of them ÷

**R [÷](glossary:division) S**: the R rows that have **all** values in S. S's columns must be a subset of R's, and result columns = R's columns − S's columns

![R(A, B) ÷ S(A): only B values that have all of S's a1, a2, a3 remain](/static/images/database-systems-ch5-relational-algebra/ra-division.svg)

SMITH ← [σ](glossary:selection)<sub>Fname='John' AND Lname='Smith'</sub>(EMPLOYEE) <br />
SMITH_PNOS ← [π](glossary:projection)<sub>Pno</sub>(WORKS_ON [⋈](glossary:join)<sub>Essn=Ssn</sub> SMITH) <br />
SSN_PNOS ← [π](glossary:projection)<sub>Essn, Pno</sub>(WORKS_ON) <br />
SSNS(Ssn) ← SSN_PNOS [÷](glossary:division) SMITH_PNOS <br />
RESULT ← [π](glossary:projection)<sub>Fname, Lname</sub>(SSNS \* EMPLOYEE)

- Employees who work on every project Smith works on. If SMITH_PNOS = \{1, 2\}, only Essns that work on both 1 and 2 remain

**Template for [÷](glossary:division)**: ① build S, the list of "all" ([π](glossary:projection) of one column) → ② build R, who does what ([π](glossary:projection) of two columns, including S's column) → ③ R [÷](glossary:division) S → ④ join back to the original with \* to get names

## 10. The complete set and query trees

**[Complete set](glossary:complete-set-of-operations) \{[σ](glossary:selection), [π](glossary:projection), [∪](glossary:union), [ρ](glossary:rename), −, ×\}**: these six make all the others

- R [∩](glossary:intersection) S = (R [∪](glossary:union) S) − (([R − S](glossary:set-operation)) [∪](glossary:union) (S − R))
- R [⋈](glossary:join)<sub>c</sub> S = [σ](glossary:selection)<sub>c</sub>(R × S)

**[Query tree](glossary:query-tree)**: the expression as a tree. Leaves = tables, inner nodes = operations, runs from the leaves upward

![Query tree for the Stafford project query, drawn in the order σ → ⋈ → ⋈ → π](/static/images/database-systems-ch5-relational-algebra/ra-query-tree.svg)

## 11. Same question, SQL next to relational algebra

| Question                                                      | [SQL](glossary:sql)                                                                                                  | [Relational algebra](glossary:relational-algebra)                                                                                                                                                          |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Names and salaries of department 5 employees                  | `SELECT Fname, Lname, Salary FROM EMPLOYEE WHERE Dno = 5`                                                            | [π](glossary:projection)<sub>Fname, Lname, Salary</sub>([σ](glossary:selection)<sub>Dno=5</sub>(EMPLOYEE))                                                                                                 |
| Names and addresses of Research employees                     | `SELECT Fname, Lname, Address FROM EMPLOYEE, DEPARTMENT WHERE Dname = 'Research' AND Dnumber = Dno`                  | RESEARCH ← [σ](glossary:selection)<sub>Dname='Research'</sub>(DEPARTMENT) / RD ← RESEARCH [⋈](glossary:join)<sub>Dnumber=Dno</sub> EMPLOYEE / [π](glossary:projection)<sub>Fname, Lname, Address</sub>(RD) |
| Employee and supervisor names                                 | `… FROM EMPLOYEE AS E, EMPLOYEE AS S WHERE E.Super_ssn = S.Ssn`                                                      | S ← [ρ](glossary:rename)<sub>S(Sssn, Sfn, Sln, …)</sub>(EMPLOYEE) / EMPLOYEE [⋈](glossary:join)<sub>Super_ssn=Sssn</sub> S                                                                                 |
| Employee count per department                                 | `SELECT Dno, COUNT(*) FROM EMPLOYEE GROUP BY Dno`                                                                    | <sub>Dno</sub> [ℱ](glossary:aggregate-function) <sub>COUNT Ssn</sub>(EMPLOYEE)                                                                                                                             |
| Employees with no dependents                                  | `WHERE NOT EXISTS (SELECT * FROM DEPENDENT WHERE Ssn = Essn)`                                                        | ALL ← [π](glossary:projection)<sub>Ssn</sub>(EMPLOYEE) / HAS ← [π](glossary:projection)<sub>Essn</sub>(DEPENDENT) / [π](glossary:projection)<sub>Fname, Lname</sub>((ALL − HAS) \* EMPLOYEE)               |
| Working on every department 5 project                         | `WHERE NOT EXISTS ((SELECT Pnumber FROM PROJECT WHERE Dnum = 5) EXCEPT (SELECT Pno FROM WORKS_ON WHERE Essn = Ssn))` | P5 ← [π](glossary:projection)<sub>Pnumber</sub>([σ](glossary:selection)<sub>Dnum=5</sub>(PROJECT)) / SP ← [π](glossary:projection)<sub>Essn, Pno</sub>(WORKS_ON) / SP [÷](glossary:division) P5            |
| Employee + supervisor, including employees with no supervisor | `LEFT OUTER JOIN`                                                                                                    | EMPLOYEE [⟕](glossary:outer-join)<sub>Super_ssn=Sssn</sub> S                                                                                                                                               |

## 12. Question wording → symbols

| When the question says                                                 | Use                                                                                                              |
| ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| who are ~ (condition)                                                  | [σ](glossary:selection)                                                                                          |
| the names, numbers of ~ (picking columns)                              | [π](glossary:projection). At the very end                                                                        |
| Columns from two tables                                                | [⋈](glossary:join)<sub>[FK](glossary:foreign-key)=[PK](glossary:primary-key)</sub>. \* if the column names match |
| An employee and their supervisor                                       | Rename a copy of EMPLOYEE's columns with [ρ](glossary:rename), then [⋈](glossary:join)                           |
| ~ or ~                                                                 | [∪](glossary:union) (with matching columns)                                                                      |
| ~ and also ~ (in both results)                                         | [∩](glossary:intersection)                                                                                       |
| not ~, with no ~                                                       | − (all − the ones that have it)                                                                                  |
| How many, sum, average                                                 | [ℱ](glossary:aggregate-function)                                                                                 |
| per ~, for each ~                                                      | Grouping columns before [ℱ](glossary:aggregate-function)                                                         |
| working on all, every ~                                                | [÷](glossary:division)                                                                                           |
| Rows without a match must show too                                     | [⟕](glossary:outer-join) [⟖](glossary:outer-join) [⟗](glossary:outer-join)                                       |
| Column names don't match so \* can't be used / renaming result columns | [ρ](glossary:rename)                                                                                             |
